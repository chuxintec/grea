## 本版重点

**GREA 以技能为主，monkey 与 beaver 作为 GREA 模块统一发布。**

- **模块统一发布**：`modules.lock.json` 固定 monkey 0.4.1 与 beaver 0.4.0 的 wheel（文件名、SHA256、字节数、依赖、来源）。双平台完整插件在 `modules/wheels/` 内置两个 wheel；`grea_modules status` 只读查看，`grea_modules install <monkey|beaver>` 校验后隔离安装（macOS/Linux；Windows 安装返回 needs_action），再经 `monkey_pipeline ensure`、`beaver_pipeline pin`、`toolchain_check` 判定就绪。模块共享依赖（Pillow、pypinyin、jsonschema）由 GREA 锁定运行时提供。
- **执行代码迁出 GREA**：30 个执行工具移入模块——23 个到 beaver（`beaver tool <id>`：资产台账与依赖审计、轨迹/事件对照、录像/图片/数值纹理、制品核验与便携封装、包备份、静态复制、原生退出检查、配置与原生资源候选、证据清单、表现与性能对照、兼容/运营预览、Unity 试点），7 个到 monkey（`monkey tool <id>`：Laya 契约审计、ELF 常量、XAPK/wxapkg 解包与解密、配置表导出、Shader 探针）。工具 ID、参数、报告与退出码不变，`run-tool`、MCP 和类型化操作自动委托；相应测试随代码迁移。仍留在 GREA 的执行代码依赖 GREA 自带的非 Python 资产（.NET 程序集读取器、自有 UPM 框架、项目模板、暂停中的 Cocos Node AST 索引）或属于路由/检查本身。
- **技能按工作流重组**：路由技能按“调研→取证→恢复为候选→工程开发→对照修复→构建交付”列出 12 个子技能及其执行模块；阶段专属文档归属唯一阶段（如生命周期与变更合同→grea-evolve）。
- **技能与项目文档分工**：技能只承载规范与工作流，跨阶段共用规范（测试与结果交付、真实体验对照、工具链调用等）只有一份，在 `grea` 技能的 `references/`，其他技能直接链接；`check_grea_skill` 拒绝离开 `plugin/skills` 的链接，已安装技能不依赖源码仓库。根目录 `docs/` 精简为项目概览与产品使用说明（安装、接口、Unity、故障排查、维护发布、provider/工具），维护历史移至 `proposals/design/`。
- **品牌统一**：文档、技能说明与插件展示名统一写作 GREA；`grea` 命令、Skill ID、包名和路径保持小写以兼容已有安装与项目。
- **经验沉淀**：来自[项目 A]与[项目 B]的输入自动化、原生执行陷阱、宿主模块化、立项前提与进度度量、配置/存档版本、复合查找键、项目脚本晋升等方法已写入对应技能。
