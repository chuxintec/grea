# Beaver virtual pointer Unity companion

`BeaverVirtualPointer.cs` is a Development Build-only, opt-in macOS Player companion for Unity Input System 1.20.1 and `InputSystemUIInputModule` consumers. Other platforms are explicitly unsupported; there is no native-input fallback. The source is inert unless all three gates hold: `BEAVER_VIRTUAL_POINTER` is defined, `ENABLE_INPUT_SYSTEM` is defined, and the process is a Development Build with an explicit `BEAVER_VIRTUAL_POINTER_CONFIG` path.

Startup waits for a nonzero viewport stable across frames before registering the device or publishing its endpoint. The config is a strict UTF-8 JSON document with `contract: "beaver-virtual-pointer-config/1"`. Its endpoint path is the private discovery JSON file path; the companion writes the full nonsecret discovery record there after binding an ephemeral loopback TCP port and creating its custom `Mouse` device. The token stays in the config and is never echoed in logs or receipts. Input commands use the closed `beaver-virtual-pointer-command/1` line protocol and responses/receipts use `beaver-virtual-pointer-receipt/1`; completed command receipts are create-only files under the configured receipt root.

Each scene's active `InputSystemUIInputModule` receives temporary actions from a dedicated `InputActionAsset` and map whose device list contains only `<BeaverVirtualMouse>`. This covers point, left/right/middle click, scroll, navigation, submit/cancel, and tracked-device pose routes; unsupported routes have empty virtual-only actions. Queued `MouseState` events advance at most once per Unity frame, and acknowledgements are produced from `LateUpdate` after the normal EventSystem update. Stop/lease cleanup restores every original action reference and enabled state, then destroys the temporary references, asset, and custom device. Safety releases are queued independently of an active gesture and are acknowledged after a normal UI frame before teardown. `Application.runInBackground` is temporarily enabled and its previous value is restored during normal cleanup. No `InputSettings` focus policy is changed.

Project code may use `BeaverVirtualPointer.IsActive`, `BeaverVirtualPointer.DeviceId`, and `BeaverVirtualPointer.IsVirtualPointerEvent(PointerEventData)` to distinguish this device on normal Input System UI callbacks. The event helper checks `ExtendedPointerEventData.device` against the owned virtual device object; it does not treat every `Mouse` event as virtual.

Supported operations are `hello`, `inspect`, `move`, `down`, `up`, `click`, `drag`, `scroll`, `release`, and `stop`; `capture` returns `not_supported`. The device never becomes `Mouse.current`, never warps a cursor, and has no OS event injection, activation, text-entry, keyboard, direct button callback, game-state, or manual EventSystem processing path. Read-only Objective-C calls sample `NSWorkspace.frontmostApplication.processIdentifier`; native mouse, keyboard, touch, gamepad, joystick, or pen state events stop the companion only when that OS PID is the target process and the event changes at least one control. The observer reads only event/device metadata and never reads keyboard contents. Other applications' input is not treated as target takeover. If foreground observation is unavailable, initialization reports `not_supported` and publishes no endpoint.

Each completed shutdown writes one token-free lifecycle receipt under the private receipt root, including its fixed reason, Unity focus and batch-mode values, OS foreground PID, viewport identity, frame/event counts, and cleanup results. Command receipts keep `focused` as the `Application.isFocused` value and separately report `osForeground`, `frontmostPid`, and `applicationBatchMode`. A viewport resize closes the instance while retaining its original screen dimensions in terminal records; clients must bind a fresh instance.

This companion routes only uGUI pointer actions consumed through `InputSystemUIInputModule`. Gameplay that reads `Mouse.current`, another input module, bespoke direct-device input, or a project-specific capture path is outside this runtime's support. Compilation, live Unity integration, drag interruption behavior, and consumer-level UI results require separate Unity validation; this source-only handoff does not claim those results.
