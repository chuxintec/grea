# beaver v0.6.0 release scope

Release version: 0.6.0. Publication follows the exact component and combination acceptance records. This release consolidates the fixed development capabilities without upgrading existing game consumers.

| Layer | Supported boundary | Evidence and limits |
| --- | --- | --- |
| Python distribution | Python 3.10+ metadata; portable pure-Python wheel and source distribution | Isolated installation and CLI checks use the interpreter recorded in the validation report; no universal platform-native claim. |
| Native Unity editing/build | Unity 6000.6.2f1; declared uGUI/TMP and exact project/dependency profile; macOS build route | Existing neutral native save/reload/build/source-restoration evidence can be reused only where relevant executable bytes are unchanged. Native builds require the installed Editor and platform module. |
| Incremental intake | Explicit source/target identities; spec1–5, engine objects, retained assemblies | Static contract validation is separate from Editor import, Player compilation, visuals and gameplay. No complete arbitrary script recovery claim. |
| SDK and assembly migration | Exact declared managed assembly identity and supported importer roles; explicit existing transaction methods | Unknown importer roles, conflicting assemblies and missing compiler/provider evidence remain refused. A higher version alone is not migration proof. |
| App and input | Explicit owned instance and launch contract; macOS instance observation; Input System UI companion | Virtual pointer is backup only, with no OS pointer warp/global event/activation fallback. Natural human parallel use and all takeover situations are not universally certified. |
| Toolkit/server helpers | Optional libraries and explicit external providers | No production deployment, payment acceptance, service upgrade or implicit global installation. |

Computer Use and virtual pointer must not be active simultaneously. Existing focus/process/ownership guards and partial/blocked/unsupported outcomes remain effective. Logical callback tests are not proof of a real human takeover. Native compilation is not proof of gameplay or visual parity.

The publication gate requires an installed-artifact check and a representative GREA CLI/MCP combination. Static plan/readiness success is never reported as native apply/build/runtime execution. Windows-native, arbitrary engine versions, Cocos native execution and universal visual fidelity are not claimed.

Existing fixed17 build, fixed29 intake and fixed31 QA consumers remain pinned. Use original implementation identities for retained transactions; never substitute this release into an old transaction automatically.

The public source and packages contain neutral tests, contracts, native companions, notices and templates. Private source indexes, logs, player archives and machine configuration are excluded. Build/source hashes, external dependencies, validation scope and unverified items are supplied in the candidate/release manifest.

macOS instance/desktop bridges require the already-installed Xcode command-line compiler and the OS permissions required by the chosen operation. The package does not install compilers, grant permissions, change TCC/SIP or replace existing input guards.

See [validation summary](VALIDATION-v0.6.0.json) for executed layers; the release manifest binds exact distributed artifacts.
