# 维护与发布

用途：维护 GREA 产品与构建可评审候选；游戏工程和用户安装不属于仓库源码。先核对 Git 根、AGENTS、分支和本轮授权。

## 版本分支

GREA 仅保留开发分支 `vX.Y.Z.devN`（N 为正整数）与正式分支 `vX.Y.Z`。不再使用 main、develop、codex/、功能名、日期或 fix 名分支；历史发布由不可变 tag 追溯，无需保留已合并分支。

GREA 当前正式分支及远端默认分支为 `v1.0.0`，当前开发分支为 `v1.1.0.dev2`。相关模块在该开发线集成；需要隔离时使用 detached worktree，不新增功能名分支。发布前建立对应版本的正式分支；正式分支建立不等于允许发布，已发布 tag 与制品保持不变。

删除分支前核对提交可达性、在途工作树、未提交文件和消费者。活跃分支原地改名；重复或已合并分支删除，唯一成果先整合。分支与 tag 可以同名，比较和远端操作显式使用 `refs/heads/…`、`refs/tags/…`，不强推重写历史。

## 架构与唯一来源

- `src/grea`：CLI/MCP 共用应用、契约和工具；OS 差异集中 `host/`。
- `registry.json`：工具 ID、别名、依赖及 argv；`contracts.py` 生成 schemas。
- `plugin/`：整套技能、权威流程、启动薄层和目标 runtime lock。
- `tools/`：Unity 包与非 Python 实现；`scripts/` 只做维护/测试准备。
- `docs/`：项目介绍、安装、使用与维护手册；执行所需格式合同和示例归 `plugin/skills/*/references` 与 `assets`；`validation/` 保留验证记录；脱敏摘要与原始证据身份分开，见验证索引；已完成过程从冻结 Git 历史追溯。

新增工具先核对现有语义；保留旧 ID、参数和别名，同步实际调用方。不要为“统一入口”复制业务实现。未验证的候选与当前能力分开。

### 功能模块与依赖方向

| 位置 | 维护责任 |
| --- | --- |
| `features/<模块>/commands.py` | 模块的公开动作、核心操作和专项工具声明。`features/catalog.py` 只登记 14 个功能模块并发现声明。 |
| `features/<模块>/recovery.py`、`development.py` | 对应模块的参数声明和调用编排；`ROUTES` 声明旧动作与公开名字的对应关系。公共入口与旧阶段入口分别创建解析器，共用声明和执行函数。 |
| `commands/model.py`、`catalog.py` | 中立命令对象、参数描述、目录汇总、归属检查及重复动作拒绝。 |
| `commands/interface.py`、`result.py` | argv / JSON 输入校验、`CommandResult` 和一次性公共回执序列化；不识别恢复或开发后端。 |
| `features/adapters.py` | 现有核心操作、恢复、工程回执及专项脚本的边界适配。只有仍然打印结果的独立脚本和静态绑定旧入口使用输出捕获。 |
| `recovery/` | 来源解析、身份、依赖闭包和候选恢复算法。 |
| `development/` | 计划校验、原生采用、事务日志、受控写入、独立复验和回滚；`reporting.py` 提供有预算的报告读取与摘要。 |
| `application.py`、`contracts.py`、`runner.py`、`host/` | 核心 Schema 与 MCP、隔离进程及平台实现，继续使用原执行和预算合同。 |

依赖从接口进入功能模块，再进入恢复算法或工程事务。恢复、工程库不反向依赖阶段 CLI；`recover`、`develop` 是兼容适配入口。`commands/groups.py` 仅提供旧 Python 导入名的动态兼容视图，不再维护分组映射。

已有模块新增动作，只修改所属模块的参数、处理函数及测试；新模块另在 `features/catalog.py` 登记。处理函数签名为 `(arguments, argv, parser) -> CommandResult`；已有 `(value, exit_code)` 函数可使用 `commands.result.structured()`。不要在公共接口新增后端分支，也不要把业务结果打印后再解析。CLI 帮助、JSON 目录、MCP 查询及命令参考均从真实公开解析器生成。

### 批量恢复的边界

肥鹅的字体、描边、锚点和布局修复归来源恢复规则；僵尸的资源闭包、GUID/fileID、资产命名、批量原生读取与采用归相应算法和工程事务。游戏特例、原件、截图和采用证据保留在游戏工程外部目录，不进入工具命令层。

候选生成、静态验证、Play Mode、真机对照与正式采用保持不同的证据状态。资产数量不等于源对象覆盖率，静态指纹一致不代表业务可运行。采用、增量接入、回滚和结束事务保持各自合同，不因接口统一而互换。复用已有稳定指纹、分批导入和保存后冷读的实现，不在命令层复制这些判断。

工程生产者指纹覆盖 `development/`、`features/` 和 `commands/` 的可执行文件、模板及声明，排除 Python 缓存。迁移命令文件会改变实现身份；已冻结计划仍绑定原生产者，必须由原固定实现接续。不得改写历史计划、锁或回执来绕过身份校验。

## 开发验证

```sh
uv sync --frozen
python scripts/generate_contracts.py --check
python scripts/generate_command_reference.py --check
python scripts/check_docs.py
python scripts/check_skill_closure.py
python scripts/check_semantic_docs.py
python scripts/render_brand_assets.py --check
python -m pytest -q
```

上面的 python 应为 `.venv/bin/python` 或 Windows `.venv/Scripts/python.exe`。Skill 只修改 plugin；用 `scripts/sync_skill.py --destination /absolute/isolated/skills` 同步，再加 `--check` 检查；候选验收不更新全局安装。同步只接受技能集合内部引用，运行 `check_skill_closure.py --skills-root /absolute/isolated/skills` 验证脱离仓库后的引用闭包；CLI/MCP 与执行模块仍是独立的运行依赖。

命令架构变更先运行 `tests/test_command_architecture.py`、`tests/test_command_modules.py`，再执行受影响恢复/工程测试及全量回归。macOS 本机测试使用 `TMPDIR=/private/tmp`，避免系统临时目录的符号链接影响路径身份夹具。测试包含命令归属、无阶段分派、旧参数兼容、写入前拒绝、生产者指纹和真实 stdio MCP；它们不替代 Unity 或游戏的原生验收。

## 供应方与公开分发

凭据、providers.local、二进制、游戏素材、原始日志和本机 .venv 不提交。暂存后运行 `scripts/audit_public_tree.py` 审计实际字节，并人工检查许可证与归属；模式扫描不能证明无全部敏感内容。许可来源见 [THIRD_PARTY](../THIRD_PARTY.md)。

跨平台文本为 UTF-8。Windows Case 使用共享/独占 LockFileEx；目录使用同卷、无替换移动；工具先挂入 Job 再执行。平台事实与原生验收边界见 [验证索引](../validation/README.md)，不把权限位当 Windows ACL 或用清 PATH 冒充沙箱。

## 构建候选

当前 v1.1.0.dev2 在 GREA 单仓维护完整本地实现。公开插件须使用已批准的编译制品；恢复与工程实现、内部工具及历史记录均从公开投影排除。二进制构建与发布仍暂停，已发布身份按原版本保留。

新 binary provider 安装与 pin 走[恢复与工程操作](../plugin/skills/grea/references/恢复与工程操作.md)；它与旧 Python 锁独立。模块 owner 保留目录/版本/单写与构建来源，GREA负责人统筹组合验收与统一公开分发。私有仓库 token、源码、编译中间源和敏感日志不进入公开 CI/产物；新增认证须有具体最小权限配置，不借用本机个人全权凭据。

在匹配平台、干净提交上分别运行：

```sh
python scripts/build_plugin.py --target macos-arm64 --out dist/plugin
python scripts/verify_plugin.py --bundle dist/plugin/grea-plugin-macos-arm64.zip --report dist/plugin/plugin-acceptance.json
```

Windows 使用 `--target windows-x64` 和 `grea-plugin-windows-x64.zip`。构建时联网取得锁定归档/依赖，使用时不下载；重复构建比较哈希。`--worktree` 仅未发布预览，不能标成提交制品。发布仅提供两个完整插件 ZIP，内部保留全部技能；`scripts/release.py prepare` 生成元数据，attach-plugin 绑定两平台及验收报告，verify 必须检查完整目标集合。源码使用 GitHub 自动下载，不额外生成安装 ZIP。

## 发布流程

仅收到明确发布授权后统一 package/runtime/uv.lock/两份客户端版本、更新 `validation/release-notes/<tag>.md` 发布说明并提交。推送版本标签才会触发 Release 工作流；rc 自动预发行。源码、目标包和各自验收报告须绑定同一提交；缺目标不得用其他平台报告代替。使用 `release.py verify` 核验附件清单、哈希和发布回读。

发布前在对应版本的开发分支及正式分支上通过 CI 与 Release dry run，才创建正式标签。Windows Server 原生 CI 是本轮 Windows 门槛；桌面/Unity/Player 实机明确排除并记 not_run。用户安装独立授权，不随发布升级。

平台实现依据：[LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)、[MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)、[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)。API 文档不代替本轮原生测试。

原工具的算法、合同与出处摘存于 `docs/history/recovery/` 和 `docs/history/development/`，供读旧证据使用。完整移入前快照为 `24dbe6e`。当前命令以[执行参数索引](../plugin/skills/grea/references/功能模块和命令参数.md)为准。
