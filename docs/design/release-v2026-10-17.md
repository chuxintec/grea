# grea v2026.10.17 修复与插件发布方案

日期：2026-10-17。执行会话：Grea 开发与维护。工作目录：`Games/grea`。

本轮完成遗留问题修复，将安装制品收敛为 macOS 与 Windows 两个完整插件，在自动化验收通过后合并 main、推送 GitHub 并发布正式版本 `v2026.10.17`。Windows 不进行实机验收；此项由用户明确移出本轮发布门槛。

## 1. 范围及授权变更

本方案覆盖旧 Windows/docs 计划中与本轮冲突的范围、发布门槛和分支限制；旧方案的有效实现约束继续适用。

- Windows 只修复现有实现及自动化验收问题，不扩展 ARM64、WSL、虚拟机、桌面输入或 Windows Unity 实机验证。无需搭建本地 Windows 虚拟机。
- Windows 的“验收通过”指 Windows Server x64 原生 CI 的核心测试、完整插件测试及临时客户端安装验证通过。Windows 11 桌面、Unity Editor、Player、图形性能和人工操作标为 `not_run`，原因为“本轮用户明确排除”，不标成 pass，也不阻塞发布。
- 用户已授权：完成修复、构建两个平台的插件、验收后合并 main、推送 GitHub、创建标签并发布 `v2026.10.17`。满足门槛后连续执行，无需再次请求相同授权。
- 开发使用 `codex/release-v2026-10-17` 分支；不在 main 直接继续修复。当前 main 已包含上一轮 Windows/docs 工作，本轮合并的是修复与分发调整增量。
- 不修改游戏项目，不升级用户全局插件，不安装 Claude 客户端，不使用子 Agent。不删除历史 Release、历史制品、用户证据或私有运行时。

## 3. 遗留问题修复

### 3.1 Windows 插件工具启动

重点检查 `src/grea/host/windows_process.py`、`src/grea/runner.py`、`scripts/windows_sandbox.py` 与 `scripts/verify_plugin.py`。定位 Access denied 出现在进程创建、受限令牌、Job 绑定、句柄继承、路径 ACL 或其他具体步骤，记录证据后做最小修复；当前错误只证明启动失败，不能先假定根因。

必须保留进程所有权、超时/取消/输出超限清理和有界等待，不能为了通过而禁用沙箱、改用管理员账户、删除失败断言、放宽为任意访问或把失败改成跳过。若需要调整验收环境，只开放工作目录及必要执行权限，证明源码读取、安装写入、联网拒绝仍有效。

Windows 自动化验收必须执行到结尾：搬移到带中文和空格的目录、独立 HOME、最小 PATH、自带解释器、CLI/MCP、真实内置工具子进程、旧入口、来源与配置工具、安装目录不变。网络探针使用同一活跃端点的沙箱外前后对照，不能用任意超时冒充禁网成功。两份客户端启动配置分别验证；这不等于安装了两个客户端。

增加能捕获本次缺陷的回归断言，在 Windows 原生 runner 执行。失败报告保留具体错误阶段与系统错误码，便于复查。

### 3.2 客户端、平台状态和文档

- Windows CI 中实际完成原生 Codex 的临时安装、注册回读、8 个技能发现、21 个 MCP 工具发现及安装副本 session 版本核对；不发送模型请求、不改用户安装。已有脚本可继续使用，固定客户端版本并记录实际版本。
- `schemas/tool-platform-matrix.json` 保持“声明”与“实测”分开。新增本轮验证索引，按 canonical 工具 ID 关联实际 CI 用例、版本、输入类型和结果；没有实测的供应方继续 `not_run/provider_missing/unsupported`，不要把 61 项 implemented 全部改成 verified。剩余可选供应方实机检查不新增为本轮门槛。
- 修复 `AGENTS.md` 中已删除的 `docs/工作区接入.md` 引用；更新仍写“本轮不合并 main”的文档，以及 Windows 候选、独立 Skill 包、源码安装包等过时发行描述。
- 在 `validation/` 落地本轮可复查报告，更新验证索引，关联 CI run、源码提交、目标、制品哈希和排除项。旧历史报告保持原字节。
- 文档链接、显式语义、生成契约和公开树检查通过。纯文本路径引用也人工核对，不能仅依赖 Markdown 链接检查。

## 4. 制品收敛

本轮自定义安装附件仅保留：

| 附件 | 要求 |
| --- | --- |
| `grea-plugin-macos-arm64.zip` | 完整插件、自带 macOS ARM64 运行时及锁定依赖 |
| `grea-plugin-windows-x64.zip` | 完整插件、自带 Windows x64 运行时及锁定依赖 |
| `release-manifest.json`、`SHA256SUMS` | 两个平台的身份、版本、来源、哈希及证据绑定 |
| 分平台验收报告 | 必要的验收证明；文件名包含 target，禁止同名覆盖或跨平台混用 |

源码继续由 Git 和 GitHub 自动生成的 Source code 下载提供，本轮不额外上传自定义源码 ZIP。取消独立 `grea-skill-*.zip` 的构建、CI 上传和 Release 附件；不能通过先生成再漏上传来保留旧分发链路。GitHub 自动源码附件不属于需要删除的自定义制品。

**保留插件内部的全部 8 个技能、共享参考、图标、MCP、运行时和许可证。**取消独立 Skill ZIP 不等于删除技能内容；`scripts/sync_skill.py` 的维护同步用途也保留。历史 Skill 包由其历史版本保留，不批量清理旧 Release。

优先修改 `.github/workflows/ci.yml`、`.github/workflows/release.yml`、`scripts/release.py`、`scripts/plugin_release.py` 及对应测试。`prepare/verify/attach-plugin/publish` 不能再把源码包和 Skill 包的数组位置或文件名作为固定前提；以明确的目标集合验证最终附件。

- 最终发布集合必须恰含 macos-arm64 与 windows-x64 两个安装插件；构建中间态允许分平台产出，最终 verify/publish 必须拒绝缺平台、重复平台和多余安装包。
- 缺失、损坏、被替换、错误 target、版本不一致、不同源码提交、过期验收报告、跨平台报告混用均必须拒绝。两个平台任一失败不能只发布另一个。
- 两包必须来自同一干净提交；插件内容由现有 product projection 生成，取消独立包不能丢失运行必需文档或许可。
- 各平台连续两次构建比较 ZIP SHA-256；源/技能单独 ZIP 的旧测试替换为完整插件中的技能与文档闭包验证，保留有价值的链接、确定性、损坏和越界反例。
- `scripts/build_skill.py` 无剩余生产消费者时退役独立打包入口；若仍共享纯函数，将其移入已有合适公共模块后更新调用方，避免保留误导性产品入口。删除范围以实际引用审查为准。
- Release 上传和回读使用精确附件集合。不要用 `dist/*` 将旧包误带入新版；使用新的干净构建目录。

## 5. 执行顺序及门槛

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| R1 修复 | 定位 Windows 启动失败，补回归，修正文档遗漏 | Windows 核心与插件业务自动化通过，失败原因有记录 |
| R2 分发 | 移除独立 Skill/自定义源码安装包，重构发布集合与测试 | 仅双平台完整插件；全部必要内容仍完整；缺失和错误报告反例能拦截 |
| R3 候选 | 统一为正式版本 2026.10.17，提交分支，运行原生 CI 与发布 dry run | Windows/macOS 包测试、Codex 临时客户端验证、重复构建、身份/文档/许可检查通过 |
| R4 合并 | 分支通过后合并 main，推送 GitHub | 实际 main 提交重跑全部必要 CI 和发布 dry run，通过后才创建标签 |
| R5 发布 | 在已通过的 main 提交创建并推送 v2026.10.17，完成 Release 工作流 | 双平台制品与报告匹配标签提交；从远端回读并验证哈希、附件集合及正式发布状态 |

统一版本范围包括 pyproject、uv.lock、本体版本、plugin/version.json、两份客户端 manifest 和其他实际版本消费者。正式标签为 `v2026.10.17`，不是 rc；不得保留 prerelease 标记。版本字符串更新后重新生成与检查契约，不能继续使用旧候选包冒充正式包。

合并产生新 SHA 时必须对新 SHA 重建和验证，不能重标分支包的 source_revision。已执行的自动化证据按提交绑定；main CI 未结束或仍失败时不推标签。tag 发布工作流再次验证后再从 draft 晋升正式 Release，上传后下载核验。

自动化通过而 Windows 实机未运行，允许按用户本轮范围发布。发布说明明确：Windows x64 在 Windows Server 原生 CI 通过；Windows 11 桌面、Unity/Player 和性能未做实机验收。不能使用“Windows 全面实机验证通过”等措辞。
