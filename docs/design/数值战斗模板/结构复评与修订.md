# 结构复评与设计修订

设计版本：`0.1.0-draft.2`。复核日期：2026-10-15。范围：当前源码、目录与命名的只读检查，以及已保存测试、构建和专项验收回执的回读。本轮没有重跑 Unity、操作 Player、修改源游戏或查询远端发布状态。

**结论：样本已形成可持续维护的 Unity 工程骨架，足以作为模板设计的重要参考。** 复用重点可以从恢复过程的临时措施，转向程序集边界、制作闭环和组合回归。发布基线、后续修复候选与 grea 新模板各自保持独立身份。

## 四个方面的评审

| 方面 | 评价与依据 | 后续重点 |
| --- | --- | --- |
| 项目结构 | 409份C#、6运行程序集＋Editor＋2测试程序集；声明引用无环，没有依靠占位目录装饰架构 | 保留现有层次，不再套一层Runtime或批量搬迁 |
| 代码框架 | 强类型规则、组合根、生命周期和边界codec可借鉴；尚非可直接复制的公共框架 | 收窄组合模块，明确业务Ready，隔离来源细节 |
| 资源路径 | 6058内容文件，127工作View＋127Template；类型集中、工作层与基线分开 | 来源描述、Image/Sprite成对资产、Resources键按真实消费者治理 |
| 命名 | 已解决大部分UUID物理名，View/Template/Table/Overrides角色明确；仍有缩写与迁移期名称 | 新模板使用业务词＋角色；序列化身份不机械改名 |

本轮Assets盘点含6687个非meta文件、7106个meta文件；未发现文件缺meta、孤立meta、重复GUID、大小写/Unicode路径冲突、符号链接或空Content目录（E21）。这不是新Editor的Missing Script检查，也不是资产可以删除的证明。

### 资源目录的具体判断

| 目录 | 非meta文件数 | 判断 |
| --- | ---: | --- |

Resources可以嵌在类型目录下。当前Catalog与Shader位于嵌套Resources，逻辑键相对Resources计算；只扫Assets根的Resources会漏掉真实加载入口。来源图仍被运行resolver消费，不能当“分析中间文件”整体删除（E28）。

## 需要保留的改进项

以下是源项目评审意见与模板设计要求，本轮不代改原工程。

| 项 | 证据与影响 | 建议及关闭条件 |
| --- | --- | --- |
| F01：依赖身份漂移，P2 | profile的manifest/lock两个SHA与当前文件不符，包版本集合却相同，E22 | 从实际解析结果更新身份；版本与字节都校验。纯格式变化也需重算 |
| F02：运行依赖被可选工具间接拥有，P2 | 生产codec使用Newtonsoft；当前锁中仅Pipeline带入它，manifest未直接声明，E23 | 产品直接声明所需包；独立副本移除可选Editor连接包后验证编译/解析。本轮未执行卸载反例 |
| F03：日常文档身份混杂，P2 | 父导航给旧工程目录，维护页仍写旧测试数/“current待晋升”，E29 | 日常入口指向当前结构和状态manifest，历史按身份标注；不在多页手填“最新”数字 |
| F04：组合模块过重，维护风险 | 一个组合类承担源字段/常量、实例化、绑定、刷新、跨模块流程，E24 | 先明确模块输入输出和Ready，再逐切片拆分与差分；不整体猜测改写 |
| F05：用户提示掩盖本地首因，诊断风险 | 本地组合失败统一重试后显示网络提示，E27 | 恢复模式可保留原文案，内部诊断保留首因和类别；新模板只重试暂时失败 |

Source前缀、历史命名空间、来源组件的空兼容方法不属于可直接清理项：它们可能承担序列化或旧事件签名契约（E28）。全局改名须先证明没有身份依赖。

## 本轮补入模板的决定

1. 模块装配区分 **Created / Bound / BusinessReady / Visible / Closed**；只有遮罩和关闭按钮不算业务Ready，跨模块奖励必须完整组合。
2. UI覆盖延迟子项、所有启用分支、有效事件与源惰性事件；射线命中和函数可调用分别验证。
3. Sprite契约记录源版本、CUSTOM/TRIMMED/RAW、原图/裁切/作者尺寸及所有赋值入口，用不同尺寸构造反例。
4. Presenter与View共同更新当前选择；后续升级、预览和保存不能继续使用构造时旧状态。
5. 运行依赖直接声明，profile锁身份进入预检，可选工具不隐式承担运行依赖。
6. 命名使用业务含义＋角色＋稳定ID；Source/Legacy限兼容边界，新模板不沿用迁移阶段的Typed前缀。
