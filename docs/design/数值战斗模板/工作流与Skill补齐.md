# 工作流经验与 Skill 补齐提案

本页是待整合的规范增量，未修改 `skill/` 或安装副本。现有 [复盘规则](../../../plugin/shared/10-维护-开发复盘与规范更新.md)要求按主题修订、保留边界，不把整个项目的文档复制成 Skill。以下先列可改变下次决策的经验，再给具体合并位置。

## 可复用的工作流程

| 工作节点 | 应先回答的问题 | 产出与停止条件 |
| --- | --- | --- |
| 定义目标 | 是原版恢复、行为保持重构，还是已批准的产品适配？ | 一张范围/差异表；模板默认不覆盖源规则 |
| 固定输入 | 哪个包、源引擎、工作树、配置、构建、存档状态？ | 各自身份与 hash；dirty 内容不能只标 HEAD |
| 做功能与来源图 | 实际入口如何连接控制器、用例、数据、资产和存档？ | 可达性＋引用完整性＋绑定覆盖；隐藏/缺源/服务受限分别登记 |
| 选代表切片 | 哪条流程同时暴露 UI、规则、异步和持久化问题？ | 首页→背包/升级→战斗→奖励→返回→重开；先证实路线再批量扩张 |
| 分开转换和制作 | 哪些是导入基线，哪些已由开发者编辑？ | 原件/候选/工作资产/生成清单；Build 不重新导入或重造场景 |
| 验证语义 | 第一处差异出现在调用、数值、顺序、引用还是渲染？ | 小范围原始对照、类型化实现和第一分歧；未知项不以空方法放行 |
| 验证生命周期 | 第二次打开、失败、取消、回池、换关后发生什么？ | 订阅/任务/句柄/暂停引用的前后计数与晚回调检查 |
| 冻结交付 | 测试和构建是否改变输入，测试是否真的执行？ | 非零执行数、源码回读、包体清单、独立恢复；Player 单列 |

工作节点不是必须串行的行政审批。只读盘点、文档和独立分析可继续；依赖未完成时保留未验证状态。沿用用户已经授权的范围，不为每一个文件增加许可步骤。

Unity 假空组件、输入框激活/文字显示和数组布局等故障有局部代码与测试依据；它们不能自动推广为“全部 UI 已验收”。对源缺口、平台、实机输入和动态效果仍保留条件（E16、E18）。

K17补充（E31，修复效果仍待验）：列表初次冷启动、离屏创建后滚入、操作刷新后、页内重开、应用重开分别记录；排序后通过稳定业务ID定位对象，不用位置变化判断物品丢失。该项是验收设计，不将尚未验证的文本刷新补丁直接推广。

可并入相关主题的短约束：

> 组件与事件的覆盖必须到达实际动态实例。根页面绑定成功不代表延迟卡片、锁定/解锁分支和跨模块窗口业务已完整组合。原事件、controller、射线命中和真实输入分别记录；仅对源对象/节点/slot/handler/参数及无目标证据完全匹配的惰性声明设例外。

> 图片尺寸恢复先区分作者自定义、源原图、源裁切和Unity导入后尺寸，再核验初始化及每种换图入口。回归夹具使用刻意不同的尺寸，保留原位置/scale/pivot，避免错误映射因数值恰好相等而通过。静态总量不替代动态消费者验收。

> 对状态驱动的UI，连续验证更换选择后再执行升级/预览等操作，不能只观察第一次显示。初始化默认值仅填补缺失数据，不能覆盖已有偏好；面板关闭重开和应用进程重开属于不同测试。

> 独立工程或包直接声明自身运行依赖，不能靠可选Editor/分析工具的传递依赖维持编译。依赖版本集合、manifest和lock字节身份分别核验，profile声明过期要明确报告。

> 本地配置、资源、绑定和业务拒绝应保留首个失败类别及上下文；重试只用于明确可恢复的暂时失败。恢复任务可以保留源外显提示，内部不能因此把本地契约缺失误记成网络故障。

命名与目录已经有权威原则，本次仅补角色用语和反例，不新增“所有文件必须改名”的规则。正式Skill整合仍待后续实施。

## 可直接评审的增量文字

### 来源身份与完整调用链（K01、K03）

> 对跨引擎组件，来源身份应从实际序列化数据与注册表达式建立。只识别字面量可能漏掉常量绑定；解析不了的表达式、同 ID 不同类或关键递归引用缺失须明确失败。记录源 hash 和表达式位置，不用按名字猜测的通用 fallback 让流程继续。事件声明数、绑定控制器数、实际调用覆盖与可达玩家入口分别统计。

> 判断强类型迁移完成，需要沿真实输入到业务规则的路径确认动态桥已退出，并核对源码、资源、生成器、反射入口及 Player 程序集。C# 文件存在、编译成功或更换类名不证明规则已离开解释器/动态对象模型。旧参考执行器可在隔离 QA 中保留，但不进入生产工程或发行包。

### 随机、调度与回调（K02、K04）

> 恢复含随机比较器或共享随机流的规则时，除输出还比较调用序号、调用次数、后续状态和下一次抽取。比较器调度、移除顺序、定时器所属对象、微任务与帧末阶段都是待核对语义；不能用固定随机常数测试代替变化序列。新增表现随机独立，原本共享的消费保留。

> 视图绑定以当前实例和代次拥有。Unbind/Dispose 既解除监听，也使已捕获旧回调失效；回池与重绑之后不能更新新条目。布局缓存失效依据对象身份和几何/层级变化，不能只比较数量与尺寸。对删除公共 controller 后仍可触发的旧闭包安排反例。

### 制作、测试与构建（K05–K07、K09）

> 可编辑性须经过实际生产解析回读：修改工作配置或 Variant、保存/捕获、从运行加载路径读取，再恢复测试值。制作、校验、构建入口分责；Build 不重新生成已维护的工作资源。导出的配置候选只写声明的候选目录，检测已编辑文件，不隐式覆盖生产代码。

> 测试结果同时记录目标程序集、筛选器、预期范围、实际执行/失败/跳过数量及工具退出状态。零执行、仅 skipped、编译失败或中断不能算通过。若测试可能修改字体图集或其他制作资产，应先固定本轮已保存输入；在可控的独立副本或明确无并发编辑的测试上下文恢复并回读。来源不明的漂移保留现场，不能把另一位开发者的修改自动还原。

> 构建前保存已制作内容并捕获 Assets/Packages/ProjectSettings 等真实输入；构建后逐文件对照。允许的临时生成或制作变化需明确来源与范围，未解释的变化使输入身份门槛失败。Git HEAD、dirty 和内容清单同时记录。独立源码恢复验证自身完整性，不能借用父项目 Tools/Analysis；缓存命中不等于离线或全新机器验证。

### 来源模式与模板默认（K08、K10）

> 文件名、主对象显示名、GUID/local fileID、资源逻辑 key、源对象标识及第三方协议名分开维护。按业务用途改物理标签时，核对资源集合、依赖、子资源、图形几何与实际加载；来源字段或 Spine 页名不能因目录美化被批量改写。

> 本地广告完成只对明确批准的产品适配生效。模板默认无服务应返回不可用，QA 模拟需要显式启用并与真实服务证据分开。恢复已有游戏先保持原资格、消耗、奖励、保存和弹窗顺序；把奖励改成幂等事务是另一个行为重构目标，不与等价迁移混做。

## 暂不提升为通用规则或实现

- 不推广特定平台的保存目录、输入焦点补救键、窗口坐标、骨骼材质例外和业务额度。
- 不把样本单场景、来源共享随机或离线广告成功设成所有模板默认。
- 不将一次性迁移、项目 AST 转写器、源名称别名表和原始数值表复制进 grea。
- 事务账本、异步列表、模板 Input System 组合与真实广告接入都是待实现设计，无本轮运行通过结论。

后续整合时优先改上述既有主题，不新增十份相似参考。维护编号继续按类别共用。完成规范修改后再确定 Skill 新版本，运行结构/链接/场景检查、同步安装副本和独立 Skill 包回读；本次不提前改版本或重新安装。
