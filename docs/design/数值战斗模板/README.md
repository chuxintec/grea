# 数值战斗模板设计提案

设计版本：`0.1.0-draft.2`。复评日期：2026-10-15。状态：**文档、证据整理与合成示例；尚未实现模板或新增工具**。

本提案从一个已有发布基线和后续修复候选的 Cocos → Unity 数值战斗恢复工程提炼方法。该样本有战斗、技能选择、装备与养成、背包、活动、奖励、设置和多层弹窗，适合用来设计 grea 的第二种工程配方。结构与制作流程已基本成型，当前候选已有Mac专项交互与重开记录；完整原版一致性、高阶覆盖、受控性能和其他目标平台仍有缺口，不能外推为所有IAA游戏的通用模板。

本次形成四项成果：可并入 Skill 的条件性工作流、通用工具的提炼清单、Cocos 到 Unity 的迁移路线、数值战斗模板的架构与内容契约。公开内容使用匿名证据编号和新编合成数据；原游戏源码、数值表、资源、存档、原始报告及项目身份不随本提案分发。

## 本轮设计决定

| 问题 | 决定 | 原因及依据 |
| --- | --- | --- |
| 是否复制整个样本作为模板 | 不整包复制；提炼框架契约、模块骨架和制作流程 | 业务、来源适配、素材及未完成分支仍混合，E01、E10、E16 |
| 模板定位 | “数值战斗＋局外成长＋多页面 uGUI”的恢复工程起点 | 覆盖一个有代表性的系统组合，不承诺挂机、合成、跑酷等所有 IAA 类型 |
| 与现有标准关系 | 扩展现有分层与生成所有权，不新建竞争规范 | [Unity 工程标准](../../../plugin/skills/grea-unity-standard/references/05-Unity-工程结构与开发规范.md)仍为权威 |
| 是否保留 Cocos 兼容层 | 恢复项目按来源需要选择；新模板业务只依赖强类型端口 | 源引擎调度、随机和身份语义不能混入通用默认值，E06、E15 |
| UI 与奖励关系 | 新模板以持久化事务结果驱动展示；恢复模式先维持源顺序 | 样本中存在弹窗初始化与发奖相连的路径，直接复用会延续耦合，E10 |
| 框架与业务如何分开 | 复用 grea 现有基础包；战斗、养成和 UI Presenter 初期为 seed-once | 先验证复用点，再决定是否形成新公共包，避免空壳微包 |
| 首个目标环境 | 拟用 Unity 6000.6.2f1 / URP 17.6.0 / uGUI 2.6.0 / macOS arm64 Mono | 来自样本和 grea 的已有环境；是候选验证组合，不是新增支持声明 |
| 输入与场景 | 新配方拟用 Input System 1.20.0、Bootstrap＋Entry；逻辑页面在 Entry 内切换 | 样本是单场景，现有生成器是 legacy input；两处差异都需要后续实现和实测 |
| Skill 是否已经升级 | 本轮提供可评审的增量文字，不改动已安装 Skill 与版本 | 沉淀经验和执行规范升级分开；避免未实现设计成为日常强制规则 |

## 当前产品边界

设计名暂定 `grea-numeric-combat-ugui`，`0.1.0-draft.2` **不是可传给 CLI 的模板版本**。`examples/template-profile.example.json` 是设计说明数据，不是 `grea-project.json`，不得送入现有生成接口。

现有生成器只支持 `grea-minimal-2d/0.1.0` 的 Counter 配方；Foundation 包版本为 `0.2.1`，uGUI/Editor 为 `0.3.0`，生成器为 `0.1.2`（本轮合成示例的接入见实际框架说明）。输入支持、例外和现有工具语义以 [生成器指南](../../Unity工程生成与恢复.md)、`registry.json` 和源码契约为准。本提案没有修改这些声明。

本轮只读检查源码、历史报告和开发记录，未重新执行 Unity 测试、启动 Player 或操作原版。证据状态和报告适用范围见索引。后续实施必须重新固定样本字节，不能把本轮历史报告算作新模板的测试结果。

本次文档、示例关系、来源哈希与候选公开树的检查范围见 [本次复评检查记录](../../validation/2026-10-15-numeric-combat-review2.json)。[首版记录](../../validation/2026-10-15-numeric-combat-design.json)只对应其原文件哈希。
