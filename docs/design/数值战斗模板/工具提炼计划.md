# 通用工具提炼计划

本轮只评估脚本并定义提炼边界，没有移动项目工具、注册新 ID 或运行迁移。T 编号是设计工作项。具体项目源码/脚本位置保存在本地证据映射，公开文档通过 E/S 编号关联。

## 现有入口先复用

| 需求 | 已登记工具 ID | 本次核对后的边界 |
| --- | --- | --- |
| 文件身份、迁移前盘点 | `unity_asset_ledger`、`unity_dependency_audit` | 静态台账/引用检查；Unity 实际类型、子资源和运行加载仍需 Editor 回读 |
| 隔离源码快照/复制/验证 | `unity_pilot` | 已有 snapshot/clone/verify；不迁移源工程，不自动编译或验收玩法 |
| 参考源码分发恢复 | `unity_reference` | 当前固定 Signal Garden；不能把任意工程作为已支持输入 |
| 事件/数值比较 | `compare_events`、`compare_traces` | 接受已有格式的数据；不会自动建立 Cocos 的源 oracle |
| 包体清单、图像/录像辅助 | `verify_payload_tree`、`image_alpha_audit`、`video_manifest` | 清单、像素/媒体辅助，不证明画面、听感或输入正确 |
| 受控 Editor 调用 | `unity_cli`、`unity_pipeline` | provider 与真实连接必须核对；外层工具成功不等于 Editor 任务成功 |
| 原包解密/解包 | `wxapkg-decrypt`、`wxapkg-unpack` | 已登记的特定格式/provider；存在性不等于当前机器可运行，也不表示支持任意源版本 |
| 原配置导出 | `unity-export-config` | 当前实现与依赖按 describe-tool 核验；不冒充新的 Cocos Schema 生成器 |

`laya_contract_audit` 是明确的 Laya 解析契约，不能为省接口设计把 Cocos 输入强塞进去。历史项目自己的恢复脚本也不能未经审查替换既有 ID 的语义。实际参数以 [工具目录](../../../TOOLS.md)和源码为准。

## 提炼优先级与契约

| 工作项 | 输入 → 输出与副作用 | 现有基础/提炼决定 | 必需反例与完成条件 |
| --- | --- | --- | --- |
| T01 源码快照与独立恢复 | 明确 root、包含集、全新 output → 文件/hash清单；复制写入新目录；Editor恢复另一步 | 复用 `unity_pilot`，抽取复用的分发机制；不再复制一个写死项目名的脚本（E14、E19） | 不同 cwd、两个独立输入、symlink/越界/已有输出/变化中源；恢复不借父目录 |
| T02 测试回执判定 | Runner JSON/XML、期望程序集与范围 → valid/invalid/failed/not_run；默认stdout | 提炼实际执行数、编译/工具/测试状态与资源恢复字段（E11、E17） | 零测试“Passed”、全跳过、中断、坏XML、缺日志、编译失败、缺必测用例不能通过 |
| T03 制作输入与构建指纹 | 已保存输入、候选包、清单 → 前后差异/包身份；显式新报告 | 复用现有台账与包体工具，补 Editor Capture/Verify 接缝（E12） | HEAD相同但dirty不同、字体缓存写入、新增/删除文件、构建半途失败 |
| T04 Cocos 身份与引用审计 | 声明源版本、模块索引/常量/对象图 → source identity map、冲突/未解析清单；只读输入 | 项目提取器只作设计依据，不原样公开（E15） | 字面量/常量、重名、冲突、循环/跨图引用、未知表达式、资源缺失；未知版本拒绝 |
| T05 配置 Schema 与候选代码 | 经审查 schema＋Editor导出 → DTO/codec候选与hash；仅候选目录写入 | 提炼标准库 Python 编排与模板；保留项目生成器自包含（E07） | 未知列/重复键/缺列/null/有限数/键不符、候选人工改动、依赖缺表、关系错 |
| T06 UI 绑定与生命周期审计 | 原事件图＋实际typed映射＋Editor对象回读 → 缺绑定/重复所有者报告 | 静态和Editor两层输出，不能静态宣称真实输入（E04） | 同视图多控制器、旧闭包、二次打开、拒绝后再导航、缺目标/参数类型错 |
| T07 资产命名与身份对照 | Editor导出库存＋规则 → 只读改名计划；应用另需新计划身份与Editor执行 | 提炼导出/对照框架；本次一次性改名表和映射算法留项目（E13） | GUID/fileID/依赖/Sprite几何/逻辑key变化、大小写冲突、Variant失效；不只正则检查名字 |
| T08 规则 oracle 适配 | 冻结输入、显式项目parser/executor、命令序列 → 规范化轨迹 | 复用 `compare_events`/`compare_traces`，项目解释器仍是项目依赖（E06、E15） | RNG/排序/时钟首差异、状态相同但下一抽取不同、parser失败/超时不能略过 |
| T09 包体与旧桥退役检查 | 当前Player清单＋程序集引用＋禁止/允许项 → 发现项与范围 | 复用 `verify_payload_tree`，提炼程序集清单检查，不改vendor（E02、E16） | 改名的解释器、反射入口、Editor/Tests混入；供应包测试文件按来源单列 |
| T10 诊断预算 | UTF-8事件、session/operation身份、预算 → 项目内分段日志和统计 | 评估复用 grea diagnostics；特定会话日志器不是自动新增公共包（E18） | 多字节、超大行、重复会话、轮转、跨会话保留；日志量不是玩法证据 |

新增 T11：**工程身份与运行依赖预检**。输入项目profile、manifest、lock和显式运行依赖声明；只读输出过期hash、版本差异、运行包仅由可选工具带入的关系（E22、E23）。程序集源码引用只作为线索，不能凭using文本自动增删包。应覆盖“版本相同但文件hash不同”“解析依赖存在但没有直接声明”“可选连接包被移除”等反例；移除实验仅在独立副本执行。

先做 T11 和 T01–T03，契约明确且不依赖原游戏语义；T04–T06 支撑有限跨引擎切片。T06新增动态子项、精确惰性事件、raycast命中与BusinessReady覆盖；T07区分角色名、逻辑key与协议例外。T08–T10随真实消费者推进，不先铺满空工具。

## Python 统一入口的实现约束

未来 Python 编排/解析模块归 `src/grea/tools/`，由 CLI/MCP 共享执行层调度；仓库检查才归 `scripts/`。Unity 对象导出/制作继续用 Editor C# API，精确 C# 语义/token 分析可调用 Roslyn，JS AST 后端按必要能力选择。统一入口不意味着用正则重写完整 JS/C# 语法。

新增操作或工具前明确：参数、输入格式/版本、读写效果、输出大小、超时、退出码与 finding 语义，更新对应 contracts/registry/schema/帮助/测试。纯报告默认stdout，需要写报告时由调用者指定全新 run_dir；不得覆盖旧报告。开始运行前验证输入、输出根、路径重叠、符号链接、大小写/Unicode冲突，执行后回读源/目标。未覆盖恶意并发替换时如实标明边界。

调用 oracle 或项目解析器等同于执行代码，不应因“分析文件”就暗中执行源脚本。使用显式后端、受限参数和预算；未知结果保持 UNKNOWN/failed。日志输出位置和读取范围要清楚，不能默认联网下载缺失素材或把源码上传服务。

已有工具的 ID、参数、退出码和用途保持兼容。确实需要新语义时另行登记；示例不提供尚不存在的 grea 命令。新模板 profile 本轮也不进入正式 Schema。

## 不提炼清单

| 内容 | 留项目的原因 | 未来可提炼部分 |
| --- | --- | --- |
| 整个 JS→动态值C# 转写器 | 耦合原混淆形式、工厂、常量和运行时；活动写回已退役 | 输入身份、unsupported-syntax、候选保护、行映射与差分合同 |
| 原 UI 图、表数据、类别名和骨骼补丁 | 属于来源内容/项目语义，不是通用框架 | 数据格式适配接口与无源数据的合成夹具 |
| 一次性资源移动/代码分组脚本 | 绑定冻结旧路径、GUID 和当时工作树，重跑可损坏现状 | 只读计划、所有权、Editor执行与前后对照机制 |
| 固定机器的录屏、点击与Editor启动脚本 | 设备路径、窗口、坐标、Editor版本和项目名写死 | 显式参数、能力检测、实际进程身份与媒体验收清单 |
| 旧冻结规则执行器及第三方二进制 | 仅作项目QA、分发边界独立 | 规范化oracle输入输出和许可/依赖声明 |

两组不同的合成输入能发现参数化缺陷，但不足以宣布所有 Cocos 项目支持。来源解析器晋升为通用能力前，至少要有另一个不同布局/注册形式的获准样本，明确支持矩阵和拒绝项。
