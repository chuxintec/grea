## 第一条纵向切片

首个实现选择：启动新 QA 档 → 首页 → 背包中升级一个合成装备 → 进入一关两波战斗 → 暂停/恢复 → 固定奖励结算 → 返回首页 → 关闭应用重开 → 回读余额、装备等级、完成标记和设置。

同一条切片补失败路径：余额不足、缺配置引用、资源加载失败、重复领奖、弹窗创建失败、关闭中晚回调、写盘失败、旧schema/损坏档、战斗退出清理。额外广告奖励默认不可用；QA模拟与真实SDK分两套结果。

示例中的数值只用于证明合同，并不验证玩法乐趣、难度曲线或经济平衡。不要第一版就纳入几十种装备、全部活动和所有原技能。

## 验收沿用 A0–A5

| 门槛 | 本配方需要新增或加强的检查 | 必需证据 |
| --- | --- | --- |
| A0 结构/配置 | 模块有消费者、纯规则无Unity引用、依赖无环；表关系与插件选择；InputSystem显式支持 | 配置与依赖锁hash、实际程序集、未支持项；例外不能让生成器静默放行 |
| A1 生成/身份 | generated/package/seed-once/human分界；同输入二次生成稳定；未知/人工文件保留 | planId、逐文件hash/GUID/fileID、冲突/恢复回执；不在活工程拼YAML |
| A2 Editor | 编译与真实Prefab绑定、唯一EventSystem、Variant/配置生产回读、字体/材质/遮罩 | 实际Editor版本、对象级定位、真实执行数；零测试/编译失败不得通过 |
| A3 生命周期 | 入口到结束再进入、弹窗两轮、列表往返、池化复位、延迟/失败/取消和事务 | 初始/结束资源与监听计数、结构化轨迹、幂等receipt、save错误回读 |
| A4 目标Player | 普通/QA隔离，鼠标/键盘/IME/滚动、声音/静音/失焦、窗口适配、退出重开 | build/payload/source身份、设备/后端、操作/画面/音轨；Windows另测 |
| A5 隔离迁移 | 原规则/存档/共享RNG/调度/资源身份保持，受影响入口和性能可比 | 原/新固定输入与差分、原版同状态动态记录；未经批准不改原项目 |

纯模板首次发布的A5可明确不适用，不能因此宣布已能自动迁移既有工程。Cocos适配试点必须另做A5。

## 关键反例和可观察预期

| 注入/操作 | 预期 |
| --- | --- |
| 同operationId同请求重复完成 | 相同receipt，库存/次数只变化一次 |
| 同operationId换参数，或不同operationId重用claimKey | 前者明确冲突，后者已领取；均不重复入账 |
| 广告成功回调重复/晚到 | 只提交一次；视图已销毁则不操作它；所属业务作用域仍有可查结果 |
| 存档提交结果未知后重试 | 使用原operationId查询/恢复，不能换ID再扣费 |
| 冷启动离屏创建后首次滚入，再升级触发排序 | 初次文本/图标可见；按稳定ID回查物品；不能用刷新后的正常掩盖初次空白 |
| 同样行数的列表换了一批对象 | 名称/图标/布局/监听更新，旧资源回调无效 |
| 原图、trim、作者框、Unity导入尺寸各不相同 | 每种源模式和赋值入口采用正确尺寸；位置/scale保持 |
| 根页面成功，延迟卡片缺一个控制器 | 未达到BusinessReady；指出具体子实例；已知源惰性事件只精确例外 |
| 按钮方法可调用，但Graphic不参与射线 | 输入层验收失败；不把业务单测记为点击通过 |
| 先更换选择再连续升级/预览 | Presenter与View使用新选择，重开仍一致 |
| 包版本集合没变但manifest/lock字节变了 | 身份预检报告hash漂移；不能按版本相同放行 |
| Modal创建失败或关闭动画中销毁 | 遮罩、焦点、暂停引用都释放；设置页还能打开 |
| 配置增加未知列或引用不存在ID | 导入/启动前定位错误，不自动删列或改为零 |
| 测试只发现0项或全跳过 | invalid/not_run，不标pass |
| 测试/构建修改制作字体 | 检出具体文件；恢复仅限明确保护范围；输入身份未闭合不能交付 |
| 默认初始化碰到已有玩家偏好 | 尊重已保存值；弹窗关闭重开与应用进程重开都检查 |
| 从源码包在另一新目录恢复 | 不读取父项目Analysis/Tools，不依赖绝对file包路径；依赖来源和缓存前提明确 |

时间预算、日志预算和性能阈值在实现开始时依据目标设备/场景设定；不在文档中虚构所有设备都能达到的帧率。密集战斗、UI冷/热切换要固定关卡、敌人数/技能、存档和画质；按 [性能规范](../../../plugin/skills/grea-unity-standard/references/05-Unity-性能分析与优化验证.md)记录多轮帧时、CPU、GC与内存，不能用Editor微基准替代Player性能。

## 版本、所有权与交付

- 设计版本与 grea 产品/Skill/模板/包版本分开；本轮不增加可执行模板版本。
- 实现后新模板正式版本必须能回指recipe、生成器、包锁与本次输入；旧Counter及工具ID保持兼容。
- 工具实现归 grea；项目专用oracle、补丁、来源表和素材继续归项目。泛化不等于把原Tools移走后留下链接。
- Skill只收决策规则与工具路由；详细模板用法归docs，机器契约归源码/生成Schema，例子归独立示例目录。
- 独立Skill包、完整使用包、未来模板源码包分别说明内容与版本。未来Player只发布已验目标，不能用源码压缩包冒充使用包。
- 任何真实接入广告/支付/分析SDK都需要新的明确范围和实际验证；本提案不选择供应商或写入服务配置。

在首个完整闭环和独立恢复通过前，模板应标为实验性；在另一个结构不同的隔离样本验证之前，Cocos工具保持声明版本/格式的有限支持。
