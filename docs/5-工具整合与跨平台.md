# 工具整合与 macOS／Windows 支持

系统与 CPU 条件以 [registry.json](../registry.json) 的 host_support 为准。跨平台可移植性、模拟测试与原生实测必须分开报告。

## 整合结果

| 候选 | 已执行处理／保留理由 |
| --- | --- |
| doctor、registry_doctor、decode-doctor | 统一到 application.doctor 和受控 runner。两个旧名字兼容；默认只查存在，版本／帮助须显式选择工具。取消重复的全量启动、另一套超时及截断实现 |
| check_game_build_skill / check_grea_skill | 旧名变成注册表 alias_of，只保存一份执行契约 |
| android_emulator_arm32_legacy / android-emulator-arm32 | 库存旧名变成正式工具别名，共用平台限制和执行定义 |
| recovery / grea legacy | 统一到同一 legacy_main，保留原参数及退出码；Windows 不使用 POSIX exec 替换 |
| compare_events / compare_traces | 事件工具保留 seq／event／state 和递增验证；改为直接调用公共比较函数，移除额外 Python 子进程，不删除语义检查 |
| AssetRipper / UnityPy | 保留：工程／Prefab 恢复与字段／批量资源提取不同，不能互相完全替代 |
| Cpp2IL / Il2CppDumper / Redux / ILSpy | 保留：metadata／原生代码／托管反编译及第二解析器用途不同；Redux 仍为条件性辅助路线 |
| Spine 3.8 / 4.1 | 保留：版本格式和 API 不兼容，不将多版本依赖误删为重复 |
| scripts/testing 与 grea runner | 保留：前者控制测试内存、后者统一 Provider 日志／时间／回执，当前不具备完全替代关系 |
| 本机第三方源码／归档／安装备份 | 不随源码分发；按需自行安装，来源与接入说明集中在 docs/providers |

兼容别名共享唯一执行定义；多版本运行时与互补分析器按功能保留。平台 SDK 的固有目录名不能随产品重命名而替换。

## 平台结论

| 层次 | macOS | Windows | 处理方式 |
| --- | --- | --- | --- |
| Python CLI／MCP、静态检查和纯 Python helpers | 本机测试通过 | 源码路径具备可移植条件，未原生实测 | Windows 启动器已添加；在目标机重新建 .venv，不能复制 Mac venv |
| case 基线／证据／审阅文件锁 | POSIX 本机通过 | 当前不支持 fcntl | 明确报 UNSUPPORTED_HOST；在接入 Windows 文件锁与并发测试前，不使用这些写操作 |
| 进程超时／取消 | 清理所属进程组 | 只管理直接子进程，未实测 | Windows 重型／会派生子进程的引擎须补 Job Object 等生命周期管理后验收，不能宣称具备相同清理保证 |
| AssetRipper、Cpp2IL、Redux、Mac .NET、Homebrew 包装器 | 按实际 CPU／依赖；部分绑定 ARM64 | 仓库内 Mac 程序不可直接运行 | 下载同工具匹配版本的 Windows 发布物，验证来源／哈希，显式配置原生命令，再做真实样本测试 |
| ffmpeg／ffprobe／scrcpy／NSIS／pngquant | 本机实际安装状态为准 | 需要 Windows 原生依赖和 PATH | presence 只检查存在，指定 probe 和样本逐项确认 |
| Unity CLI／Pipeline／Editor | 官方接口独立验证 | 需要 Windows 对应安装、许可、项目和配置 | 不把 Mac 的 ~/.unity 或 .codex 绝对路径复制成 Windows 可用性证明 |
| Android SDK／ADB | 已修复并实测版本入口 | 另装 Windows platform-tools | 用 Windows adb.exe 的明确路径覆盖相同 provider；服务端手机 ABI 与电脑系统是不同维度 |
| 旧 ARM32 Android 模拟器 | 固定 Darwin 历史二进制 | 当前归档不支持 | 使用官方 Windows 模拟器，另核对 ARM32 游戏的实际兼容性；不得静默替换后声称同一原生环境 |
| Spine 源码、Unity 包归档、托管 DLL 库存 | 资料存在不代表导入成功 | 同样只属于库存 | 使用对应 Unity／.NET 版本，重新编译、导入和运行 |

每项登记都有系统及必要的 CPU 限制。错系统／架构会在启动前报 UNSUPPORTED_HOST／UNSUPPORTED_ARCH，不会尝试执行 Mac 程序，也不会自动换分析器。Windows/Linux 的 portable_unverified 只表示可移植候选，不代表原生实测通过。

## Windows 部署和显式配置

安装与启动、请求文件、MCP 配置、GREA_PROVIDERS 模板及排错统一见 [使用说明](0-使用说明.md)。先核对本页平台限制，再按使用说明部署；平台支持的结论不因配置文件存在而升级。

## 本轮验证与后续 Windows 验收

复验当前版本时分别记录公共接口、兼容别名、平台路由、原生依赖、事件校验与跨目录启动的结果。原始本机日志和业务案例不随仓库分发。

Windows 尚需：在原生 Windows x64 重新部署依赖，执行 CLI／MCP 往返与两组真实样本；实现并测试 case 的 Windows 锁；验证父子进程超时／取消；实际打开 Unity 工程与目标制品。完成前不将整套工具标记为 macOS／Windows 等价支持。当前机器无法完成这些原生验证，已保留明确缺口。

官方依据（核对于2026-10-12）：[uv 平台支持](https://docs.astral.sh/uv/reference/policies/platforms/)、[AssetRipper 发布平台](https://assetripper.github.io/AssetRipper/articles/Downloads.html)、[Cpp2IL 官方用法](https://github.com/SamboyCoding/Cpp2IL)、[Python Windows 文件锁](https://docs.python.org/3/library/msvcrt.html)。上游支持 Windows 不等于本机另行安装的 Mac 二进制支持 Windows。
