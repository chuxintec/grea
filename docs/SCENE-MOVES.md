# Scene moves and derived Build Settings

Existing `batch plan/apply/recover` handles scene `asset.move` steps without a new command. The planner inspects `ProjectSettings/EditorBuildSettings.asset` when a selected scene is registered there. Each affected entry must have one exact source path and the source `.meta` GUID; duplicate GUID/path registrations, mismatches and occupied target registrations block planning.

The plan adds `sceneSettings` with the settings path, before SHA/byte count, exact expected-after SHA/byte count, and reviewed `{source,target,guid}` rows. The expected bytes come only from replacing the selected native-format `m_Scenes` path-value spans. Flags, GUIDs, ordering, line endings and all other bytes remain bound. The settings file joins the read/write set and verified before-images. An unlisted scene has no derived settings write. Unsupported or ambiguous registrations are not silently repaired.

Apply uses `AssetDatabase.MoveAsset`; it does not rewrite YAML to manufacture the expected result. Native readback checks the exact serialized settings hash and unique target path/GUID registrations, and Python independently checks the saved file. Any additional byte change or unexpected source mutation retains a failed/recovery-required transaction. Scene identities now combine the main asset and all imported subassets, deduplicated by persistent identity. Empty GUIDs, localID zero and an empty SceneAsset identity set cannot count as preservation; legitimate negative localIDs remain valid.

The runtime job explicitly carries `hasSceneSettings`, including recovery, so omitted nested JSON objects cannot accidentally activate this path for ordinary batches. Successful reports expose `sceneSettingsReadback` with the path, expected/observed SHA, status and verified moves. This is file/identity verification, not gameplay or visual acceptance. A separate native readback can verify saved scene fields after reopening.

Recovery requires the exact witnessed after-state. It reverses engine moves, restores hash-verified before-images, removes only owned empty generated folders, and verifies original settings bytes and source path/GUID registrations. Later changes block automatic restoration. Existing failed transactions retain their original producer and verdict; use a new fixed candidate and new plan for future work.
