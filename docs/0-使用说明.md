# grea 使用说明

本页是安装与日常调用的统一入口。参数定义以 [操作契约](../schemas/operations.json) 为准；工具名称和平台要求以 [注册表](../registry.json) 为准。不要用历史验证报告中的机器路径替代当前路径。

## 1. 先确认目录和平台

本文所有相对命令默认从 **grea 仓库根目录**执行，即直接包含 pyproject.toml、README.md 和 bin 的目录。独立克隆可以放在任意位置。

```text
grea/                 Git 仓库根目录
  AGENTS.md           产品维护规则
  README.md           阅读导航
  pyproject.toml      Python 工程
  bin/                启动入口
  src/                CLI／MCP 实现
  skill/              游戏恢复规范
  docs/               使用和维护说明
  registry.json       工具登记
  .venv/              本机生成，不提交
```

游戏项目、客户端配置和工作区 memory 位于仓库外；可选接入方式见 [独立仓库与工作区接入](7-独立仓库与工作区接入.md)。

macOS Apple Silicon 已有本机验证。Windows 提供启动器及部分可移植能力，但 case 文件锁尚不支持 Windows，重型工具的子进程清理也不等价。开始前阅读 [平台结论](5-工具整合与跨平台.md#平台结论)，不要把 Mac 二进制复制到 Windows 后直接运行。

## 2. 首次安装

先准备 Git 和 uv；Python 版本要求见 [pyproject.toml](../pyproject.toml)，依赖版本固定在 uv.lock。公开源码不使用 Git LFS，也不包含本机工具安装副本。已有工作区跳过克隆步骤。

```sh
git clone https://github.com/chuxintec/grea.git grea
cd grea
```

以下命令在仓库根目录执行，macOS／Windows 相同：

```sh
uv sync --frozen
```

这一步建立 grea 自身的 Python 运行时，**不代表已安装所有第三方工具**。Unity、Android SDK、Java、.NET、Homebrew 工具及独立 UnityPy／Frida 环境按本次任务另行检查，见 [工具目录](../TOOLS.md) 和 [第三方依赖](../THIRD_PARTY.md)。独立的 Python wheel 不包含完整工具库；采用完整仓库源码部署。没有工具本体时 unavailable 是预期结果；通过 `GREA_PROVIDERS` 配置自己安装的版本，不以启动包装器存在替代安装。

已有环境且依赖未变，不需要每次重新安装。新机器必须重建 .venv，并核对项目 MCP 配置中的绝对路径。

## 3. 启动与首次检查

| 系统 | 从仓库根目录调用 |
| --- | --- |
| macOS | `./bin/grea session` |
| Windows | `.\bin\grea.cmd session` |
| 已有 Python 的跨平台入口 | `python launch.py session` |

session 返回 JSON。先确认 status 为 ok，再查看 result.version、package_root 和 providers。此操作不启动 Unity Editor；live_unity_connection 为 not_checked 是预期状态。

运行 `list-tools` 查看完整登记，运行 `describe-tool` 查看一个工具。不要每次都运行无关工具的版本探测。后续示例使用 macOS 启动前缀；Windows 将 `./bin/grea` 替换为 `.\bin\grea.cmd`，其余参数相同。

## 4. 统一的参数写法

无参数命令直接调用；带参数命令推荐 **JSON 请求文件**，避免不同 shell 的引号差异。文件保存为 UTF-8 无 BOM，只包含一个 JSON 对象，不含注释。字段名、字符串和布尔值区分类型。

例如将以下内容保存为当前目录的 describe.json：

<!-- grea-operation: describe_tool -->
```json
{"tool_id":"unity_dependency_audit"}
```

```sh
./bin/grea describe-tool --input describe.json
```

macOS shell 也可使用内联 JSON：`./bin/grea describe-tool '{"tool_id":"unity_dependency_audit"}'`。两种写法不可同时使用。请求文件内部的相对路径按调用工作目录解析，**不是按请求文件所在目录解析**；跨项目调用优先使用绝对路径。

下面所有 `/absolute/...` 都是需要替换的占位路径。Windows JSON 中使用 `C:/workspace/...`，或将反斜杠写成 `C:\\workspace\\...`。

## 5. 按顺序完成一次任务

### 检查本次依赖

保存为 doctor.json：

<!-- grea-operation: doctor -->
```json
{"tool_ids":["unity_dependency_audit"],"probe":true}
```

```sh
./bin/grea doctor --input doctor.json
```

不传 probe 或设置 false 时只检查存在；probe=true 必须明确选择 tool_ids。detected 表示检测到文件／命令，probe_passed 表示版本或帮助调用通过，均不表示已成功处理游戏包或连接 Editor。

### 检查原包并选择流程

保存为 inspect.json：

<!-- grea-operation: inspect_target -->
```json
{"path":"/absolute/project/Reference/game.apk"}
```

保存为 plan.json：

<!-- grea-operation: plan_workflow -->
```json
{"mode":"recover","source_engine":"unity"}
```

```sh
./bin/grea inspect-target --input inspect.json
./bin/grea plan-workflow --input plan.json
```

inspect-target 检查身份和库存，不自动解包。默认字节预算为 256 MiB，文件超过预算时需显式调整 max_bytes。plan-workflow 只返回路线，不执行恢复；按返回的 reference 和 tool_ids 继续工作。

| mode | 本次目标 |
| --- | --- |
| recover | 完整恢复／首次重建 |
| fix | 局部一致性修复 |
| reskin | 已授权换皮 |
| refactor | 工程结构或 UI 迁移 |
| performance | 性能优化 |
| deliver | 构建、预览或交付 |
| maintain | 工具、规范或复盘维护 |

完整开发方法由 [规范技能](../skill/SKILL.md) 维护，本页不复制游戏验收流程。

### 优先调用具名操作

例如审核导出的 Unity Assets 依赖，保存为 audit.json：

<!-- grea-operation: audit_unity_dependencies -->
```json
{
  "assets":"/absolute/project/Export/Assets",
  "roots":["GameObject/Panel.prefab"],
  "output":"/absolute/project/Analysis/dependency.json",
  "run_dir":"/absolute/project/Analysis/run-001"
}
```

```sh
./bin/grea audit-unity-dependencies --input audit.json
```

先确认根资源存在，并准备 Analysis 父目录；run-001 及报告文件必须尚不存在。roots 中的资源路径相对于 assets。重复执行时换用新报告文件和新 run_dir，不覆盖上一轮证据。

其他具名操作包括 snapshot-unity-assets、compare-gameplay-traces、inspect-numeric-texture；按操作契约填写参数。

### 其他工具使用受控执行入口

保存为 run.json：

<!-- grea-operation: run_tool -->
```json
{
  "tool_id":"compare_events",
  "arguments":["/absolute/project/Evidence/original.jsonl","/absolute/project/Evidence/candidate.jsonl"],
  "run_dir":"/absolute/project/Analysis/run-002",
  "timeout_seconds":120
}
```

```sh
./bin/grea run-tool --input run.json
```

arguments 是参数数组，不是 shell 命令字符串。工具在新 run_dir 内运行，数组中的文件路径须用绝对路径。目录内保存 stdout.log、stderr.log、run.json；查看回执中的原始退出码和限制。工具参数查 [专用脚本说明](tools/1-制品工具.md) 或执行 `./bin/grea legacy compare_events --help`。

legacy 保留工具原生输出和退出码，不提供统一回执与执行预算。仅用于参数帮助、兼容调用或明确需要原生接口的场景；不把 legacy 的退出码解释成 grea 标准退出码。

## 6. 可选的项目证据记录

以下 case 操作当前要求 POSIX 文件锁，Windows 暂不使用。普通查询无需初始化 case；需要保存项目基线及审阅记录时才使用。项目目录必须已存在，source 是基线文件，不是目录。

保存为 case.json：

<!-- grea-operation: init_case -->
```json
{"project_dir":"/absolute/project","source":"/absolute/project/Reference/game.apk","mode":"recover"}
```

```sh
./bin/grea init-case --input case.json
```

该操作新建项目内 .grea，已存在时拒绝覆盖。登记真实证据文件，保存为 evidence.json：

<!-- grea-operation: add_evidence -->
```json
{"case_dir":"/absolute/project","kind":"original_runtime","path":"/absolute/project/Evidence/original.mp4","description":"原版同版本关卡入口录像"}
```

```sh
./bin/grea add-evidence --input evidence.json
```

保存返回的 evidence.id。随后按 [证据契约](2-接口与证据契约.md#项目内记录) 登记候选运行等材料，使用 record-verification 记录实际审阅结果和这些 ID。没有执行的项填 not_run；不能为凑齐维度直接填 passed。

状态查询保存为 status.json：

<!-- grea-operation: case_status -->
```json
{"case_dir":"/absolute/project"}
```

```sh
./bin/grea case-status --input status.json
```

ready_for_review 表示记录及角色条件齐备，不表示 grea 已验证游戏等价；原文件变化会导致旧证据失效，先查原因，不手改哈希绕过。

## 7. Agent 与 MCP 使用

Agent 可以读取本仓库 `skill/SKILL.md`；需要技能发现时按工作区接入说明同步完整技能（技能名 `$grea`），按当前任务加载所需流程。技能是规范入口；MCP 是工具通信入口，二者不是相互替代关系。

已有外部工作区配置时先核对其 `.codex/config.toml`，不要重复添加同名服务。新机器按真实路径配置下列 grea 服务，保留其他服务和插件配置。

macOS 示例：

```toml
[mcp_servers.grea]
command = "/absolute/workspace/grea/bin/grea"
args = ["mcp"]
startup_timeout_sec = 30
tool_timeout_sec = 180
```

Windows 示例（使用正斜杠避免 TOML 转义）：

```toml
[mcp_servers.grea]
command = "C:/workspace/grea/.venv/Scripts/python.exe"
args = ["C:/workspace/grea/launch.py", "mcp"]
startup_timeout_sec = 30
tool_timeout_sec = 180
```

客户端加载配置后，实际发现 grea 工具并调用 session，才算完成该客户端的连接验证。CLI 名称使用短横线，MCP 使用下划线，如 inspect-target 对应 inspect_target。终端手动运行 mcp 会等待协议输入，不出现提示符是正常行为；不要将普通命令文本输入该进程。MCP 不等于 Unity Editor 已连接。

## 8. Windows 原生工具配置

先安装同工具对应的 Windows 版本，核对来源、版本与哈希。复制 [配置模板](../providers.example.json) 为本机的 providers.local.json，替换示例路径；模板不会自动生效或安装依赖。不要复制 Mac .venv 或让 Windows 执行 Mach-O 二进制。

```powershell
$env:GREA_PROVIDERS = 'C:\workspace\grea\providers.local.json'
.\bin\grea.cmd describe-tool --input describe.json
.\bin\grea.cmd doctor --input doctor.json
```

此时 describe.json 和 doctor.json 应选择你配置的同一工具 ID，例如 assetripper。先核对 configuration_source、实际命令及系统要求，再探测与执行真实样本。本地配置是受信任的执行配置，不能从游戏包或反编译文本自动生成后执行；不提交含本机路径的 providers.local.json。

## 9. 判断结果与排错

| 现象 | 含义与处理 |
| --- | --- |
| status=ok，退出 0 | 本次操作完成；按操作边界判断，不推导为游戏还原通过 |
| status=partial，退出 1 | 有差异、缺口、预算范围限制或内联预览省略；读取 result／limitations 及落盘日志 |
| status=error，退出 2 | 操作失败；根据 error.code 定位 |
| runtime missing | 确认仓库根目录，执行安装步骤建立本机运行时 |
| INVALID_JSON / INVALID_ARGUMENTS | 检查 UTF-8 无 BOM、JSON 格式、字段名、类型和必填项 |
| EXPLICIT_SELECTION_REQUIRED | doctor 的版本探测需指定 tool_ids |
| PROVIDER_UNAVAILABLE | 查 describe-tool；安装／恢复指定依赖，不盲换解析器 |
| UNSUPPORTED_HOST / UNSUPPORTED_ARCH | 系统或 CPU 与登记不符；查平台说明，配置匹配的原生版本 |
| OUTPUT_EXISTS | 换新 run_dir／报告路径，保留旧证据 |
| RESOURCE_LIMIT / OUTPUT_LIMIT / TIMEOUT | 先看预算、日志和进程状态；按需要缩小输入或显式提高预算，不无条件重跑 |
| STALE_SOURCE / STALE_EVIDENCE | 原包或证据已变化；确认版本后建立新基线，不冒用旧结论 |
| INSUFFICIENT_EVIDENCE | 审阅项缺必需的证据角色；补实际证据后再审阅 |

完整输出字段、默认预算与证据边界见 [接口契约](2-接口与证据契约.md)。运行预算目前限制时间与日志，不提供硬性 RSS 内存上限。
