# Unity saved-Prefab selection handoff

`freeze-native-selection` creates a fresh Unity project containing selected saved Prefabs and their addressable dependency closure. It does not edit the source candidate. It requires the exact candidate `manifest.json` SHA and `Analysis/Readback/editor-readback.json` SHA, checks the original Unity 6000.6.2f1 Editor readback, and calls the existing Unity Editor verifier at `level=editor`. Static and native-static validation must pass; only the known unexecuted Spine behavior and animation-curve diagnostics may remain.

The selection input is a set of canonical project-relative `.prefab` paths. The tool follows Unity YAML GUID references, preserves referenced project file bytes and metadata identities, includes available containing-folder metadata, and includes the project `Packages/manifest.json` and `packages-lock.json`. Package GUIDs are recorded with package name/version from installed `Library/PackageCache`; they are external dependencies and are not copied into the selection. The package lock is itself hash-bound as a supplemental retained file when the generation manifest does not own it. Declared exact manifest versions must equal the lock; the Unity package files remain the version authority.

Shader source also follows literal `#include` / `#include_with_pragmas` project paths recursively, with the same saved-file authority and metadata rules. `shaderDependencies` records these edges separately from C# compile dependencies. A small explicit set of Unity built-in include names is recorded as engine-provided; a same-named project file takes precedence and is carried. Unknown, macro-expanded, unsafe or missing includes fail selection. This closure does not establish target shader compilation. Diagnostics are emitted in a stable path/code order.

Selected project files are admitted only from the candidate owner manifest or the pinned native readback. Native-only files may include saved Prefabs, resources and metadata, all pinned by `nativeFiles`. All candidate manifest entries are hash checked: native readback hashes take precedence for files Unity saved, while non-native files must still match the generated manifest exactly. `ProjectSettings/ProjectVersion.txt` may differ only when the existing verifier confirms the same normalized Unity version; both generated and saved hashes are recorded. Symlinks in carried project/evidence scopes, duplicate GUIDs, unresolved non-builtin GUIDs, unowned files reached by the selected closure, hash drift, and missing declared compile dependencies stop the operation. Unrelated project files are left out. Built-in Unity zero-GUID references are recorded as engine-provided references.

The output `manifest.json` preserves the candidate and readback hashes, selection, source verification evidence, external package references, selected file hashes/owners, and `adoptionDependencies`. That section uses schema version 1 and `coverage: "producer-declared"`, with edges shaped as `{path, requires, kind: "csharp-compile"}`. Legacy static-sort templates use their pinned SHA256 identities. Current static-sort and input script edges are emitted only when candidate bytes match the corresponding bundled producer template in this monkey checkout. An absent declared dependency fails the freeze; other generated C# files receive an explicit `UNANALYZED_CSHARP_DEPENDENCIES` diagnostic. This is not arbitrary C# or assembly analysis, and coverage must not be described as complete.

When the candidate has a system-font readback, the output also includes its evidence SHA and `nativeFontCoverageContract`. The supplemental `Analysis/Readback/system-fonts.json` is not treated as a member of the main `nativeFiles` list: its source-manifest, IR, resolution-receipt, target-environment, and static-SDF receipt identities are checked against the hash-owned import plan. Saved font asset GUID/SHA binding is then audited against the selected native files. DynamicOS coverage remains unknown outside explicitly recorded text checks.

No `Library` tree is copied. Prefab YAML and selected asset bytes are carried without rewriting. Project business code, generated artifacts outside the selected closure, and unknown producer compile edges are not inferred or silently brought in.
