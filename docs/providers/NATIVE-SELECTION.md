# Unity saved-Prefab selection handoff

`freeze-native-selection` creates a fresh Unity project containing selected saved Prefabs and their addressable dependency closure. It does not edit the source candidate. It requires the exact candidate `manifest.json` SHA and `Analysis/Readback/editor-readback.json` SHA, checks the original Unity 6000.6.2f1 Editor readback, and calls the existing Unity Editor verifier at `level=editor`. Static and native-static validation must pass; only the known unexecuted Spine behavior and animation-curve diagnostics may remain.

The selection input is a set of canonical project-relative `.prefab` paths. The tool follows Unity YAML GUID references, preserves referenced project file bytes and metadata identities, includes available containing-folder metadata, and includes the project `Packages/manifest.json` and `packages-lock.json`. Package GUIDs are recorded with package name/version from installed `Library/PackageCache`; they are external dependencies and are not copied into the selection. The package lock is itself hash-bound as a supplemental retained file when the generation manifest does not own it. Declared exact manifest versions must equal the lock; the Unity package files remain the version authority.

Shader source also follows literal `#include` / `#include_with_pragmas` project paths recursively, with the same saved-file authority and metadata rules. `shaderDependencies` records these edges separately from C# compile dependencies. A small explicit set of Unity built-in include names is recorded as engine-provided; a same-named project file takes precedence and is carried. Unknown, macro-expanded, unsafe or missing includes fail selection. This closure does not establish target shader compilation. Diagnostics are emitted in a stable path/code order.

Selected project files are admitted only from the candidate owner manifest or the pinned native readback. Native-only files may include saved Prefabs, resources and metadata, all pinned by `nativeFiles`. All candidate manifest entries are hash checked: native readback hashes take precedence for files Unity saved, while non-native files must still match the generated manifest exactly. `ProjectSettings/ProjectVersion.txt` may differ only when the existing verifier confirms the same normalized Unity version; both generated and saved hashes are recorded. Symlinks in carried project/evidence scopes, duplicate GUIDs, unresolved non-builtin GUIDs, unowned files reached by the selected closure, hash drift, and missing declared compile dependencies stop the operation. Unrelated project files are left out. Built-in Unity zero-GUID references are recorded as engine-provided references.

The output `manifest.json` preserves the candidate and readback hashes, selection, source verification evidence, external package references, selected file hashes/owners, and `adoptionDependencies`. That section uses schema version 1 and `coverage: "producer-declared"`, with edges shaped as `{path, requires, kind: "csharp-compile"}`; paths and requirements remain project C# sources. Paired assembly and runtime files are recorded separately in `spineRuntimeClosure` without extending this version-1 consumer contract. Legacy static-sort templates use their pinned SHA256 identities. Current template edges require an exact match to the bundled producer source, including declared framework-only layout, progress and evidence helpers. `NativeChildLayoutGroup` is declared within the linear-layout source itself. An absent declared dependency fails the freeze.

Generated disabled static-field carriers require exact regeneration from the original hash-owned import plan, matching class/namespace, safe field identifiers, field schema, generated bytes and script digest. The proof covers compilation only: Unity object references do not imply recovered source behavior. `codeDependencyAnalysis` records every recognized script's hash, proof profile, project requirements and framework/locked-package boundary, including leaves with no project-script requirements, plus the carrier plan pin. Unrecognized or modified C# retains `UNANALYZED_CSHARP_DEPENDENCIES`; a filename or comment is never sufficient proof. This is not arbitrary C# or assembly analysis, and coverage must not be described as complete.

When the selected GUID closure contains the staged Spine helpers or plugin assets, the freeze requires the owner-manifest-pinned import plan and its `spineNativeStage`. It verifies the stage contract, runtime manifest and exact player DLL, license and package-shader hashes; both Editor-only DLLs must match the pinned Editor-build evidence and form the declared core/Unity pair. All four DLLs need their staged `PluginImporter` metadata with mutually exclusive Editor/Player scopes. Source profile shaders and their metadata are included from stage rows. The external runtime-build evidence is read by its pinned path/SHA and is recorded, not copied. Missing, changed or incomplete pair evidence blocks the freeze. The exact bundled `UnitySpineGraphicMaterialPresentation` requires `NativeStaticMaskIdentity`; `UnitySpineSourceIdentity` has no project-script dependency. Other producer C# remains explicitly unanalyzed. `spineRuntimeClosure` records the copied closure and keeps native assembly load/runtime behavior separate; no Editor is started and runtime execution remains `not_run`. Consumers must carry this entire frozen runtime closure or separately prove equivalent existing runtime mappings; the C#-only version-1 dependency edges do not certify assembly adoption. The supplemental dependency audit recomputes the Spine closure from the original pinned producer and rejects omitted or changed runtime files.

When the candidate has a system-font readback, the output also includes its evidence SHA and `nativeFontCoverageContract`. The supplemental `Analysis/Readback/system-fonts.json` is not treated as a member of the main `nativeFiles` list: its source-manifest, IR, resolution-receipt, target-environment, and static-SDF receipt identities are checked against the hash-owned import plan. Saved font asset GUID/SHA binding is then audited against the selected native files. DynamicOS coverage remains unknown outside explicitly recorded text checks.

No `Library` tree is copied. Prefab YAML and selected asset bytes are carried without rewriting. Project business code, generated artifacts outside the selected closure, and unknown producer compile edges are not inferred or silently brought in.

For an already finalized selection, `audit-native-code-dependencies --candidate <frozen> --expected-manifest <sha> --producer-candidate <original> --expected-producer-manifest <sha> --out <fresh>` writes an independent `code-dependency-supplement.json`. It verifies every target file and the target's original producer-manifest lineage. Template profiles are evaluated against the actual target script hashes, so a later runtime revision cannot borrow proof for older bytes. Carrier proof regenerates from the pinned original producer plan and joins its result to the exact target script hash; the plan need not be copied into the finalized target. Each script includes dependency paths and target hashes, package manifest/lock identities and a proof profile. Modified or unknown scripts remain in `uncovered`; original diagnostics are copied unchanged into the supplement. Consumers may accept only exact matching rows, retain unsupported warnings, and continue their existing compile/adopt/reopen validation. This command never changes the finalized candidate or repeats font generation.
