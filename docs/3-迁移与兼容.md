# 迁移、部署与兼容

共享工具迁移应同时更新目录、调用方、运行时、文件纳管边界与客户端配置；迁移前核对文件清单，迁移后验证所需入口。原始清单与机器路径不随产品分发。

| 旧入口 | 当前入口 |
| --- | --- |
| tools/ | grea/ |
| tools/bin/recovery ID ... | grea/bin/grea legacy ID ...；grea/bin/recovery仍保留相同原生输出/退出码 |
| .agents/skills/game-build/SKILL.md | 已移除；改用 .agents/skills/grea/SKILL.md 完整安装副本，唯一维护来源为 skill/SKILL.md |
| game-build references | 改用 skill/references；由 scripts/sync_skill.py 安装，不保留旧技能跳转 |
| tools/registry.json | grea/registry.json，同一来源驱动CLI、MCP和兼容分发 |

## 生效范围

- 公开仓库采用纯源码分发，不携带旧 LFS 对象；本机第三方库存和历史恢复材料由 .gitignore 排除。迁移已有私有副本时保留其本机依赖，不将其加入新公开提交。
- 外部调用方迁移时只修改共享工具路径，保留项目专用实现及既有证据。
- 历史记录中的旧命令、报告指纹和源路径保留历史含义；可点击的文件引用迁到当前实体。原始日志、媒体、导出资产及Unity场景不作批量替换。
- 虚拟环境不可跨机器直接复制；移动目录后应重建运行时并核对入口。

## 部署

当前安装、运行时重建及项目 MCP 配置统一见 [使用说明](0-使用说明.md)。本页仅记录迁移关系；旧目录路径与旧本机探测值不能直接作为当前部署参数。

## 维护与回退

新调用使用grea公共契约；旧脚本名字通过注册别名兼容，但不存在顶层tools符号链接。外部未纳管调用方需按路径映射更新。修改注册表、输入输出契约后生成schemas并运行一致性和往返测试，不手改生成物。

回退应作为一次明确迁移：恢复相关提交/文件及目录映射，同时复原对应版本的文件纳管规则、客户端配置和调用方；不能只把文件夹改回而保留新路径。项目原始数据、普通玩家存档和单独Git仓库不由根目录工具迁移回滚。
