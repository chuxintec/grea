面向工具、接口和文档维护者。日常使用从 [使用说明](0-使用说明.md) 开始，游戏开发流程以 [规范技能](../skill/SKILL.md) 为准。

自有使用文档采用“用途→前提→调用→结果／输出→失败处理→边界”。docs 和 skill/references 的新主题采用数字+中文命名；保留既有路径和被引用的锚点，迁移时提供跳转。日期版本表属于快照，不写成永久当前状态。

示例统一约定仓库根目录为 cwd，优先请求文件与绝对数据路径，标明占位符、新建输出和副作用。Windows 不复制 Mac 程序路径。示例不得使用虚构的实测成功、证据 ID 或游戏验收结论。

## 修改工具或接口

1. 查 registry、调用方和既有脚本，确认是扩展、别名还是独立语义；避免创建重复实现。
2. 通用代码／测试放 grea；项目专用代码留项目。明确输入、输出、退出码、系统／CPU 依赖和失败边界。
3. 公共接口变更更新 contracts.py，再生成 schemas；工具变更更新 registry 和对应专用说明。平台更改必须区分模拟测试与原生测试。
4. 仅运行相关回归与未决风险检查；需要完整公共接口验证时使用下列命令。不要因文档措辞修改启动游戏或付费服务。
5. 核对差异、链接、示例与输出范围；用户已明确授权的长期结论通过工作区指定的远端记忆技能保存；产品本身不纳管本地用户记忆。提交推送按本轮用户授权执行。

从仓库根目录运行：

```sh
./.venv/bin/python scripts/generate_contracts.py --check
python3 scripts/sync_skill.py
python3 scripts/sync_skill.py --check
./bin/grea legacy check_grea_skill --workspace-root /absolute/grea --json
./.venv/bin/python -m unittest discover -s tests -v
```

需要更新生成物时运行 generate_contracts.py，不带 --check；生成后回读差异。完整测试当前以 macOS 验证为基准，不能直接把它标记为已通过的 Windows 套件。

技能只修改 skill/，再同步客户端安装副本；自定义安装路径使用 --destination，见 [工作区接入](7-独立仓库与工作区接入.md)。同步检查不替代行为验收。

## 发布和历史记录

公开依赖边界见 [第三方说明](../THIRD_PARTY.md)。版本声明与 uv.lock 保持一致；若修改依赖，更新锁文件并重新验证。旧 validation 中的日志和指纹保留为旧版证据，新结果放独立目录，不覆盖后声称旧版本已验证。

发布前核对 Git 暂存范围并运行 `python3 scripts/audit_public_tree.py`，禁止把本机 .venv、凭据、providers.local.json 或项目私有产物误纳入。具体范围见 [Git 管理](../GIT-WORKSPACE.md)。提交与推送是独立动作，按实际结果报告。

## 分发内容检查

按 [脱敏规范](8-可分发内容与脱敏规范.md) 检查用户名、路径、业务案例、日志和归档创建者信息。原始日志留仓库外；在 validation 保存匿名结果摘要。历史原始资料不随产品分发后，不保留指向它们的强制依赖或断链。
