# Unity 隔离试点与迁移验收

隔离迁移已在两个获准的真实工程隔离副本中完成**模块范围的 A5**：多实体会话的协程生命周期、动态 UI 的监听生命周期。Unity 为 6000.6.2f1，目标为 macOS arm64 / Mono。原工程的选定源码与配置输入复核无变化；未迁移整个工程，未将游戏内容发布到 grea，也未发布新 Release。

公共仓库保存通用复制工具、可选适配包与匿名验收摘要。项目映射、源快照、迁移补丁、测试代码、原始日志、截图、QA 存档及 Player 留在本机被忽略的 `grea/.private/unity-m5/`。这些游戏资产没有公共再分发承诺。[机器可读摘要](validation/2026-10-13-unity-m5.json) 是执行记录摘要，外部读者无法仅靠公共仓库重跑私人游戏。

## 1. 选择与采用范围

| 试点 | 结构差异 | 本次迁移 | 保留的边界 |
| --- | --- | --- | --- |
| multi-entity | Built-in、实体/弹道/停泊队列、协程驱动、默认程序集与独立 Domain | 两个既有脚本接入父子作用域；取消一代任务后可再次启动，销毁宿主释放作用域 | 原有 Unity 协程调度、规则、队列/RNG、场景/Prefab、存档字段 |
| dynamic-ui | URP 17.6.0、新 Input System、编译后的规则运行时动态创建 UI | 一个宿主改为 partial，新增监听所有权适配文件；节点/宿主销毁解除自身监听 | 动态节点 ID、回调顺序、隐藏/复用页面、第三方监听、资源键和存档格式 |

两者分别使用 Input 设置 Both 与 Input System，保留既有包锁和默认 Assembly-CSharp。它们不属于静态规划的 URP/legacy 新工程矩阵，因此没有伪造通过静态规划配置校验，也没有用工程生成器覆盖既有工程。私有 adopt 计划明确前像哈希、变更白名单、不变量和例外。

目录整理遵循渐进采用：已有业务目录、程序集身份和资产路径继续保留。只引入确实使用的包与适配文件，不为符合模板创建空目录，不批量移动资源或重写 Prefab。

## 2. 通用能力

### 输入快照与独立复制

`unity_pilot` 已注册到统一工具目录，其实现为 [src/grea/tools/unity_pilot.py](../src/grea/tools/unity_pilot.py)：

```sh
./bin/grea legacy unity_pilot snapshot --source /path/to/source \
  --unity-root . --output /path/to/private-evidence/source.json
./bin/grea legacy unity_pilot clone --snapshot /path/to/private-evidence/source.json \
  --output /path/to/new-baseline
./bin/grea legacy unity_pilot clone --snapshot /path/to/private-evidence/source.json \
  --output /path/to/new-candidate
./bin/grea legacy unity_pilot verify --snapshot /path/to/private-evidence/source.json
```

Unity 位于子目录时指定 `--unity-root 子目录`。默认只选择 Assets、Packages、ProjectSettings；通过重复 `--include 相对路径` 明确补充外部 oracle 等必要输入。快照包含本地绝对路径，私有工程的快照必须留在私有证据目录。

工具记录逐文件内容哈希、长度、执行位与树哈希；拒绝已有输出、源目录内输出、符号链接与缓存目录，复制前后复核输入，实际复制字节而非硬链接。空的选定目录也会保留。输入变化停止，复制途中失败保留部分输出供检查，不能覆盖重试。`verify` 不一致返回退出码 1。它不运行 Unity、不迁移代码、不写源工程，也不是对抗恶意并发文件修改的隔离沙箱。

### 默认程序集兼容适配

新增 [com.grea.adapters.predefined 0.1.0](../tools/unity/adapters/predefined-assemblies/README.md)，与 **com.grea.foundation 0.2.0** 一起嵌入目标工程的 Packages。核心包与参考游戏分发锁不变。

核心 Contracts 保持显式引用；只有这个可选 facade 使用 `autoReferenced: true`，让默认 Assembly-CSharp 通过仅含 BCL 类型的 `LegacyLifetimeScope` API 调用核心作用域。已有 asmdef 的工程应继续直接引用 Contracts。此包没有调度器、场景对象、Update 循环或持久化策略；不自动把旧游戏转成分层程序集。

项目决定资源归谁所有和何时释放。两个已验证用法是：

- 协程仍直接调用 `StartCoroutine`，不增加 IEnumerator 包装或额外一帧；作用域只负责停止该宿主的任务与取消代次。
- 页面隐藏不等于销毁；隐藏时保留监听，销毁时只移除自己登记的回调，保留第三方监听。没有 Button/ScrollRect 的节点不额外创建作用域。

## 3. 实际验收

| 层次 | multi-entity | dynamic-ui |
| --- | --- | --- |
| 输入/资产身份 | 原始 2,934 个输入复核不变；既有非代码 Assets 与 meta 不变 | 原始 13,936 个输入复核不变；既有非代码 Assets 与 meta 不变 |
| 原有静态/Editor 校验 | 原有 GameValidation 通过，包含队列/停泊/速度 oracle | 原有 NativeProjectAuthoring 校验通过 |
| PlayMode | 基线 4/4，迁移版 4/4：即时启动、取消/复用、独立停止、销毁与两次加载 | 基线 3/3，迁移版 3/3：重复登记、隐藏/重开、滚动、宿主释放、两次加载 |
| Player 自动路线 | 基线和迁移版各 5/5：通关、合并、拖拽、破坏效果、弹窗/复活/清理 | 固定时钟和随机带的规则差分：8 个阶段、7,200 个战斗帧、最终 2,473 次随机消费、完整报告与存档逐字节一致，错误 0 |
| 原生输入/视听 | 人工操作迁移版反馈“正常”；记录到实际指针、发射/合并、设置和关卡转换 | 人工操作迁移版反馈“全部正常”；14 次点击及拖动记录、页面/设置反复开关，音源在播放 |
| 关闭重开 | 重开保留第二关与音乐开关；未承诺保存局内所有方块 | 重开保留音效/音乐音量，设置文件字节不变；正常运行的登录时间字段允许更新 |
| 回退/重复应用 | 独立新副本应用最终补丁，再应用为 0 变化，回退后恢复全部原始输入哈希 | 同左 |

四个 Player 均构建成功，执行文件核验为 arm64，使用 Mono；它们是私有 Development/QA 验收包，不是可公开发布的成品。现有 QA/调试内容与原生构建警告保留在证据中，不能沿用参考游戏的生产包裁剪结论。

自动化点击曾未稳定进入引擎记录，因此实际输入依据为人工操作与回读，不把内部回调当真实点击。视听结论限本轮受影响流程的人工反馈、截图和运行音源状态；没有重新证明完整原版视听一致性。

多实体 Player 路线按不变量验收；墙钟用时和逐帧中间值存在差异，未宣称两次运行逐帧相同。固定规则差分的动态 UI 测试使用 fake rendering host，并以夹具触发失败结算；不是自然通关或真实输入证据。

## 4. 成本、例外与升级/回退

发现并处理的接入问题：

1. 首份多实体副本漏了 Assets 外的三份 oracle，原有校验因此失败。将三个明确文件加入快照后通过，未复制整个分析/缓存树。
2. 默认程序集无法直接使用 `autoReferenced: false` 的 Contracts。增加可选 facade，保留现有脚本序列化身份；未扩大核心依赖。
3. 动态 UI 最初为每个节点分配作用域，收敛为只有输入组件才登记；保留隐藏后重新激活的原语义。
4. 系统 Python 缺少仓库测试依赖，改用仓库 `.venv` 执行；最终 150 项测试中 148 通过、2 项既有可选集成跳过。
5. 人工补验两次，每个试点一次；自动输入能力与游戏行为分开诊断。未统计完整开发工时、性能预算或效率提升百分比。

首次成功 Player 构建的 UTC 结束时间：两组基线分别为 13:25:28 与 13:25:50，迁移版分别为 13:27:39 与 13:28:00。它们只表示本次构建记录，不是通用迁移耗时承诺；精确时间以私有 provenance 为准。

后续升级必须重新冻结输入与包版本，创建新的候选目录，只应用审阅过的变更白名单，然后重跑受影响的 Editor、PlayMode、Player、真实输入和关闭重开检查。隔离迁移的私有补丁应用器只接受专用 roundtrip 目录，先验证所有前像；已到目标版本返回 unchanged，漂移拒绝。它不是公开通用 refactor 引擎，也不保证崩溃时事务回滚。

回退在新隔离目录复原前像和包锁，删除仅由该补丁新增且哈希仍匹配的文件，复核完整输入快照；不覆盖原工程或后续人工编辑。本轮实际完成两组应用→重复应用→回退，并另建了独立原始恢复副本。未单独启动回退副本 Player；运行基线证据来自同一冻结输入的基线副本。

## 5. 推广结论

允许在下一次明确授权的模块范围内复用作用域与默认程序集适配模式。暂不推广全工程转换：保留两个结构例外，不增加游戏专用规则到核心，不扩大静态规划能力矩阵，不升级模板/生成器，不批量改工作区工程。

完整原版一致性、Windows/Linux、IL2CPP、移动设备、低端机性能、离线全新机器与生产签名发布仍未验。现有游戏中与迁移无关的历史问题继续由各项目追踪。隔离迁移完成不会改变这些项目原有整体验收状态。
