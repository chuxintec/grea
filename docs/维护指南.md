# grea 维护说明

面向工具、接口和文档维护者。日常使用从 [使用说明](使用指南.md) 开始，游戏开发流程以 [规范技能](../plugin/skills/grea/SKILL.md) 为准。

自有使用文档采用“用途→前提→调用→结果／输出→失败处理→边界”。docs 使用直接表达用途的中文名称；插件参考（plugin/shared、plugin/skills/*/references）使用 `<类别编号>-<类别>-<模块>.md` 命名且文件名在插件内唯一，如 `05-Unity-工程重建与恢复.md`，不按历史加入顺序编号；保留被引用的锚点，迁移时同步所有调用方并记录旧新路径映射。日期版本表属于快照，不写成永久当前状态。

示例统一约定仓库根目录为 cwd，优先请求文件与绝对数据路径，标明占位符、新建输出和副作用。Windows 不复制 Mac 程序路径。示例不得使用虚构的实测成功、证据 ID 或游戏验收结论。

## 修改工具或接口

1. 查 registry、调用方和既有脚本，确认是扩展、别名还是独立语义；避免创建重复实现。
2. Python 产品实现放 `src/grea/tools/` 或对应领域模块；非 Python 工具和 Unity 包放 `tools/`；测试放 `tests/`，维护脚本放 `scripts/`；项目专用代码留项目。明确输入、输出、退出码、系统／CPU 依赖和失败边界。
3. 公共接口变更更新 contracts.py，再生成 schemas；工具变更更新 registry 和对应专用说明。平台更改必须区分模拟测试与原生测试。
4. 仅运行相关回归与未决风险检查；需要完整公共接口验证时使用下列命令。不要因文档措辞修改启动游戏或付费服务。
5. 核对差异、链接、示例与输出范围；用户已明确授权的长期结论通过工作区指定的远端记忆技能保存；产品本身不纳管本地用户记忆。提交推送按本轮用户授权执行。

从仓库根目录运行：

```sh
./.venv/bin/python scripts/generate_contracts.py --check
python3 scripts/sync_skill.py
python3 scripts/sync_skill.py --check
./bin/grea legacy check_grea_skill --workspace-root /absolute/grea --json
./.venv/bin/python -m unittest discover -s tests -v
```

需要更新生成物时运行 generate_contracts.py，不带 --check；生成后回读差异。完整测试当前以 macOS 验证为基准，不能直接把它标记为已通过的 Windows 套件。

技能只修改 plugin/，再同步客户端安装副本；自定义安装路径使用 --destination，见 [工作区接入](工作区接入.md)。同步检查不替代行为验收。

## 发布和历史记录

版本标签自动触发测试、打包和 Release 发布，操作步骤与失败重跑见 [自动发布](Release自动发布.md)。rc 标签自动标为预发行；只有发布作业使用 GitHub 写权限。

公开依赖边界见 [第三方说明](../THIRD_PARTY.md)。版本声明与 uv.lock 保持一致；若修改依赖，更新锁文件并重新验证。docs/validation 的历史快照中的日志和指纹保留为旧版证据，新结果放独立目录，不覆盖后声称旧版本已验证。

发布前核对 Git 暂存范围并运行 `python3 scripts/audit_public_tree.py`，禁止把本机 .venv、凭据、providers.local.json 或项目私有产物误纳入。具体范围见 [Git 管理](../GIT-WORKSPACE.md)。提交与推送是独立动作，按实际结果报告。

## 分发内容检查

按 [脱敏规范](公开分发规则.md) 检查用户名、路径、业务案例、日志和归档创建者信息。原始日志留仓库外；在 docs/validation 保存匿名结果摘要。历史原始资料不随产品分发后，不保留指向它们的强制依赖或断链。


## 文档冲突处理与目录职责

开发方法、Unity 工程规则和验收门槛以 `plugin/shared/` 与 `plugin/skills/*/references/` 为权威，`docs/` 只解释安装、使用与维护，不复制另一套规范。发现规范与实现不同，记录实现缺口；不得用文档覆盖实际接口声明。参数和输出以源码契约为准，工具 ID/依赖以 registry 为准，验证记录只证明其日期与范围。

日常指南不使用研发阶段编号。阶段计划放 `docs/history/`，历史 JSON 验收快照保持原文与哈希，通过路径迁移表定位旧来源。冻结的 Unity 包源码、原生测试程序集/保护标记可保留历史内部名称，不为文档整理改变资产 GUID、生成内容或存档。

scripts 只承担仓库维护和测试环境准备；用户可调用的诊断、源码分发和隔离复制等属于 src。原有 Python 工具 ID、参数、退出码和别名保留；文件路径迁移见 [映射表](路径迁移表.json)。Unity 包/第三方运行时仍由独立进程和各自工具链执行。

Skill 作为独立构建项，版本与构建方式见 [Skill 构建与安装](Skill构建与安装.md)。维护规范时核对源码与独立包的本地链接，不把本机同步成功等同于可迁移安装通过。

完整平台插件使用 `scripts/build_plugin.py`，归档身份与安全解包在 `plugin_bundle.py`，上游许可闭包在 `runtime_licenses.py`；`verify_plugin.py` 检查隔离运行，`verify_plugin_clients.py` 检查真实客户端安装和发现。`plugin_release.py` 把平台包、运行时身份、原生隔离报告与发布提交绑定，再由原 Release 流程统一上传回读。源码模式和纯文档 Skill 包继续保留；不要手动复制开发虚拟环境或把运行时二进制提交 Git。


## 参考文档分类编号

类别与编号固定：01 流程、02 工具、03 恢复、04 资源、05 Unity、06 玩法、07 美术、08 验收、09 交付、10 维护。同类文档共用编号，如 `05-Unity-工程重建与恢复.md` 与 `05-Unity-工程结构与开发规范.md`；编号不表示逐篇阅读或执行顺序。新增模块沿用类别编号，新增类别再分配新编号。

工作流和维护场景引用完整文件名，不通过编号猜测某个模块。重命名同时更新链接、路由、路径迁移表、安装副本和独立 Skill 包；原始验收快照不改写。
