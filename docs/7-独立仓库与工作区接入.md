# 独立仓库与工作区接入

GitHub 的 chuxintec/grea 仅维护 grea 产品。仓库根目录直接包含 README.md、pyproject.toml、src、bin、skill、docs、registry.json 等，不包含外部工作区治理文件。

Git 根目录即本仓库目录，可位于任意工作区。项目数据、记忆与客户端配置由使用者在仓库外管理，不随产品分发。

## 独立使用

从 [使用说明](0-使用说明.md) 克隆与安装，在仓库根执行命令。不需要业务项目、预置记忆或用户配置才能运行 CLI、读取技能和检查本仓库链接。第三方库存为本机可选依赖，不随公开 Git 分发，参见 [第三方说明](../THIRD_PARTY.md)。

## 接入已有工作区

可以将本仓库克隆为任意工作区中的 grea 子目录。外部工作区负责项目、产物和记忆服务的调用配置；调用方使用实际路径访问 bin/grea 或 launch.py。更新工具位置时同步调用方的实际路径。

需要 Agent 技能发现时，从仓库根运行以下命令，将完整技能安装到客户端发现目录：

```sh
python3 scripts/sync_skill.py --destination /absolute/workspace/.agents/skills/grea
python3 scripts/sync_skill.py --destination /absolute/workspace/.agents/skills/grea --check
```

默认目标为仓库所在工作区的 `.agents/skills/grea`。同步包含 SKILL.md、references 和 agents 展示配置；技能内部引用仍指向安装副本，指向仓库文档和工具的相对链接按安装位置重写，锚点保留。安装副本依赖原仓库；移动仓库或更换安装目录后重新同步。

`skill/` 是唯一维护来源，安装副本不手工编辑、不纳入 grea Git。同步覆盖副本并删除目标中的多余文件；该目录必须专用于 grea 技能。隐藏文件和缓存不分发。`--check` 只读，内容不同、缺失或多余文件退出码为 1，断链或非法目标为 2，一致为 0。它核对副本内容并检查源 Markdown 的相对文件链接，不验证标题锚点或 Agent 实际行为。修改 skill 后先同步，再检查；不再安装 game-build 旧名技能，历史任务改用 `$grea`。工具别名兼容不受影响。

MCP 在客户端配置中填入实际命令路径，参见使用说明；不要把某台机器的配置提交为产品默认值。

兼容检查器的 --workspace-root 参数接受本仓库根目录，也接受包含 grea 子目录的外部工作区。新调用优先传仓库根目录，参数名为旧接口兼容保留。

## 外部经验和项目资料

技能保存通用方法；原始案例、工作区记忆和业务项目资料均属于可选外部上下文，不是工具安装、技能加载或测试的必要条件。需要记忆时通过工作区指定的记忆技能搜索和读取已授权原文；需要保存时遵守该技能的授权、去重与存档回读要求。

这些来源只能解释规则的形成背景，不能证明当前项目状态。新工作区以自己的项目证据、用户授权和局部规则为准；本产品不创建本地 memory 或阶段日志副本；记忆通过外部服务托管。通用规则继续维护 skill，产品验证摘要继续维护 docs/validation，用户项目数据留外部项目。

## Git 边界

产品更新在本仓库提交；不从外部工作区根目录提交。本仓库的 .gitignore 和 .gitattributes 决定公开范围，具体见 [Git 边界](../GIT-WORKSPACE.md)。
