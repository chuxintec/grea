# grea SKILL 审计（2026-10-16）

## 审计口径

- **对象**：`skill/SKILL.md`、`skill/references/`（23 篇，合计约 21.6 万字节）、`skill/agents/openai.yaml`、`skill/version.json`（`2026.10.14rc1`）、`scripts/sync_skill.py` 与 `build_skill.py` 的分发方式、`tests/scenarios`（29 个行为场景）。
- **参照**：
  - 工作区已有插件 `lifeos`：`.codex-plugin/plugin.json` 配一个 MCP 连接，下挂四个独立 Skill，并在插件根目录放共享 `references/`。
  - 仓库外代表性数值战斗样本的原生化审计（2026-10-15）发现的问题；项目身份与原始报告保留在样本工程内。
- **用户目标**：以 Cocos/Laya/Unity 等引擎的原版为来源，转换为**纯原生 Unity 工程**，使用 Unity 原生逻辑、官方或主流插件，并遵守 Unity 开发规范。
- **方法**：只读通读与关键字统计，没有修改技能文件，也没有运行 `check_grea_skill` 或行为场景。

## 结论摘要

| 问题 | 结论 |
| --- | --- |
| 1. 描述是否合理 | **需要修改**。描述没有说清"把其他引擎的游戏转成 Unity"这个主场景，没有覆盖 Cocos、Laya、微信小游戏、H5 等触发词，也没有给出目标形态（原生 Unity）。它同时覆盖 8 种模式，触发面过宽，但边界不清 |
| 2. 需要补充的内容 | 最高优先级是**原生转换模式的规范和目标形态**，以及**修正与之冲突的现有条款**；其次是 Cocos、Laya 等源引擎到 Unity 的映射手册，以及 Unity 主流技术选型基线 |
| 3. 是否拆分为插件 | **应该拆分**。拆成 1 个路由技能加 6 个领域技能，打包为 `grea` 插件，共用一个 MCP 连接和插件级共享参考，结构与 `lifeos` 一致。应先在单技能内修好内容，再做拆分，避免把错误规则搬进新结构 |

## 一、描述评估

### 现状

```yaml
name: grea
description: 依据原版实玩、包体资源、Prefab 和代码证据恢复 Unity 游戏；用于完整复刻、局部一致性修复，以及已有恢复工程的授权换皮、结构重构、性能优化和构建交付。不用于原创新游戏或与恢复无关的普通功能开发。
```

### 问题

| # | 问题 | 影响 |
| --- | --- | --- |
| D1 | "恢复 Unity 游戏"有歧义：既可以理解为找回原作者的 Unity 工程，也可以理解为把游戏恢复到 Unity。正文其实两者都管（AssetRipper 恢复和跨引擎重建），描述只体现了前者 | 用户说"把这个 Cocos 小游戏做成 Unity"时，可能不会触发 |
| D2 | 没有源引擎和平台的触发词：Cocos Creator、Laya、FairyGUI、Egret、微信小游戏、wxapkg、H5、APK/XAPK、IL2CPP 都没出现，**Cocos 在整个技能中只出现 1 次** | 触发靠运气；IceFire 这类 Cocos 项目最常见，却最缺少指引 |
| D3 | 没有声明目标形态。"复刻""一致性"只说明对比的对象，没说明产出应该是 Unity 原生实现 | Agent 默认追求越像原版越好，于是仿写源引擎的运行时（IceFire 的问题 F1–F5） |
| D4 | 8 种模式挤在一句话里（复刻、修复、换皮、重构、性能、构建、维护等）；"性能优化""构建交付"这类通用词会和普通 Unity 任务抢触发 | 误触发会加载大量恢复流程；一旦触发又要读很长的正文 |
| D5 | 只有中文触发词。`agents/openai.yaml` 的 default_prompt 依赖 `$grea` 显式调用 | 英文请求，或不知道 grea 这个名字的请求，很难命中 |
| D6 | `name: grea` 不表达用途（缩写含义没有说明） | 在技能列表里无法从名字判断用途 |

### 建议描述（单技能阶段，拆分前先替换）

```yaml
name: grea
description: >-
  把已发布的游戏（Cocos Creator、Laya/FairyGUI、Egret、Unity 包体，来源可为
  微信小游戏 wxapkg、H5、APK/XAPK、IL2CPP）依据原版实玩、资源与代码证据，
  转换或恢复为纯原生 Unity 工程（Unity 原生组件、官方或主流插件、Unity 工程规范），
  并对照原版验收规则、画面与交互。也用于这类恢复工程的局部一致性修复、
  原生化重构、授权换皮、性能对照与构建交付。
  Use when porting / recovering / remaking a shipped Cocos, Laya or Unity game into
  a native Unity project. 不用于原创新游戏，也不用于与原版无关的普通 Unity 开发。
```

拆分后，每个子技能的描述见第三节。

## 三、拆分为插件

### 判断：应该拆分，但先修内容，再拆结构

**支持拆分的理由**

- 模式多，触发词差异大：取证解包、跨引擎转换、换皮、构建发布面对的用户请求完全不同。一个描述无法同时写准确，拆开后每个技能可以有精确的描述和"不适用"边界。
- 上下文成本高：当前一次触发就要先读完 8 KB 的 SKILL.md 并做模式路由；拆分后只加载相关的技能。
- 已有可用结构：执行层（grea CLI/MCP）已经统一，而 `lifeos` 插件正是"一个 MCP 加多个 Skill 加共享 references"的结构，可以直接照搬。
- 可以扩展：可以加入子 Agent（例如原版取证、原生化审计）、命令和 Validator 钩子，这些都是单个技能放不下的。

**风险与对策**

| 风险 | 对策 |
| --- | --- |
| 技能之间重复共同约束 | 共同约束放在插件根目录的 `shared/` 中，各技能只引用不复制；`check_grea_skill` 检查重复内容 |
| 跨技能链接失效 | 规定只允许技能内部链接加 `../../shared/` 链接；`sync` 和 `build` 脚本校验 |
| 子技能之间选择错误 | 保留 `grea` 作为路由技能（描述宽泛、正文很短），只负责模式判断和转交 |
| 已安装用户的兼容性 | 保留一个版本的过渡期：旧 `grea` 技能变为路由，原链接重定向；`路径迁移表.json` 记录新旧路径映射 |

### 目标结构

```text

  .codex-plugin/plugin.json             # Codex 插件清单（参照 lifeos）
  .claude-plugin/plugin.json            # Claude Code 插件清单（如需同时支持）
  .mcp.json                             # grea MCP 服务（与 bin/grea 共用契约）
  plugin/                               # 插件源（取代现在的 skill/）
    shared/                             # 共享参考，只被引用、不单独触发
      common-constraints.md             # 授权、证据即数据、QA 存档、分层报告
      verification-layers.md            # 规则、运行、体验、原生化四类验收
      tools-index.md                    # 工具 ID 选择表（由原 02 改写）
      glossary.md
    skills/
      grea/                             # 路由技能
      grea-evidence/                    # 原版取证与资源/代码提取
      grea-native-port/                 # 跨引擎 → 原生 Unity（核心新增）
      grea-unity-recovery/              # Unity 包体 → 找回 Unity 工程
      grea-parity/                      # 规则/动画/界面一致性对照与修复
      grea-unity-standard/              # 工程结构、重构、资源治理、性能
      grea-delivery/                    # 构建、窗口、发布
      grea-reskin/                      # 授权换皮（可选，也可并入 delivery 以外的单独技能）
    agents/                             # 子 Agent 定义（可选）
      native-auditor.md                 # 只读审计生产工程中的源引擎残留
      evidence-collector.md             # 原版取证（受授权约束）

```

技能维护（原 `10-维护-*` 和工具准入）面向 grea 维护者，不面向游戏任务。建议放进仓库的 `docs/维护指南.md`，不作为插件技能触发。
