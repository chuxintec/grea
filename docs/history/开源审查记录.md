# 开源发布审查

审查日期：2026-10-13。对象为即将公开的全新 Git 文件树；旧提交、LFS 对象、忽略文件及本机恢复副本不进入新仓库。

## 结论与处理

| 类别 | 发现 | 处理 |
| --- | --- | --- |
| 敏感或业务内容 | 项目派生脚本含业务标识、固定资源哈希、验收计数与来源专用算法参数 | 5 个脚本排除出公开树；保留本机副本供既有调用方使用 |
| 第三方许可 | 原仓库包含第三方二进制、Unity 包快照、插件包和 Spine vendor | 不重新授权或复制到公开树；保留来源说明、必要许可文本与可选接入配置 |
| 缓存和冗余 | 工具安装树、归档与解压副本、重复包备份、调试符号、日志 | 本机保留、Git 排除；新的公开源码无需 Git LFS |
| 误导性能力状态 | 包装器存在时，缺少程序本体仍可能被识别为可用 | 增加 required_files 检查；本机覆盖配置不继承旧安装要求；补充回归测试 |
| 文档与元数据 | 缺少项目许可证，旧说明仍要求私有权限和 LFS | 增加 MIT、第三方说明、贡献指南与发布检查；修订首次安装和 Git 边界 |
| 公开后防回流 | 无统一暂存区检查 | 新增源码检查器及 CI，检查实际暂存字节；疑似秘密只输出位置和类别 |

已审阅保留文件中的 URL 主机、邮件地址候选和凭据赋值候选。静态规则检查典型访问令牌、私钥、带凭据 URL、本机用户路径、业务应用 ID、私网地址、LFS 指针、二进制及受限路径；当前候选未命中。它不是完整漏洞审计，也不能证明未知格式秘密不存在。

## 发布方式与后续

用户已选择删除原私有仓库，新建同名 public 仓库；公开历史只从本次根提交开始。操作前在被忽略的本机位置保留恢复材料，避免丢失既有工作。新的 Git 作者信息采用 GitHub noreply 地址。

以后每次提交先检查暂存区，按 [贡献指南](../../CONTRIBUTING.md) 回归；可选工具从 [第三方来源](../../THIRD_PARTY.md) 获取。新增二进制、vendor、游戏样本或原始日志须重新评估，不因以前曾纳入私有仓库就自动公开。
