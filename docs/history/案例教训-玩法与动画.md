# 案例教训：玩法规则与动画时序

日期：2026-10-16。来源：`plugin/skills/grea-parity/references/06-玩法-规则与随机一致性.md` 与 `05-Unity-动画特效与事件时序.md` 在审计 C1 之前的案例段落，按原文迁出。

**适用边界**：下列内容来自具体项目（三消、队列取箱、Flow 派发、旋转拔销、组合道具、采集飞行等玩法）的返工记录，只对相同机制成立。它们说明"曾经在哪里出错"，不规定其他游戏的数值、顺序或默认分支。现行可泛化规则见 [规则与随机一致性](../../plugin/skills/grea-parity/references/06-玩法-规则与随机一致性.md) 和 [动画特效与事件时序](../../plugin/skills/grea-parity/references/05-Unity-动画特效与事件时序.md)；新的案例经验通过工作区记忆服务保存，本文件不再追加。

使用方式：当前项目出现同类机制时，把对应段落当作排查清单的候选项，再用当前游戏的原代码、配置和录像逐项验证。


## 一、玩法规则案例

### 补充元素与匹配算法

- 原始关卡配置正确，不代表生成与难度已经恢复。用户反馈过于容易时，先对齐补充顺序、随机通道、随机调用次数、匹配组划分/优先级、自动连锁与道具生成；不得直接降低道具概率或强行截断连锁来人为调难。
- 同种子还须同初始化状态、同操作和同调用顺序。记录每一步的棋盘、输入、各随机通道调用计数、补充元素、连锁轮数及道具生成位置/数量，定位第一个分歧；仅比较胜负、平均道具数或最终棋盘会隐藏原因。
- 固定种子专项夹具与普通设备种子分开；一个种子或几步对齐，只证明该轨迹。尚未恢复的生成分支、重排和优先级应单列，不写成“算法完全一致”。
- 只读提示/可行步搜索不能调用会结算、补充或消耗随机数的操作方法。临时交换应在异常路径也恢复；验证完整棋盘、步数、状态及随机通道均不变。

### 闲置提示与设置

- 闲置时间应从可操作且棋盘稳定时计算；拖动、选择道具、动画、结算、弹窗、引导和后台暂停按原版门控处理。交互应及时取消提示，回到稳定态重新计时。
- 提示包括候选选择、涉及元素、边缘粒子、动作和重复间隔。恢复了原粒子不代表已恢复评分/排序、随机选择或晃动曲线；不能把本次游戏的秒数、显示时长推广为通用默认。
- 默认显示 ON 的旧存档缺失字段，不能直接用 `!undefined` 切换，否则第一次点击仍为 ON。让显示、行为和持久化使用同一默认值；核验首次点击、OFF 状态、刷新和重进。

### 有限槽位与连接组事务

适用于队列取箱、联动上阵及在途收集。先追完整调用顺序：成员可取性→已有槽位是否收紧→连续槽预约→整组离队→移动→消耗→整组完成→释放。不能只修“空格相邻”而漏掉原版的前序收紧，组内顺序也不能自行改成列号顺序。

- 连续可用槽包含占用与idle/移动状态；总空槽数不等于可分配的连续区间。收紧会改状态时，先在计划副本验证完整结果再提交，或提供失败回滚；拒绝后核对队列、组关系、槽位与预约均未出现部分提交。
- 逻辑预约可先于到槽动画，使重复点击无法抢同一槽；按对象/组状态判断能否接受其他输入，不把视觉整理标志自动当作全局输入锁。
- 数量为零、在途完成、整组完成和槽位释放是不同事件。保留原版的成组等待与释放时点；满槽时分别检查可继续派发、等待在途和稳定无进展，不能一律判负。
- 修正组生命周期后，旧求解路线和通关记录只对旧规则成立。按新状态模型重放受影响关卡；不得为保住旧PASS放宽组规则，或把搜索未找到解写成数学上无解。

### 颜色身份与派发资格

美术换色保持玩法颜色 ID 与映射可追溯；不能把多个原色压成难以区分的同色，再宣称数据未改就等价。派发资格由当前游戏的可见/可达/表面/预约与候选排序共同确定，不能因为有同色库存就全量派出。旋转和采集后重验资格；原版选择规则未恢复时保留缺口，不套用其他 Flow 游戏常量。

### 几何互锁、碰撞与消除

适用于旋转、拔杆、连接销、复合碰撞体和接触触发玩法。先画出输入捕获→约束轴→路径探测→实际姿态提交→接触进出→关系更新→求解/计分的调用链，标出发生在哪一帧及哪些方法会改状态。

- **按碰撞职责恢复，不按外观猜。** 区分主体、连接柄、销墙、传感器、固定扣、触发器及输入碰撞体，核对层、trigger、拥有者和过滤规则。主体没碰到不代表附属柄没碰到；源方法若逐个附属碰撞体独立查询，不能以主体接触缓存代替。排除某面或角色的条件只作用于原分支，不扩成全局免碰撞。
- **区分关系与几何。** 静态配置、活动绑定、正反持锁、接触集合与可消除状态分别维护。某个传感器退出不等于整体脱离；按源方法保留其他实体仍互锁的关系，覆盖最后一销未脱离、完全脱离、重入及移除后的缓存失效。目标类型不能只处理环对环而漏掉环对杆等关系。
- **原探测可能有副作用。** 不预设所有试探姿态都只是查询：碰撞探测中的首次接触可能立即引爆/结算。沿调用者和回调确认时点与目标快照，不能统一延迟到最终姿态才检查，否则快拖会漏命中或多命中。审计、提示、搜索等只读入口则应明确禁止提交效果，异常时恢复姿态及状态；真实移动与只读入口分开验证。
- **普通和快速输入分别回归。** 同起点、同方向至少覆盖慢速连续移动、单帧较大位移、受阻后反向、松手再拖、障碍移动/消除后再操作；比较首次碰撞对象、停止位置、保留关系、移除集合及得分，而不只比较最终可通关。更密的诊断采样只产生候选，仍须核对原采样算法和真实输入，不能据此擅改源阈值或宣布原版也有Bug。
- **字段仅在所属模式生效。** 枚举轴、局部/世界方向、自定义锁、起始位置约束和阈值逐分支对齐；不能把一种模式的限制叠加给所有物件。无宿主、空列表或不参与收集可能是合法类型，先核对原可选分支，再决定是否为异常。

### 跨语言规则与优化（原段落中的玩法专用条目）

- 空槽足够时的自动收尾、合并时迁移在途任务、预留与实际扣弹、取消退款、无剩余同色时清理余量等分支，以当前原调用链发现为准，不作为所有游戏的默认玩法。
- 性能优化先保留候选优先级、同距离tie-break、遮挡、随机和预约状态。可采用等价的空间索引、边界退出、缓存与剪枝；不要用减少命中次数或更换目标规则换帧率。缓存键及失效时机需覆盖旋转、消除、预约、重排等实际依赖。

## 二、动画与特效案例

### 组合道具与特效

- 携带道具和普通道具不一定共用命中职责。运输事件与落点爆炸若都提交伤害，可能提前消除并重复发射粒子；按原版调用链分清运输、落点伤害与子特效所属事件。
- 组合路径缓存必须包含影响路径的参数和道具类型；普通风扇与携带风扇不能无条件复用。
- 双根道具存在相对运动、缩放及前后排序；固定把 TNT 画在风扇下面会遮住它。恢复曲线及层级切换后还要检查起飞、中段、落点和回填。
- 黑块不一定是丢贴图：先检查引用、UV、alpha、普通/预乘/加法混合和图集边界。不得一律把黑像素删掉。
- 导出全部粒子系统不等于运行时应同时播放全部系统。沿实际启用分支检查发射、延迟、循环、父变换、世界/局部空间和排序；原纹理加近似材质/投影仍属于部分适配。不要仅凭截图增减粒子数量来掩盖启用或材质错误。
- 横向火箭反馈不能只靠命中索引否定。逐项对照清除事件、受伤障碍、动画和回填；视觉上新填入元素可能掩盖清除，也可能确有调度错误。
- 常量或部分反编译方法恢复不等于完整算法恢复。明确尚未恢复的 SmoothDamp、旋转、目标重选与时序，并用原生录像核对。

### 奖励表现与流程边界

- 区分奖励资格、已确认奖励、屏幕计数和最终存档。结算数值正确但缺少金币散开、飞行、抵达反馈，仍是体验缺口；视觉数量不得反向成为奖励来源。
- 沿实际接受的奖励事件给动画附带来源位置、金额和时间。不要从最终总额倒推每次爆炸，也不要把列表容量、对象池预留数量或常量名字误认成发射数量；追到实际循环和调用参数。
- 飞行动画要核对散开、转向/加速、终点、逐枚计数、声音及完成屏障。进入结果页、跳过、退出和切后台时，按原版生命周期收尾，防止重复到账、遗留帧循环或等待永不完成。是否等待全部飞行完成，仍以该游戏代码和录像为准。
- 原图轮播不等于恢复翻转动画；帧序、速度、尾迹、阴影和材质分别记录。已恢复的运动常量不能证明整套视觉一致。
- 初次进入、已有存档、未完成关卡和正常回主页是不同入口。按原版分别验证；不要让仅在 QA 参数下能直达第一关的路径掩盖普通启动错误，也不要用新手规则重置已有存档。
- 资源不足是完整业务分支。应根据实际入口验证“尝试动作→资源不足提示→返回准备页→再次进入”的完整路径。按原版决定是否保留任务页、是否先显示关前页，不用 toast 或直接开局代替。验证失败不扣资源、不推进任务，关闭、重入和重复点击不重复提交。

### 关系型表现与平台回调

- 连体、合并等逻辑关系不等于连线已经显示。恢复独立连接资源、端点锚点、双端颜色、轴向、深度测试、排序和缩放；跟随队列前移、飞入、槽位压缩与缩小。解除关系、刷新、成员销毁和切关时清理；不连接已失效的缓存分组。
- 广告/分享/云存档分别定义完成、取消、不可用和重复回调。用户明确指定离线自动领奖时，走同一完成入口并标注为离线策略，验证幂等、消耗、退款和存档；不能把它当真实平台成功。没有该授权时保留真实不可用/取消结果，不自发发奖，也不自动触发外发操作。

### 可打断反馈与队列动画

- 重复触发缩放/弹跳时，不从正在变化的Transform重新取“初始值”。保留稳定基态或专用反馈子节点，重播前取消旧反馈并复位；合法移动接管、取消、复用和销毁都须交还姿态。可升级/动态缩放对象的基态要随业务变化更新，不能无条件永久缓存Awake值。
- 连续选择若按原规则可并行，重排从当前可见姿态续接。可用generation/操作ID令旧动画在yield后失效，只有当前操作可以写最终位置、解除忙态和发完成事件。该方法适用于可被新布局替换的表现；扣费、领奖等事务不能直接丢弃旧回调。
- 对升层分别记录低态、过渡、高态与特效触发；横向居中不能重复算升层。验证整理早期、升层中途、连续多次输入、暂停与切关，不只验证最终位置。

### 隐藏状态覆盖整个外观

隐藏箱体、数字、连接球、两段连杆及附属效果应从同一可见状态派生，不能从真实颜色材质初始化后永不更新。连接两端可独立揭示：检查双方隐藏、仅一方揭示、整组上阵和后续消失；未揭示端不能泄露真实颜色。隐藏材质/颜色取自源资源，取色近似与原Shader恢复分别标注。

### 飞行闭环与动画写入所有权

- 对采集类飞行逐阶段记录上架完成→派发资格→起飞→寻路/着陆爬行→命中采集→携带离面→返航→入口消失→反馈/槽位释放。实际阶段和并发以原版为准；单只蜂合成测试不覆盖飞行中旋转、目标失效、卡住脱困、暂停和重试。
- 携带方块检查局部挂点、缩放、碰撞体、体积遮挡与飞行姿态；模型重叠不能只靠整体放大解决。归巢时在同一画面对照飞行物与顶部 UI 蜂巢层级，终点应与实际洞口投影一致，再检查消失与蜂巢反馈。
- 队列补位、隐藏揭示、上架、失败翻转等动画若同时写同一 Transform，要定义当前写入者、交接与取消。位置正确的终态断言不能覆盖中段跳跃；分别测试普通取走和道具批量消除后的补位。
- 序列帧使用固定画布和稳定身体锚点；逐帧按 alpha 包围盒居中会因翅膀/光效变化产生上下跳。只调整表现不能改变一次性采集、奖励与完成回调。

### 消除反馈的运行时绑定与去重

- 原粒子Prefab的网格/形状引用可能由移除事件在运行时填入。沿事件参数恢复源网格、变换、发射时刻、暂停和结束清理；仅Instantiate后隐藏原件，可能得到“突然消失”而非实际碎裂。用真实粒子及开始/中段/结束画面核验。
- 同帧消除多个类型时，核对音效去重的作用域与完整事件集合。原版若每帧发送一组声音，不能按首个物件类型二选一，吞掉其余声音；也不能反过来按每件重复播放整组。覆盖不同移除顺序、跨帧连续消除及声音关闭。事件日志、DSP有效样本、可听效果与原版混音一致性分别报告。

### 换材质与 UI 粒子组合的回归

- 替换材质或 Shader 前列出实际业务访问的属性、关键词和机制状态。普通方块好看不能证明隐藏/冰冻/双色/溶解可用；对当前正在使用的 Shader 做回读，并从真实机制入口触发。
- UI 粒子分开检查原粒子输出与最终 Canvas 合成：激活根节点、Camera/RenderTexture 范围、alpha/预乘或加法、色彩空间/HDR、极点或底图遮挡。原始缓冲有光而最终被盖住时，先修合成链，不把增大发射尺寸当通用修复。
