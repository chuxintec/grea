# 全量初版工程与协作

## 恢复流程

完整恢复／首次重建依次完成：来源冻结 → monkey 全量导出独立候选 → GREA 核来源去向和交接 → beaver 在隔离工程采用并做适用的原生验证 → 游戏 Agent 在[开发阶段](../../grea-develop/SKILL.md)接续业务。只读研究、来源辨识和输入准备可以先行；已有可维护工程的局部修复不强制重新导出。

monkey 负责源格式解析、资源转换、目标资产装配及代码依据/初稿；源格式转换缺口归 monkey。GREA 负责工作流、来源冻结、规范入口和交接判定；beaver 负责开发工程的采用、编辑及验证工具；工程操作缺口归 beaver；游戏 Agent 负责产品业务，产品代码与证据仍留游戏项目。GREA 不另写转换器，monkey 不代做整套游戏业务。Unity 来源的 Unity 目标和 Creator 来源的 Unity/Creator 目标，均以本次声明及固定 provider 的实际支持为准；不支持的目标明确保留为缺口。

## 冻结输入与候选范围

输入清单按游戏、来源引擎/版本和修订冻结，登记主包、分包、Bundle、代码/metadata 及有证据支持的补齐文件。全量只表示这份明确的来源集合，不承诺未知服务器数据、未取得的远端内容或所有受保护代码。原件只读，工具版本、能力与计划身份固定，既有计划不随 provider 新版本切换。

每项输入都要有处置和去向；每个逻辑资产都要保留唯一来源 ID 到目标路径/GUID 的映射。候选应含适用的资源、Scene/Prefab、动画、字体/音频、配置及可恢复代码依据。未恢复的方法、资源和不支持项保留来源位置、证据、原因或 TODO，并与已确认实现区分。空类、lookup、IR、gallery、媒体池、文件数量或 `conversion.completed` 都不能冒充完整初版。

## 初版交接门

先由 monkey 生成独立候选，再依据 manifest 和实际产物核每项输入的去向、哈希、引用和未完成项。源类别决定检查内容：源有 Scene/Prefab 时核对实际原生图文件与引用；没有该类别时不凭空设数量门。候选的文件完整性与工程可导入/编译分别验证；适用时使用真实目标引擎回执。静态字节、`completed`、目录规范、provider 可用和 exit 0 不能单独放行。

批量恢复的工具 ID、精确调用、版本绑定、预算、输入 Schema 和旧接口边界由共享的[monkey 恢复工具合同](../../grea/references/monkey恢复工具合同.md)维护。GREA 用 `monkey_pipeline` 做计划、执行和文件审计；需确认来源到原生资产去向时再使用显式 handoff 合同。具体调用前读[monkey/beaver 调用规范](../../grea/references/monkey与beaver调用.md)核两个 provider 的固定身份与权限。这里不复制参数表或安装步骤。

## Prefab完整恢复的独立对照

从原包恢复Prefab时，先冻结原包/版本/hash、源UUID/RF/class/node身份及资源/代码闭包。项目中现有的导出文件或修补版只用于定位与差异线索，不能当作原包真值。分开保存：原包及匹配版本的原版状态、旧工具纯输出、新工具纯输出、游戏人工修补结果；纯输出不得调用游戏Author/Repair/Integrate补丁补节点、改布局或补业务方法后归功于恢复器。允许独立最小宿主与有来源的状态输入，但不让夹具修改被验Prefab或暗补功能。

### 源组件分母与映射

按每个源节点/序列化组件建立账本，记录字段、引用、事件及预期依据，再分别核“源→IR是否遗漏”和“IR→目标是否正确”。未知/忽略/不支持的源组件仍进入分母，不能只检查生成器自己的计划。原生零MissingScript、文件/节点数量或编译通过不证明组件覆盖。动态生成对象另记源码依据及状态，不能混入静态组件数制造覆盖率。

| 账本层 | 必须保留的事实 |
| --- | --- |
| 源 | 固定来源身份、组件/序列化版本、字段与别名、对象引用/事件、解码状态；不可读部分明确未知 |
| 映射 | 目标资产/对象/类型/属性及恢复规则、缺口；一对多/多对一说明原生表达与语义依据 |
| 验证 | 静态/导入/保存独立重开/挂载/动态/视觉/输入分别记录结果和候选身份 |

跨版本/跨引擎完整恢复指明确范围内的显示、引用和行为等价，不要求目标字节或组件名称相等；使用目标原生机制，不嵌入源引擎解释器。源未支持项不能丢弃、塞空壳或擅自排除分母。最终分别报告源组件总量、已映射/未映射及字段/引用/事件完整性，支持率不冒充完整恢复率。账本是证据要求，不是尚未交付的CLI或Schema。

### 逐样本分层验收

- 树/组件：父子顺序、嵌套/覆盖、启用状态、变换/pivot与属性别名；实际导入、保存后独立重开保持。
- 可显示闭包：SpriteFrame裁切/旋转/offset、九宫格、字体/描边、遮罩/排序、材质参数与Shader、实际涉及的动画/骨骼。来源Shader证据、源码、目标编译及渲染分记，不能默认换材质掩盖缺口。
- 脚本接线：源类/RF到目标脚本身份、字段/数组/对象引用、事件目标/参数与有据生命周期。类型壳、语法初稿、可编译、已挂载、绑定正确和运行正确分别报告，空回调不算恢复；必要修复应进入monkey可复用规则或可追溯产物，不依赖每样本外部补丁。
- 动态/视觉：按源可达状态验证长短文本、空/增减列表、显隐/选中/完成、滚动、刷新与关闭重开；按[单属性布局所有权](../../grea-develop/references/Unity界面还原与输入交互.md#布局属性所有权)检查写者。真实宿主的参考视口与本次支持的另一比例分别检查，几何正确不代替画面一致。
- 比较/再生：同页同状态同视口按[画面对照](../../grea/references/实际体验与画面对照.md#开发与ui对照)比较；差分只定位，容差在比较前按来源精度和目标特性明确，不事后放宽。同输入重复生成无非预期变化，并用缺组件/字体/材质/事件的负例验证不会假成功。

只有用户明确批准两个目标时，才分别验两个目标的原生Prefab、动态、脚本与视觉；不能互相代替，也不因此恢复暂停的游戏产品。引擎版本/依赖/producer固定，工具隔离验证与游戏采用分别记；原生操作只选实际已验证的beaver能力，Creator等缺执行能力时保留缺口，不猜命令或自动装引擎。物理输入与回调夹具按[测试层级](../../grea/references/测试与结果交付.md)区分。

原服务不可得时，可用有来源的响应形状驱动纯展示并记录service_boundary及不可执行动作；关键显示/本地行为未验仍是partial，不能整项排除或标pass，更不能假发奖励或访问未授权账号/原服。样本数量与版本完成条件由本次批准计划决定，不把某版的10项门槛强加所有恢复；同一Prefab副本、多个状态或辅助预览场景不能重复算独立核心样本。未完成的版本条件保留未完成，不因文档已写或工具文件已产出签收。

## 开发接续

只有来源、候选与适用原生交接证据核清后，才由 beaver 在隔离工程采用/比较候选，由游戏 Agent 接续规则、界面、交互、服务和存档。已有工作工程参与比较/合并时，按来源身份保护既有代码、GUID、正式 JSON 和存档。此交接不是完整可玩验收；业务、视觉、真实输入、存档续玩和目标平台按开发阶段及本期范围另行验证。若交接不完整，保留缺口并停在恢复阶段，不以小样替代全量候选。
