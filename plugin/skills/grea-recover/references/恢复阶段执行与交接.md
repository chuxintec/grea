# 恢复阶段执行与交接

## 选择工作范围

**只读取证**用于回答明确的来源、格式、资源或代码问题：冻结获准读取的包与版本，输出相关证据路径、哈希和缺口后结束。它不生成目标工程、不运行来源脚本，也不自动转成完整恢复。游戏机制与成本分析由[调研阶段](../../grea-research/SKILL.md)负责；只在证据会改变判断时补做技术提取。

**完整恢复**需要用户明确目标和范围。对照已存在工程与候选，避免无条件重导。确认来源、目标和输入集合后，恢复阶段生成独立候选并核对交接；缺少目标或来源证据时先补来源识别，不猜格式或替换引擎。

已有可维护工程的局部修复、资源治理和功能开发转[开发阶段](../../grea-develop/SKILL.md)。恢复完成后，规则、UI、服务器、存档接续等产品业务也由开发阶段负责；恢复候选、工具计划和导入成功都不代表这些工作已完成。

## 一次维护的调用流程

操作与参数见[来源恢复操作](../../grea/references/来源恢复操作.md)和[实际命令索引](../../grea/references/功能模块和命令参数.md)。先核 GREA 版本、源包哈希、输出位置和选定操作；依赖缺失时保留真实诊断。

接续任务先核当前主责、在途批次、固定产物和消费者回执，复用同身份已验结果。仅当用户明确要求时派生子 Agent。

完整恢复的输入冻结、候选范围及原生交接门见[全量初版工程与协作](全量初版工程与协作.md)。plan 只描述范围；执行后保留 provider 原始状态、未完成项和候选身份。文件清单、字节数量、`completed` 或 exit 0 都不能代替来源去向审计及适用的原生回执。

## Unity目标

Unity 来源保留原程序集、类型和资源身份，按 Mono/IL2CPP 证据分别处理；DummyDLL、伪代码和已恢复实现不可互相冒充。非 Unity 来源以 Unity 原生资产和机制表达可观察结果，不在运行时复刻源节点图或源引擎调度。按[Unity 工程重建与恢复](Unity工程重建与恢复.md)区分来源导出、工作副本、代码证据与原生回读。

Cocos 全集转换须声明 `source-family=cocos`、完整 `input-set` 和目标 `unity6`；Unity 全集须声明 `source-family=unity`、`target=unity6`、`unity-export-scope=all` 和完整 `unity-dependency-manifest`。分段导出只复用身份匹配且已核实的输入和结果；详细请求参数、预算和版本锁以来源恢复操作和命令参数索引为准。其他格式先查固定 provider 能力，不能用图片 gallery 代替工程候选。

## Cocos目标

以下记录用于查询既有显式目标调用。后续恢复统一输出 Unity，Cocos 来源继续解析。

只有用户明确选择 Creator 目标时才进入此路线。声明 `target=cocos38`；只有明确批准双端时才使用 `both`。来源版本与目标 Creator 3.8.8 分别记录。候选需在目标 Creator 中核导入、引用与浏览器运行；有限序列化支持不能推广为全版本转换。

## 分阶段接收与工具缺口

交接固定来源哈希、provider/CLI/Schema身份、候选路径和回执；列出实际可采用的代码/资源子集、旧新路径与类型身份、已验层级、剩余缺口及采用范围。`needs_action` 候选只能以明确子集受控接续，不升级为整体恢复完成，也不自动覆盖已有工程。开发阶段用 GREA 的 project 与 prefab 模块接收、审计结构与规划迁移；目标 Player 的构建、输入与业务验收归发布阶段，不能互替。

Shader 交接区分可编译源码、平台编译数据/恢复二进制、未知或不支持，附来源映射及分类依据；扩展名不证明可编译，未知不能默认为运行资产。asset 模块负责来源分类，build 和 qa 模块 负责目标平台/管线的实际构建依赖筛选、原生回读和捕帧。优先复用已验能力；新增 CLI 与 Schema 必须核对固定生产者后再适配，不猜命令、不修改已发布模块锁。原生引用回读、图像可见、真实输入与玩法完成分别报告。类型目录与例外统一见[目录规范](../../grea-develop/references/Unity工程目录与资产归类.md)。

对冻结候选进行 Shader 分类使用 `grea asset classify-unity-shaders`，显式传入工程、清单、预期哈希和新输出。分类原始数据与实际引擎编译分开。

资源缺失与工具不支持按[缺口归属](../../grea/references/故障排查与重试规则.md#先分清缺口归属)区分：先证明准确版本/源ID在获准输入中存在，再判断解析/恢复失败；没有新来源不重复全池，版本缺图不由近似资源或手工占位补作原件。混合资源/业务状态分别交接。
