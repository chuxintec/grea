# GREA · 构建与发布

构建是交付阶段；普通代码、资源、场景或配置编辑和 Editor 调试由 [grea-develop](../grea-develop/SKILL.md) 承担。先读[游戏构建与版本发布](references/游戏构建与版本发布.md)，按本期交付等级选择构建、Player 验收、封装、current/安装或正式发布；这些步骤分别记录，并按已获授权范围执行，不重复询问已有授权。

| 本期要求 | 交付出口 |
| --- | --- |
| 本地预览/候选 | 新 buildId 和独立目录中的真实目标制品、原生构建报告或日志索引、源输入身份及明确待验项；不自动安装或发布。 |
| 目标 Player 验收 | 绑定该 buildId 的实际启动、真实输入、受影响流程、存档续玩和平台证据；构建通过不替代它。 |
| 封装与 payload 校验 | 保留平台目录结构，记录压缩包与文件清单哈希、权限/签名状态；哈希通过不代表安装或运行通过。 |
| current 晋升、安装或正式发布 | 仅在对应动作已获用户授权时执行；复核已有制品、存档兼容、授权和回退路径。 |

按需读取 [许可证与再分发](references/许可证与再分发.md)；Windows 目标再读[Windows供应方与桌面验收](references/Windows供应方与桌面验收.md)。需要修改业务、资源或调试 Editor 时转 `grea-develop`；为本次构建调用 Editor 仍由发布阶段编排，不夹带未批准代码/配置修改。

## 执行边界

以获准目标及现有工程约定为准；仅未指定平台的Unity任务默认macOS。Cocos/Web、Go按[目标规则](references/游戏构建与版本发布.md#非unity目标交付)执行。先核实际工具链能力，缺失项保持needs_action，不从文档推断已安装。

本地候选、目标运行、封装、安装、Git推送与正式发布分别记录。沿已有授权执行，保留新buildId和来源身份；失败保留证据与旧current，回滚核存档兼容。详细字段和流程只在构建参考维护。
