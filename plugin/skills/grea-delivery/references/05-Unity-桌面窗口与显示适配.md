# Unity · 桌面窗口与显示适配

适用：Unity恢复版从移动端转为桌面，或用户反馈启动比例、窗口尺寸、缩放后布局/命中异常。目标尺寸、固定比例策略以当前项目授权为准，不把某次项目参数推广为默认。

## 新项目窗口默认

新项目未指定尺寸且没有已批准版式时，macOS/Windows 桌面使用 1080 × 2340 的竖屏初始窗口并允许调整大小。用户指定尺寸/比例覆盖默认；配置窗口模式及可调整选项后，按本页在目标系统测启动、DPI、缩放和输入。系统限制可用空间时记录实际尺寸，不只引用 PlayerSettings；设计参考分辨率不等于窗口客户区尺寸。

## 先确定尺寸口径

分别记录Canvas设计参考、Camera viewport、Player渲染像素、原生窗口客户区、含标题栏的外框以及Retina/DPI缩放。截图尺寸要注明截的是渲染帧还是桌面窗口。CanvasScaler的referenceResolution只定义UI参考布局，不保证客户区尺寸，也不自动限制窗口比例，见[Unity CanvasScaler](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/script-CanvasScaler.html)。

显示器不足以容纳请求尺寸时，按项目要求决定缩小/保留大小，记录实际结果；不默认把要求的像素尺寸解释为一半逻辑点。若选择“完整可见”，需查目标显示器工作区和窗口边框后计算可容纳比例，仅按Screen.height计算不能证明窗口不会越界。

## 默认值、历史偏好与普通启动

1. 核对构建入口最终写入的PlayerSettings、目标平台和运行时尺寸代码；跨平台构建可能共享Standalone设置，不能只看上一次的ProjectSettings。
2. 对比普通启动与指定尺寸的诊断启动。后者正确而前者错误时，检查保存的窗口/最大化状态、命令行和初始化代码。不得用诊断启动截图替代普通启动验收。
3. 产品从占位标识迁到独立应用标识时，先盘点PlayerPrefs与进度文件路径及迁移影响；只迁移本项目必要数据，不删除共享偏好来解决窗口问题。新建项目尽早采用稳定且独立的标识。
4. 运行时确需强制初始尺寸时，等待应用后再读实际值。[Screen.SetResolution](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Screen.SetResolution.html)在当前帧末应用；不要紧接调用读到旧值就不断重设或宣布失败。

## 固定比例是目标平台能力

- 约束客户区比例，标题栏和边框另算；同时核对UI和世界相机，避免只有棋盘保持竖屏、HUD铺满横屏。
- macOS原生窗口约束与Windows窗口消息是不同集成。若用Win32 WM_SIZING，应调整拖动矩形并涵盖八个边/角；其[官方契约](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-sizing)并不证明启动、最大化或程序设尺寸也受到相同约束。
- 原生钩子的句柄归属、回调生命周期、卸载、窗口重建、DPI/显示器切换需目标系统验证。几何函数测试仅覆盖算法，不能证明消息实际到达或回调安全；未经验证的项目插件留在项目内。

## 最小验收矩阵

| 场景 | 回读与操作 |
| --- | --- |
| 新偏好普通启动、已有偏好重启 | 实际模式、客户区/渲染尺寸、构建ID；不强制清空旧偏好 |
| 拖边/拖角后关闭重开 | 比例、尺寸持久化、布局与命中；程序改尺寸不替代真实拖动 |
| 最大化/恢复、较小工作区、DPI变化 | 是否符合项目窗口策略，是否越界或突然横屏 |
| 首页、弹窗、长队列、教学 | 相机/UI一致，按钮可点，遮罩与粒子正确 |

按平台、输入方式和构建分别记录；缺少目标系统时只报告已完成的编译、清单、几何测试，将实机项留待验。原版移动端画面、macOS运行与Windows交叉构建不能相互替代。
