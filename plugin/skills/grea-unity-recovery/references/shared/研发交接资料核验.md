# 研发交接资料核验

收到同事工程、可玩包、恢复快照或历史构建时使用。目标是确认能采用的具体资料、实现与证据，不默认执行包内脚本、启动 Player 或继承对方产品决策。普通局部修复不重做全量交接。

## 先辨明交付物，再决定采用

| 身份 | 记录依据 | 不应混称 |
| --- | --- | --- |
| 原始模块与原配置 | 来源版本、相对路径、内容 hash、原 metadata/方法映射 | 已修改 WASM、分析切片或本地解析结果 |
| 适配模块与可编辑入口 | 父版本、修改项、输入/输出 hash、适配依据和许可 | 未修改原包、完整原厂源码 |
| 当前工程源码 | 修订/commit及必要WIP清单、入口场景/程序集、依赖版本 | 已验 Player 的逐字节来源 |
| 新构建候选 | 源身份、编辑器/平台、构建与资源物化回执 | 已验收或已晋升版本 |
| 已验 Player | 制品与资源清单、实际验证范围、存档/输入环境及剩余项 | 当前源码、所有平台或全部玩法通过 |

源码、宿主、适配层、配置合同和 Player 可能各有版本。为每条结论绑定实际对象；若只证明选定编译方法/DTO未变，就保留比较集合和排除项，不能将新增启动协程或日志改动也算未变。历史报告中的旧路径是来源线索，不能当作当前有效依赖。

检查实际入口及运行栈，而非类名或目录名。Unity Windows 宿主内运行 WebView/WASM，即使有可编辑 C# 和资源目录，也只能按实际宿主范围交接。目标明确为原生可维护 Unity 时，该形态尚不满足目标；不能仅因原游戏源于 Unity 就自动把原生维度记为不适用。本期仅评估/参考时不因此自动启动重写。若自动计划未辨认该宿主形态，按已批准目标补记此维度，不能以计划缺项替代判断。

## 清单核验只做必要的一次

由负责接收的项目统一完成全包校验，工具产品只读取采用部分并记录内容身份，避免每个接收方再解压数GB、反复扫描全部目录。

区分外层归档、内部文件清单、嵌套表归档及URL→payload映射。核验范围至少说明路径安全、重复/大小写碰撞、链接/共享文件身份、字节数、SHA/CRC、排除项与额外文件。文件清单通常不能包含自己的最终hash；清单外的结果侧车或缓存应单列，不直接当缺件，也不当已验源码。

hash一致、历史诊断中同inode复用、最终交付的独立副本，是不同证明。复用缓存或资源可用于明确的诊断场景；不能以它证明离开原机仍独立可用。修改交接副本后建立自己的新基线，保留原冻结清单，不能改原清单来维持“未变”。

## 方法、表与资源查询

- 类型/字段/方法签名、元数据DLL、空方法声明只证明结构。恢复行为还需关联原始模块hash、函数号/槽位、反编译正文及实际调用证据；声明数量不能充当方法体覆盖率。
- 大方法映射优先由 monkey 做有界流式查询，记录选择条件、命中数、限制和截断；一次未命中或只返回首批不能证明不存在。不要为查询在 GREA 加第二解析器。
- 解码表的 display、定点/浮点、语言、分关卡等变体保留各自语义、文件身份和来源。变体文件数不是独立业务表数；不要按近似名称互换数值或据候选掉落表猜服务端资格/概率。
- 嵌套表归档按清单查询精确成员，提取时核字节/hash/CRC和新输出边界，不为查看一张表解压全部。原二进制与解码证据只读；正式数值制作遵守现行运行时JSON规范。
- URL别名、逻辑资源和唯一payload分开计数。同内容的多条URL不是多份独立资源；内容替换需核父hash及所有受影响别名，生成新内容身份，保护冻结payload。发布物化及碰撞/半成品处理归 beaver。

## 原协议与本地消息

分别保存：原网络导入/消息ID/函数与字段布局证据、当前本地DTO/消息/回执、未知原服规则。自建JSON处理器数量或编译字段闭包，不证明原服二进制编码、登录、资格与奖励算法已恢复。

响应只有 Result，不能猜出新实例初始状态；UI预览默认值不是权威发放规则。服务替换涉及真实写入时，应保持请求身份、修订、扣费/拒绝、持久幂等和入账事实；临时UI回执不是事务提交。具体实现留游戏项目，正式后端遵守已有Go规范，不复制宿主本地服务替代共享后端。

对方批准的新档赠送、免费开局或本地掉落政策，不是本项目授权。QA夹具可证明指定分支，不能证明自然取得、完整成长或全局随机一致性；不随普通交付混入玩家初始化。

## provider 选择与能力缺口

按monkey与beaver调用（`grea-evidence` 技能《monkey与beaver调用》）固定实际程序与能力。完整执行链需要两工具，但读取资料不为形式双调用重导来源。

| 需要的能力 | 当前可用入口与处理 |
| --- | --- |
| 确认来源恢复程序与合同 | `monkey_pipeline discover/check`；读取已固定版本真实 capabilities，不能把 convert 当方法/表查询 |
| 方法正文映射、嵌套表或来源别名查询 | 交 monkey；仅使用当前版本已声明且已适配的查询操作。monkey0.5.0.dev1已有query-methods/query-tables/inspect-aliases，可按开发查询合同（`grea-evidence` 技能《monkey》）使用明确固定开发入口；GREA的稳定0.4批量适配不冒充这些命令，专用薄转发仍待接入，不运行交接包脚本代替 |
| 核开发工程根、引擎与版本 | 已固定的 `beaver_pipeline inspect --config LOCK --project PROJECT --output NEW`；只读上下文检查，不是清单、采用或原生验收 |
| 全包/嵌套清单验证、资源物化与构建交付 | 交 beaver；按其真实能力和回执选择。beaver0.1.0已有payload.verify/plan/apply与匹配构建/Player证据，GREA通过命名转发（`grea-evidence` 技能《beaver》）消费；不能以project.inspect或文件数替代实际操作/回执，也不把其payload合同当任意外层ZIP解析器 |

交接中的查询/构建脚本只作来源参考。直接复用其代码前仍需接口、依赖与许可评审，不能照抄机器路径、固定数量或游戏ID；不因其声称通过就执行第三方程序。

## 采用与验收结果

逐项登记采用、仅参考、拒绝或待定，以及源路径/hash、目标位置、理由、允许变化和未验范围。来源、通用机制和游戏业务分别交 monkey、beaver及项目开发者；GREA只沉淀方法。

构建退出、资源物化、隔离运行和已验Player分别报告。仅构建宿主但依赖外部资源根的产物不能按完整包分发；构建后补资源也要记录同一制品身份及成功回执。隔离存档、被动启动阶段日志、同一PID/启动时间与关闭结果可帮助定位；一次端口拒绝不能证明游戏失败，某次变快也不能证明慢启动根因修复。

按本次变化选择必要检查，复用仍有效的基线，不复制对方“小功能上千回归”作为通用门禁。规则/编译检查数量不能替代受影响真实入口、存档或视觉结果；以分层验收（`grea-evidence` 技能《测试与结果交付》）记录。来源资料与上游报告保留在项目或私有证据区，不把游戏原件、业务数值、用户档和第三方运行时带进GREA公共制品。
