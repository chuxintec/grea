# Unity · 工程重建与恢复

工具推荐：unity_dependency_audit、unity_asset_ledger、Unity CLI/Pipeline；包恢复先查grea/.private/backups/unity-packages。 入口和限制见 [工具清单](../../../shared/02-工具-选择与调用.md)。

新增或获准标准化工程时，按 [工程标准 v1](../../grea-unity-standard/references/05-Unity-工程结构与开发规范.md) 选择目录、依赖和生命周期契约；框架包与受限生成器已经提供，实际范围见 [生成与恢复](../../../../docs/Unity指南.md)；它们不能代替原版资源恢复。

## 工程路径与版本

先读取局部 AGENTS、ProjectVersion、Packages 与状态入口；新建仅在确认没有目标工程后执行，使用空闲 project-XX。源游戏 Unity 版本与目标编辑器版本分别记录，不能为了“最新”自动升级。用户要求升级时备份 Packages/ProjectSettings，检查脚本、程序集、Shader、Spine 和构建工具引用，再由新编辑器打开验证。

复用另一项目的中间数据时记录源包哈希、源文件路径与哈希、方法证据及验证状态；被移植版本只是参考实现，必须回到原包代码核对。不要把网页近似算法重新写成 C# 就称为 Unity 原版逻辑。

## 原始导出到可运行工程

1. 原始导出保留在 `Analysis/AssetRipperExport` 或既有目录，只读作为依据。工作工程的导入副本与修复副本分开，名称沿用项目约定。
2. 以原场景/Prefab 为根计算 GUID 闭包；保存 `.meta` 与引用身份。审计文本依赖之外，还查 Resources.Load、Addressables、AssetBundle 与代码拼接路径的动态资源。
3. 排除未经核对的导出脚本空壳、重复的 Unity/TMP/Spine 程序集；记录被排除的组件身份与恢复计划，不把所有 Missing Script 直接删掉而丢失序列化证据。
4. 脚本重映射使用原程序集 GUID + fileID + 类型身份 → 目标 MonoScript GUID/fileID；不能凭同名取第一个脚本，DLL 类型 fileID 也不能一律当源脚本的 11500000。映射表项目专用，不能复用其他工程的 GUID 或绑定数值。
5. 通过编辑器 AssetDatabase/PrefabUtility 导入与修复工作副本。活编辑器可连接时禁止外部手改场景/Prefab YAML；导入批处理使用 try/finally 恢复 AssetDatabase 编辑状态。
6. 等待导入与域重载结束，检查 Missing Script、资源引用、纹理、材质、字体与控制组件；先让一个原 Prefab 在真实 Camera/Canvas 下显示，再扩展整个系统。

## 代码恢复证据链

| 产物 | 可用于 | 不可声称 |
| --- | --- | --- |
| 原 Mono 程序集有方法体 | 反编译、控制流和常量核对 | 自动等同原项目源代码/注释 |
| DummyDLL / return default 空壳 | 类型、字段、签名与序列化 schema | 原业务实现已恢复 |
| IL2CPP dump/script 索引 | 方法地址、类型、字段、定位 | 任一方法逻辑正确 |
| Ghidra 伪代码/反汇编 | 分支、结构、调用、内存布局的静态依据 | 可直接编译的 C# 或完全准确类型 |
| 跨语言转写 | 经逐项核对的实现 | 原生严格一致，除非已有对照 |

每个恢复模块记录方法签名/地址、原 SO 和 metadata 哈希、入口与调用者、字段与返回值布局、状态写入、随机/时钟、目标实现及验证。先恢复数据模型与执行顺序，再对关卡数值比较；配置相同不证明算法相同。

重点复核值类型返回、打包整数高低位、符号扩展、数组初始化、缺省值、状态机 MoveNext、委托/回调和虚调用。任务经验中，高 32 位曾被误读为“记录存在”而非完成状态；遇到类似结构先查构造与消费者，不依据一个变量名猜语义。原版有条件替换已有记录，不可随意改成 upsert。

Ghidra 优先复用同哈希的现有数据库，以方法地址清单定向恢复。已完成分析的数据库才考虑只读/noanalysis 路线；目标本身未分析时不能禁用分析后将缺失当空方法。脚本应输出方法清单、失败原因、调用关系与代码到新目录，不用循环全库导出掩盖类型问题。

## 运行时和资源兼容

Spine 先读取数据版本再选择运行时，不根据机器已有 Spine41 就用于 3.8 数据。保留上游来源、提交与 LICENSE；修改兼容 API 的工作副本，配置目标 Editor/Library 引用，不硬编码旧编辑器路径。只有 Editor 编译和真实动画播放通过后才算接通。

Shader 同名不保证同实现：以实际资产路径、属性、渲染队列和关键字核验。TMP 字体为空时不要继续访问材质；先修字体引用。SpriteSkin、BoneFollower、遮罩和运行时资源替换是功能组件，不应因为场景暂时可见就忽略。

具体缺图、Spine 页名/尺寸、排序、占位 Shader 的顺序见 [资源逆向恢复](../../grea-evidence/references/04-资源-提取与引用恢复.md)。不要把特定游戏的动画名、骨骼偏移、奖励或费用写成通用默认值。

## 原包与可运行中间版本的区别

已解压H5或前一版网页工程可能含登录屏蔽、平台桥接、自动测试入口或格式化修改。先对原包成员做逐字节哈希，必要时按模块正文比较并解释包装/换行差异；“文件数一致”不证明原逻辑未修改。保留原件、中间版本、目标实现三个层次的来源。源不是Unity时，用原数据重建Unity对象，不称为恢复出原作者Unity源码。具体网格/骨骼/坐标契约见 [跨引擎恢复](../../grea-native-port/references/05-Unity-跨引擎移植与行为一致性.md)。

## 加密或热更新代码的定位边界

方法索引存在但磁盘SO缺少可直接定位的方法体时，先区分磁盘文件、运行时解码/映射后的代码、静态注册表和元数据身份。地址槽是“方法身份到代码位置”的定位证据，不是方法体；读取地址表不等于恢复了算法。先复用已有同版本代码捕获，建立模块/类型/token→地址槽→运行地址/RVA→代码段→调用链的可核验映射，不能用相邻地址猜身份或把多个共享泛型地址当多份独立实现。

只有现有授权覆盖时才读取目标游戏的运行时映射或静态表；核对包版本、模块基址、计数、段边界及只读范围。说明为何磁盘SO/metadata不足，以及本次到底读的是代码、地址还是不可变元数据。沿用用户已明确扩大且仍适用的授权，不按历史小批次反复申请；该授权不自动扩展到玩家/账户对象、注入或整个进程导出。原始快照、方法清单、探针和常量继续留项目，不提升为通用解密能力。

## 动态代码与时序

Prefab 不能独自解释运行结果。结合初始化、数据绑定、按钮回调、状态切换、动画事件和销毁流程，恢复真实行为。

IL2CPP 静态分析先用 metadata/类型/方法地址限定范围，再追字段和调用者。方法名、伪 C 代码和单个函数内未出现调用都不是充分结论；必要时查看异步状态机、回调和交叉引用。静态证据与原版行为交叉核对。

动画恢复关注 Clip、Controller、曲线插值、父子变换、active/alpha、事件、声音和完成回调。音频触发可能在 Clip 外，不因找到音频就猜播放时刻。目标运行时不支持的行为必须说明适配边界。

## Shader 与 Spine 接入回读

- 遇到 DummyShaderTextExporter 等占位导出，先恢复匹配渲染管线的正式 Shader。先检查 Shader 是否定义目标属性，再改颜色；对没有 `_Color` 的 Shader 反复设颜色不能修引用问题。
- Spine 运行时匹配数据版本；atlas 页名与纹理绑定名、导入后的真实尺寸应一致，检查运行材质非空、旧导出网格与新骨骼渲染是否重复。动画名取原序列化动画引用；骨骼挂载、屏幕定位和标题跟随还需追运行代码。

- UnityEngine.Object 的存活判断使用 Unity 的 null 语义；带失效原生对象的托管包装可能不被 `??` 识别。MissingComponent/空字体问题先查引用和生命周期，不把所有空值都归为这一原因。
