# 配置、表现与性能的有限预检

这些工具按明确数据契约分析输入，不执行源游戏、不推断服务端规则。工具 ID `config_preflight`、`presentation_audit`、`performance_compare` 由 Beaver 0.4.0 提供；从 GREA 使用时通过 `describe-tool` 核对当前登记，再以原 ID 调用 `run-tool`。直接使用 Beaver CLI 时按当前 help。输入保持只读，输出使用新路径，报告保留输入 SHA-256；provider 存在或合成样本通过都不表示目标游戏已验收。

## 配置 `config_preflight`

`--contract contract.json --output new-report.json`。契约包含 `schema_version: 1`、`codec: typed-json-v1`、`tables` 和 `references`。

每张表声明唯一 `name/path/authoring/key/fields`。`path` 相对契约文件，不能越过上级；`authoring` 是 `json`、`excel_export` 或 `scriptableobject_export`，后两者表示由该唯一制作源导出的 JSON。工具本身不读取 Excel 公式或 SO 二进制。

字段声明 `name/type`，类型支持 int32、有限 double、bool、string（对应 `int/double/bool/string`）；可选 `array/optional/nullable/min/max`。不将缺失变成 null，不将 null 变成空串，不将大整数偷偷转为损失精度的 double。数组不接受隐式分隔字符串。输出保留原始数值和逐字段 missing/null/value 状态。

只有 `references` 中的 `from_table/field/to_table/key/sentinels` 会触发跨表检查。没有声明的数字不是外键；表达式字符串只是数据，不能执行随机函数来“验证”。本工具与现有 `unity_config_candidate` 的标量原生资源生成器职责不同，不冒充完整业务编译器。

## 表现 `presentation_audit`

`--input capture.json --output new-report.json`。契约包含 `schema_version: 1`、`candidate_sha256`、`run_instance` 和至少两个 `frames`。每帧有递增 `frame`、`phase` 和 `nodes`。阶段为 cold_open/active/closed/reopen/pool_reuse。

Unity Editor 中可在 Play Mode 调用 `Grea.Editor.PresentationSampler.Sample(root, phase, pointer)`，读取真实 Graphic、TMP/legacy 文本、CanvasRenderer mesh/cull、遮罩、raycast、Animator 时间与粒子数。不会强制刷新布局来掩盖首帧问题，也不会重播动画。将多个采样封装为 `PresentationSampler.Capture`，用 JsonUtility 输出到项目证据目录。

节点 ID 包含层级和兄弟索引。动态重排后需由项目适配器提供稳定领域 ID，不能把不同节点硬配成同一对象。`expected_clickable/expected_mask/expected_restart/generation/callback_generation` 是项目明确注入的预期，通用采样器不会猜测。Spine 轨道和项目 Tween 回调需项目适配器补充真实值。

- 检查 active 但 culled、非空文本无 mesh、命中遮挡、缺少预期遮罩、旧生命周期回调、池复用未重播。
- `blend` 默认 unknown。只有明确 alpha 混合才能据 alpha=0 报透明问题；additive/PMA 的 alpha=0 仍可能贡献 RGB。
- 缺失字段表示未观察，不当作 0；节点引用非空和检查无告警不证明屏幕像素正确。
- 最终字体、缩放、动画、交互仍需 Player 截图/逐帧/真实输入验收。采样工具依据 [Unity CanvasRenderer API 源码](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Modules/UI/ScriptBindings/CanvasRenderer.bindings.cs) 读取当前网格，绝不销毁渲染器拥有的网格。

## 性能 `performance_compare`

`--before before.json --after after.json --output new-directory`，输出 JSON 和便于表格查看的 CSV。每个 run 包含 `schema_version: 1`、`candidate_sha256`、`identity`、`samples`、`counters`。

identity 必须含 workload_sha256/device/platform/viewport/quality/seed/input_sha256/measurement；比较时全部一致。每帧声明 frame/phase/focused/valid/frame_ms。phase 为 cold/warmup/steady，分别统计，不能混算。比较要求阶段样本数相同；任何失焦、无效帧、非有限值均拒绝作为优化结论。

counter 使用 `{supported, value, unit}`；不支持的值必须为 null，不能填 0。报告为 mean/p50/p95/p99 和稳态百分比变化，分位数采用 nearest-rank。小样本只描述本次测量，不证明统计显著性。工具不自动认定达标，不降低画质、不限制怪物数、不把不同种子/输入或 QA 配置混成优化前后。

## 当前边界

版本、provider 和现场回读结论以当前 registry 与项目证据为准；本工具不携带项目验收结果。未采集的目标平台和游戏仍是未验证；这些工具不能自动签发游戏验收通过。

CSV 输入使用规范列 `frame,phase,focused,valid,frame_ms`，bool 必须为小写 true/false；用 `--before-metadata` / `--after-metadata` 明确提供各自 JSON 身份和计数器状态。不会自动猜测项目 CSV 的毫秒/纳秒单位和冷启动边界。
