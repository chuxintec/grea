# 候选交接、采用与三方合并

用于将 monkey 候选或同事交来的工程接入既有开发工程，或接收后续恢复增量。日常局部修复不重新触发来源恢复。完整来源取证和候选准入属于 `grea-recover`；开发阶段只采用固定候选和证据，不默认执行交付包内脚本、启动 Player 或继承对方产品决策。

## 先绑定交付物身份

| 交付物 | 记录来源 | 不可混称 |
| --- | --- | --- |
| 原始模块/配置 | 来源版本、相对路径、内容 hash、原始 metadata/方法映射 | 已改 WASM、解析切片或本地结果 |
| 适配模块/可编辑入口 | 父版本、修改、输入/输出 hash、适配依据和许可 | 原包副本、完整原厂源码 |
| 当前工程源码 | commit、必要 WIP 清单、入口、依赖和工具链版本 | 已验 Player 的逐字节来源 |
| 构建候选 | 源码身份、Editor/平台/参数和资源物化回执 | 已验收或已晋升版本 |
| 已验 Player | 包与资源清单、环境、实际验证范围、存档/输入及限制 | 当前源码、所有平台或全部玩法通过 |

逐项绑定实际对象。目录名、字段/方法签名、metadata DLL 和空壳方法只证明结构；采用业务行为还须关联固定来源、实现/调用依据和状态变化证据。旧路径与历史报告只是检索线索。按实际入口、宿主与资源加载路径识别运行形态；Unity 宿主内若实际运行 WebView/WASM，本期原生可维护 Unity 目标仍未满足。仅作评估时不因此自动启动重写。

完整包与嵌套清单、路径安全、资源别名、原生闭包及深度方法/表取证由 `grea-recover` 处理；本篇不另建解包器或来源解析器。原网络/消息证据、当前本地 DTO 和未知原服规则分开；本地字段闭包不证明原服编码或算法。玩家档、数值和 pending/回执按[生命周期与变更合同](生命周期与变更合同.md)保护。交付方的新档赠送、免费开局、掉落规则或 UI 默认值不是本项目授权或事实。

GREA 维护接手方法；monkey 固定来源身份和只读候选，beaver 处理当前工程比较、采用、迁移及受控恢复。使用当前固定 provider 与其真实合同，见[monkey 与 beaver 调用](../../grea/references/monkey与beaver调用.md)；没有已核能力时保留 `needs_action`，不运行交接包脚本代替。

## 比较与受控采用

只有清单/哈希通过时，可进入采用规划和适用的隔离原生检查；不能将它写成业务接续已准入。核对恢复交接要求的来源覆盖、原生回执和明确例外后，再固定开发基线。已有匹配证据可复用，不为进入开发而重导；缺口只阻塞依赖它的部分。

已有工程必须比较旧候选、新候选、当前工程。没有可靠共同基线或来源身份有歧义时请求明确选择，不猜同名即同资源。分别列出仅候选变化、仅人工变化、双边冲突、移动和删除建议；源文件消失不直接删除工程资产。GUID/UUID/localID、Sprite importer、嵌套 Prefab/Variant 与动态资源键都是兼容条件，单看文件 hash 不够。

beaver 计划须固定工程/候选/provider 身份、允许写区、`expected-before`、动作和恢复位置。apply 前复核前置状态；失败保留逐批回执。原生资源移动/保存走工程的 Editor API。恢复仅撤销当前仍匹配本次 `after` 的自有变更，不能覆盖后续人工修改、玩家存档或服务端事实。

登记每项采用、仅参考、拒绝或待定，包含来源路径/hash、目标位置、允许变化、证据和未验范围。候选文件齐全、hash一致、构建退出 0 或工具生成目录均不能证明原生导入、运行、业务或视觉通过。采用、静态引用检查、Editor 导入/编译、实际运行、业务/视觉验收分层记录；只改来源工程但仍依赖外部资源根的构建不能当完整可分发包。结果写回项目自己的交接/验收记录；GREA 不保存原包、玩家数据、凭据、私有提示词或完整原始运行日志。
