# 开发任务与模式选择

本篇把已采用游戏工程的实现任务分派到开发专题。模式决定比较基线与必需边界；不因同属开发阶段而混用恢复、玩法增量、换皮或发布验收。

## 阶段边界

| 目标 | 阶段 | 处理方式 |
| --- | --- | --- |
| 从包体、源码交接或异构序列化恢复来源，并形成新工程候选 | `grea-recover` | 冻结来源、恢复资产/代码并核验候选；已有可维护工程不因继续开发而重导。 |
| 在已存在或已采用工程内修复、接入配置/资产、做结构治理或 Editor 操作 | `grea-develop` | 沿当前工程和已验收基线实施本期范围；普通修复不顺带重构。 |
| 以原版证据修复规则、资源、画面、交互或时序差异 | `grea-develop` 的 parity 任务 | 原版证据定预期，只修复有界差异；局部修复不重新解包全游戏。 |
| 构建、目标 Player 验收、封装、安装或发布 | `grea-release` | 固定工程输入与构建身份，分层交接构建和目标运行证据。 |

研究建议、恢复候选、工具计划、Editor 回读或构建成功，都不自动批准后续阶段或扩大范围。未获批的开发目标只做方案，不创建、迁移、安装或发布产品工程。

## 开发模式

| 模式 | 比较基线 | 必须保持或声明 |
| --- | --- | --- |
| 维护/修复 | 当前采用工程、现行行为、资产身份和存档约定 | 只改授权缺陷及直接影响；普通修复不迁移目录、程序集或框架。规则预期有争议时采用 parity 证据。 |
| `feature` | 固定旧不变量与批准的新行为 | 合同说明目标、允许变化、基线、产品/存档身份及 config/save/protocol/pending 兼容。 |
| `tuning` | 可比测量基线和明确目标 | 固定测量口径和允许变化；不以改规则、随机、画质或存档语义冒充性能/数值提升。 |
| `prototype` | 独立工程和存档 | 只回答一个问题，写清保留/丢弃条件；输出仍是候选。 |
| `reskin` | 最新批准设计与需保持的行为合同 | 按授权替换表现；衍生产品身份与来源分开。完整阶段见[游戏换皮与资源制作](游戏换皮与资源制作.md)。 |
| `evolve/ui_ux` 兼容模式 | 旧 v1 UI/UE 合同与玩法不变量 | 只改变明确批准的表现维度，不据此扩展玩法。新 feature/tuning/prototype 读[生命周期与变更合同](生命周期与变更合同.md)，不套用旧 UI/UE 限制。 |
| 自有 Go 服务 | 批准的自有业务边界与客户端合同 | 不恢复未知原厂服务；六服归属、事务和部署边界见[Go六服与事务](Go六服与事务.md)。 |
| Creator 工程 | 用户明确选择的 Creator 目标、版本和已采用工程 | 不包装成 Unity，也不套用 Unity asmdef/uGUI/UPM 规则；工具支持子集见[Cocos目标工程工具](Cocos目标工程工具.md)。 |

模式合同与存档兼容见[生命周期与变更合同](生命周期与变更合同.md)。工具校验、规划或 caller 声明不代表用户批准、实现、迁移或验收。

## 任务到专题参考

只读取与本期任务有关的专题，不整组加载。

| 任务 | 参考 | 边界 |
| --- | --- | --- |
| 工程结构、生命周期、Prefab、脚本所有权、目录或资产迁移 | [Unity工程结构与开发规范](Unity工程结构与开发规范.md)、[重构与资源迁移](Unity重构与资源迁移.md)，再按对象读程序集/组件/生成专题 | 仅在治理或迁移需要时加载；保留 GUID/local fileID、生成所有权与人工修改。 |
| Unity 数值配置、原生 Sprite 或动画资源 | [Unity配置与资源制作工具](Unity配置与资源制作工具.md) | 正式数值以唯一运行时 JSON 为源；SO/Prefab/Scene 管对象与资源引用。 |
| Unity 配置表现、性能采样或优化 | [配置表现与性能预检工具](配置表现与性能预检工具.md)、[Unity性能分析与优化验证](Unity性能分析与优化验证.md) | 只在相应缺陷或优化目标下读取；缺值不当作零，普通 UI 修复不自动要求多轮基准。 |
| UI、输入、动画、规则或随机差异 | [开发前检查与迭代](开发前检查与迭代.md)、[规则与随机一致性](规则与随机一致性.md)，再选对应 Unity 专题 | 原版证据决定预期；不以截图、合成回调或单一测试代替真实输入/运行。 |
| 换皮、图像规格、映射和资源台账 | [游戏换皮与资源制作](游戏换皮与资源制作.md)、[主题资源映射与台账工具](主题资源映射与台账工具.md)、[图像联系表与规格工具](图像联系表与规格工具.md) | 工具只做其明示范围；联系表/alpha 统计不能证明视觉或交互通过。 |
| 新功能、调优、原型及 config/save/protocol 变化 | [生命周期与变更合同](生命周期与变更合同.md) | 固定基线、不变量和兼容维度；兼容计划不执行存档迁移。 |
| Go 服务所有权、幂等事务或 Go 样板 | [Go六服与事务](Go六服与事务.md)、[Go六服模板工具](Go六服模板工具.md) | 内部 gRPC/Protobuf，外部 HTTPS/JSON 或 WSS，MySQL 持久事实、Redis 缓存；实际支持以工具合同为准。 |
| 已采用 Creator 工程或有限迁移 | [Cocos工程与迁移](Cocos工程与迁移.md)、[Cocos目标工程工具](Cocos目标工程工具.md) | 有限序列化候选不等于 Creator 导入、编译、浏览器实测或原版一致。 |
| 外来工程/候选交接与采用 | [候选交接、采用与三方合并](候选交接与三方合并.md) | 原件、适配层、当前源码、构建候选和已验 Player 使用不同身份与证据。完整来源恢复交给 `grea-recover`。 |
| 已采用恢复工程继续补齐缺失业务 | [已采用工程的业务接续](已采用工程的业务接续.md) | 只接有依据的代表闭环，不要求重新做首次恢复交付。 |
| Unity Editor 长操作 | [Unity编辑器连接与任务执行](Unity编辑器连接与任务执行.md) | 发现实际 Editor/版本，按当前合同执行；导入、保存、Play 和 Player 是不同证据层。 |
| 已有UI批量检查、引用/事件接线或跨阶段错误诊断 | [固定beaver0.5合同](../../grea/references/beaver工程操作合同.md#固定05的ui接线与诊断) | 只在固定能力就绪且本期有实际需要时调用；静态分析/计划不代替原生执行、视觉或业务验收。 |

开发前证据不足时读[开发前检查与迭代](开发前检查与迭代.md)。验收分层、结果状态与协作合同沿 GREA 共同规范；开发任务本身不触发构建或发布。
