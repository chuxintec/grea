# 已采用工程的业务接续

用于从已接收并采用的恢复工程继续补齐有来源依据的缺失业务。包体取证、全量来源恢复、跨引擎初版转换、工程交接准入和新恢复候选均属于 `grea-recover`；不能在开发阶段重开完整恢复，也不能用单个小样替代原本尚未交付的恢复候选。

开始前固定实际采用的工程/提交、目标引擎与版本、来源证据、当前未实现业务、已知玩家档和配置身份。按获批范围选择一个可操作的代表闭环；证据只覆盖实际观察到的规则、状态和表现，不用猜测补齐未知规则。不能直接从证据推导的部分标为未知，先完成可独立且有依据的工作。

先打通代表路径的状态写入、真实入口、结果反馈和关闭后续玩；具体路径由项目实际玩法决定，不把示例顺序写成所有游戏的固定流程。闭环以规则依据正确、入口可操作、结果和保存一致为准；有依据且属于基本可见内容的效果/输入不必推迟到视觉收尾。该路径通过后再按不同数据、页面、镜头或生命周期风险扩展其他模块。

存档兼容遵守[生命周期与变更合同](生命周期与变更合同.md)：正式数值配置依项目合同使用 JSON 唯一制作源，原始提取表只读保留；配置版本与玩家存档 Schema 分离。修复发现根规则或资源假设错误时，回到受影响阶段并重验引用入口；没有新证据不重复调参。

每次接续记录“来源依据 → 工程实现 → 实际入口 → 运行结果 → 未验差异”。候选、静态检查、Editor 回读和构建均不能替代对应的 Player、输入、存档、视觉或业务证据；结果按[测试与结果交付](../../grea/references/测试与结果交付.md)分层报告。
