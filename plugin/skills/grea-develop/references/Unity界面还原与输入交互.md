# Unity · 界面还原与输入交互

工具调用先核固定版本与能力，使用已接入的 beaver `ui.inspect/analyze/repair-plan`；原生字段或预览捕帧按[beaver合同](../../grea/references/beaver工程操作合同.md)的实际候选能力选择。字段、几何分析和规划不自动证明材质效果、真实输入或画面合格；截图须在实际允许的Editor/Player或桌面入口观察。未知专项检查保留人工核对与缺口，不编造可用工具。

以下汇总界面恢复的实际返工，用于确定检查方向；对象、参数及规则仍须由当前游戏验证。

## 布局与图片

恢复并映射实际存在的组件：

- UI：Canvas 模式、缩放规则、参考分辨率、RectTransform 锚点/pivot/尺寸/偏移、父级缩放、LayoutGroup、ContentSizeFitter、滚动和遮罩。
- 场景：Transform 父链、Camera 投影、位置和缩放、SpriteRenderer 排序、active/enabled、镜像和颜色透明度。
- 图片：Sprite rect、紧密裁切/旋转打包、pivot、pixels-per-unit、border/九宫格、纹理实际尺寸和透明通道。
- 字体：原字形/字体资产、字号、描边、行距、对齐、换行和自动缩放。不要用拉伸图片掩盖字体布局错误。

不要把隐藏层全部显示，不要将主页建设场景直接当作关卡背景。背景可能由区域配置和运行状态共同选择。

实现源参数到目标平台的映射，保留坐标单位说明。必要的截图校准标为适配值，不标为原始 Camera 参数。旧 HTML/CSS 适配值只能作为历史参考，当前 Unity 的 Camera/Canvas 映射仍需回读验证。

### 布局属性所有权

对发生冲突的 RectTransform，按属性和状态明确写者：锚点/pivot、位置、宽度、高度分别由布局组件、父级适配或业务/动画控制。一个节点可以使用不同组件控制不同属性；同一属性在同一阶段只有一个权威写者，动画与布局接管时点须明确。沿真实父链和刷新顺序核对生成值、LayoutGroup/ContentSizeFitter、项目约束组件及直接坐标写入，不能凭组件存在就认定冲突。

先查是谁在打开、绑定数据、图片就绪、滚动或尺寸变化时覆盖属性，再修权威源或控制关系。保留原版适配、九宫格、滚动和动画依赖；禁止无差别删除布局组件，或仅逐控件挪位置遮盖共因。重复问题先修共有布局/样式的来源，再回归实际受影响页面，生成与旧入口按[唯一生成源](Unity脚本与生成契约.md#唯一生成源与退役)收口。

项目按标题、正文、数字、按钮等原版角色维护自己的样式与复合组件，具体边界见[项目样式与视觉组件](Unity通用组件与Prefab.md#项目样式与视觉组件)。涉及底框、描边或状态图层缺失时同时核 Sprite/材质/排序/裁切与实际绑定，不能以文本存在或功能测试通过关闭视觉问题。先用代表性静态弹窗、滚动网格、动态任务列表验证共因，再按本次批准范围推广；这三类只是检查策略，不强制所有游戏建立同名页面。

同页/状态/视口、来源版本差异和缺陷状态统一按[画面对照](../../grea/references/实际体验与画面对照.md#开发与ui对照)记录，不在本页另建一份验收表。

### 映射中容易遗漏的细节

- 静态 prefab 坐标不等于最终画面。动态挂载父节点、屏幕比例分支、运行时换图、滚动内容高度和布局重算应一起追踪。明显屏外的静态投影先记录缺失的运行调整，不靠裁掉溢出或逐控件偏移冒充恢复完成。
- Simple Sprite 按 rect/PPU，Sliced Sprite 按 renderer size 与 border 处理。九宫切片的目标边宽由 border/PPU、父级变换和 Camera 投影决定；两半镜像先各自切片再合成，不能整图拉伸。改变容器尺寸时检查角部与边宽，暴露错误的缩放责任。
- 运行时生成 Sprite 可能使用不同于静态资源的 PPU/pivot；静态 m_Sprite 为空不证明缺图。沿创建/赋值代码恢复参数。
- 换图时保留源尺寸模式：使用图片原尺寸与保留作者自定义尺寸是不同契约，连同帧原尺寸、裁切尺寸及节点锚点核对。不要统一缩小图标；空图片在源引擎中若透明，不能映射成 Unity 默认白块。
- 文字宽度异常先查前后空格、换行、富文本和溢出模式，再决定测量/布局方式。保留源语义需要的空格，不能对所有文本统一 trim 或统一禁用换行。测量结果关联原文本与节点，最终到实际页面复核。
- 进度条区分水平、垂直与填充模式，核对总长度、方向、锚点及实际进度，不能默认映射为径向填充；一种模式通过不覆盖其他模式。
- 曲面文字使用字形 advance、bearing、基线、边界、TMP 字号与自动缩放，以及完整父变换链。图片透明 padding 不算字距；曲线位移和切线斜率使用同一坐标单位，不用几个视觉缩放常量补偿缺失的单位转换。
- 原始网格的逐顶点颜色需要插值。放射光等网格不能把每个三角形填成第一个顶点的颜色；同时恢复混合、遮罩与排序。独立展示页的正确效果仍需在真实父节点、比例和生命周期下接入验证。

## 资源与界面

- 找到相似 PNG 不等于找到正确界面。主页用户栏、资料编辑页和资料展示页是不同对象；先确认根、加载方法和运行分支，再沿完整引用链导出。
- RectTransform 的 localPosition 为零仍可能有 anchoredPosition。只取局部位置会使字体集中或偏移；必须处理锚点、pivot、父变换和运行布局。
- 导出按钮内部绿色底图会遗漏外层金框；检查完整父节点。Shop 不同礼包使用不同奖励分支，不能把所有道具排成自拟的一行。
- 多层艺术字不能用同字体的单层文字代替；逐层核对材质颜色、描边、排序、父级锚点和曲面变形。重复出现的标题偏移应回到公共映射修复，再对受影响宿主和状态做回归；结果绑定当前构建与输入，收口边界见[失效、复用与收口](../../grea/references/测试与结果交付.md#失效复用与收口)。


## 图片拼接、坐标与列表（后续返工补充）

- 多页正中央出现细黑线时，检查镜像半图和九宫格的共享边界是否落在小数像素。分别取整位置与宽度可能留下半透明采样缝；在最终栅格阶段统一量化共享边界，由边界之差得到尺寸。保留原始世界几何，检查不同设备像素比和缩放，不能用覆盖一条色线掩盖根因。
- 换成灰色、锁定或选中态图片时，连同新 Sprite 的 rect、border、PPU、pivot 一起切换。仅替换 PNG 而沿用旧切片参数，会使边框消失或中心切片尺寸无效；不要人为画边框替代原始切片。
- 场景粒子错位先列清“世界坐标 → Camera/RenderTexture → 裁剪区 → RectTransform → 屏幕像素”的转换链。检查裁剪原点、背景缩放方式、父级 Transform 和 CanvasScaler/AspectRatioFitter；不要先移动发射器去补偿画布被压缩。
- 弹窗内容复用不等于能复用全屏宿主。检查Canvas/RectTransform 的 anchor、offset、pivot、布局重算和居中规则；原版画面居中的内容放入全屏 Canvas 容器后，可能贴到顶部。修正后重拍实际宿主里的截图。
- 列表“只有两个场景”分开查：配置总数、实际生成节点数、过滤条件、可滚动高度和遮挡层。恢复有证据的条目；未恢复完整目录时明确数量边界，不用复制占位项制造完整性。
- 滚轮可用不代表触摸或鼠标拖动可用。核对 InputSystem/EventSystem、手势捕获、拖动阈值、ScrollRect 和拖动后误点击；异步图片加载完成后再定位列表，锁定项仍应可随列表滚动。当前区域的初始定位、标题和底栏固定也要验证。
- 虚拟列表改动或有跳页空白反馈时，分开检查逐页滚动、大步长事件、首尾边界、条目回收与关闭重开；记录实际输入幅度。仅回收夹具通过不能关闭另一种输入触发的空白，也不要仅凭相同画面认定同一根因。



## 高频拖动与UI事件分发

- 先分清输入排队延迟与渲染帧耗时。每帧只处理一个移动样本可能落后于高频鼠标；对“当前位置决定结果”的拖动可合并连续move，保留down/up/cancel及多指身份。轨迹绘制、速度积分、手势识别需要中间样本时，不套用丢弃策略。
- 原版若仅在按下时检查起拖区域，捕获后的移动不得继续被起拖边界截断。验证跨区域、窗口外抬起、失焦、切关、快速反向与重复手势；只有拿到手势的对象消费拖动。
- UI框架必须看到正确的按下位置与释放边沿。为逐帧采样框架保留边沿时，模型可用最新位置，UI首帧仍用原按下位置，防止拖到按钮上被误判为从按钮开始点击。不把手动调用onClick当真实按压、gear动画或音效验收。
- 旋转核对源坐标单位、起始姿态、局部/世界轴、四元数乘法顺序、归一化、自动旋转的暂停与恢复。没有原证据时，不加惯性/插值或改灵敏度掩盖事件积压。

## 自动化输入与跨帧验收

- 桌面自动化（CUA等）可能把按下与松开压进同一帧，拖拽退化为点击。先确认是工具时序问题还是产品缺陷，不在正式代码中为工具加常驻补丁，也不因工具限制长期卡住关键路径。
- 拖拽、长按、多点等跨帧手势优先用 Input System 的 `InputTestFixture` 等 PlayMode 测试按帧模拟按下→移动→松开；正式包同样跑一遍快速拖拽和掉帧场景，防止只在 QA 路径修好。
- 确需的验收输入适配只读取真实窗口事件、交给已有公开 UI 模块，放 Editor/Development 程序集并受编译开关与显式环境变量双重保护；退出 Play/进程后恢复，Player 默认不启用，结果与标准输入分开记录。
- 合成事件、自动输入和真人试玩是三层结果。关键链路保留真人短时试玩检查点（如每天主链约10分钟）；真人几秒能完成的步骤，不为“禁止请人测试”的规则耗费数小时绕路。

## 弹窗、提示与音效生命周期

- 原UI包优先于重建组件。FairyGUI等系统除了pivot数值，还需保留pivotAsAnchor等语义；缩放动画后检查最终位置及关闭重入。
- 通用按钮声音应走真实事件入口并遵循设置；暂停局内音源不能误停同一操作的UI声音。资源存在、AudioSource.isPlaying、可听见与原版混音一致是不同证据。
- Toast的到期清理不能只依赖会被切关统一取消的协程。给临时UI明确的宿主、时钟、销毁规则，检查显示→自动消失、暂停、重进和切关无残留。

## 点击无响应先分辨入口与资源状态

沿“系统输入→EventSystem/射线→遮挡与interactable→监听绑定→业务资格→下一页面”定位第一处中断。零体力、计时到期、未解锁、空次数与被遮罩挡住不能混为一个点击故障；先读当前普通存档及相关原配置。临时直调回调只能隔离原因，不能替代修复真实按钮。

- 将输入命中、业务接受、业务拒绝、预约/占用和最终提交记录为不同状态。按压或命中不等于已接受，动画/提示也不等于事务成功；被拒绝、等待、被其他操作预约、已提交分别按各自的原行为呈现。验证快速重复输入、并发操作、取消、晚到回调和返回后重进，确保预约只由其所有者释放，失败/取消不会伪装成成功或遗留阻塞。
- 检查跨关/重进是否重置按钮可用性；资源权益、倒计时、开关状态和按钮交互分开建模。到期后的行为依据原版或用户明确的离线策略，不能默认永久禁用，也不能自发免费续期。
- 旧档缺少恢复时间时显式迁移并保留不确定性；文件修改时间仅是兼容估算，不能当精确耗尽时刻或服务器时间。存档副本与真实用户档分别验证，禁止靠清档让入口恢复。
- 导航按钮同时检查监听、目标页面、按压/选中/回切状态。选中底座坐标须经过共同父空间转换；布局尚未结算时不能把初始化坐标误报为稳定位置。暂不可用服务显示明确状态，不把空白或禁用按钮当成功接通。

## 文本输入与保存

文本输入组件还需恢复文本/背景引用、可见状态、长度限制、变化与结束编辑事件的参数，以及原保存回调。先激活并观察焦点，再输入和提交，回读结果及重开状态。分别记录键入、输入法组合或粘贴实际覆盖了哪一种；粘贴中文通过不等于输入法已验收，立即输入丢失也不能直接归因于输入法。

## 按住反馈、焦点与声音

- 用户要求“按下放大、松开上架”时，down 只捕获对象并开始反馈；up 在同一有效目标、UI 未遮挡且业务允许时提交一次。移出、失焦、目标失效、切关或弹窗出现时取消。只接 onClick 或按下直接提交不满足该手感；旧视图销毁前立即关闭碰撞/射线资格。
- 自动化窗口 Raise、指针悬停和应用获得焦点不是同一件事。先读 `Application.isFocused`、输入边沿和截图；必要时经允许的系统 UI 激活已运行 App，再测试。不能为自动化绕过生产失焦门禁，也不能把仅设置后台运行当作点击修复。
- 频繁派发音效先检查触发事件、加载/解码时机、音源数量与叠音。预加载短音效并复用播放器，按用户/原版依据选择声音；上架、派发、采集、归巢各绑定正确事件。真实听音与 AudioSource/日志证据分别记录。
- 按钮正常/按下/禁用状态均检查透明边缘；文字和数量使用同一字体体系及基线。授权换皮的素材流程见 [素材生成与切分流程](游戏换皮与资源制作.md)。

## 复合物件的选取与继续捕获

连接部位不好拖动时，分开检查“未选中”“选中了被锁对象”“已捕获但受物理阻挡”，不要先扩大命中框或加插值。核对原射线深度、输入层与物理层、父级处理器、固定导向件向可动物件转交，以及遮挡优先级；物件列表中第一个重叠项不一定是原选取结果。

原版若支持按下未命中/被拒绝后，按住移动继续选取，应恢复该生命周期；新捕获从当前指针建立偏移，避免跳动，并按原规则限制同次手势重复拒绝反馈。若原版只允许按下捕获，则不引入滑入选取。验证空白滑入、连接处起拖、相邻对象、UI覆盖、失焦与释放，不以业务回调直调替代真实输入。

## Unity 原工程恢复的显示检查

- 对象 active、Renderer 存在和 Sprite 有名字/几何都不代表可画。实际检查 `sprite.texture`、图集绑定、UV、网格、相机可见范围及最终截图。同名候选须结合对象身份、图集与引用确认，不能批量按名称盲换。
- 保留原层次职责，不能把整个庄园/场景放进 Dialog 排序层。TMP/Spine 的 stencil 和遮罩控制脚本缺失时恢复写入/测试链；临时关闭遮罩只能定位问题，不能当最终一致性方案。
- prefab 序列化任务 ID 与配置/动画逐项映射，不按列表顺序或中文含义猜对象。恢复存档后的建筑末态应有原状态/动画依据，并实际截图核验。

## 运行实例与安全绑定

### 应用内虚拟指针与用户桌面并行

仅本次明确授权且显式启用的自有测试实例可接通应用内虚拟输入，普通分发默认关闭。固定后端与入口按[beaver虚拟输入合同](../../grea/references/beaver工程操作合同.md#应用内虚拟输入接入门)核验；尚未交付的后端保持未就绪，不复制私有替代器或用系统鼠标填补。

独立虚拟设备必须经过目标的真实InputAction、EventSystem射线及按下/拖动/松开/滚动生命周期。核当前Input System包版本、UIInputModule设备绑定、玩法读取Mouse.current或Action的路径、屏幕/视口坐标及窗口缩放；只画光标或直接调用Button.onClick、玩法方法、领奖接口均不构成输入通过。不把项目页面名、固定UUID或业务动作写入通用工具。

窗口生命周期与虚拟输入分开核授权。用户明确要求打开App时，可正常启动窗口；不能把运行时“不抢焦/不移动系统鼠标”自行扩大为“启动前必须证明窗口绝不激活”，再以此阻塞已授权的窗口化验收。记录首次打开可能激活，后续虚拟输入不靠反复激活/raise或系统鼠标完成。只有用户明确要求启动也不能激活时，才将严格prelaunch nonactivation作为该模式门槛；未经证明就报告该模式不支持，不外推为所有测试路线受阻。

虚拟模式不允许系统光标warp、全局输入、AX激活/raise、焦点切换或HardwareCursor回退；用户在其他App的正常鼠标/焦点变化不是虚拟坐标来源，也不应触发退出。目标失焦时能否继续运行、处理输入与捕帧分别实测，不通过抢焦点凑成功。需要测试专用后台设置或companion时按固定版本可撤销采用，不改正式产品策略来迎合测试。

保留用户主动接管目标测试App的停止策略；不能把主动接管与普通失焦混同。停止、超时、断开、取消拖动均须释放本虚拟设备的按键/接触状态，不动用户物理设备。错进程/实例、旧序号、过期指令与未知设备拒绝；可能已部分执行时先保全实际消费回执，不自动重发或退回原生输入。

应用内虚拟输入与旧native输入分别出结论。用户自然操作其他应用期间，须有目标click/drag/scroll处理回执及可比状态/帧，才能签桌面并行通过；缺少自然样本保留待验，不自动操控无关App伪造。分层记录见[虚拟输入与原生输入分层](../../grea/references/测试与结果交付.md#虚拟输入与原生输入分层)。

启动、只读盘点、仅绑定已有实例和发送真实输入分别记录。仅绑定须明确PID、开始时刻、实际exe文件身份、Bundle/build、运行profile及窗口所属PID；同名、同路径字符串或PID单独不足。包装器切换实际exe、别名、多实例、旧会话和退出后重绑都须验证；不存在/歧义/身份变化时拒绝，不选首个同名实例、不静默启动替代App或结束外部进程。

调用前核桌面后端真实API：在当前macOS CUA合同，getApp只接受名称/路径/Bundle ID且必要时会后台启动，未提供PID/windowId/noLaunch/attachOnly选择。Linux/Windows的windowId接口不能套用到macOS。因此string路径、getState后再getApp、重置CUA或输入后检查都不能保证“仅绑定指定已有进程”；不能据此签实例稳定绑定通过。未知/不安全绑定段停止，先使用只读实例证据。

有效替代必须有实际PID/窗口绑定且无fallback launch的控制接口，例如固定工具提供的native AX/窗口桥接，并在输入前复核同一进程/窗口/profile。该实现归beaver，GREA只维护合同与调度，不另造控制器。只读inspect产物不能冒称安全输入句柄；尚无这种能力时保留具体缺口及待验，不以重复重置绕过。SDK迁移后的候选还须把相应资产/实例身份和构建证据一起绑定，再由消费者验证输入确实送达、正常退出续玩及同实例日志收集。
