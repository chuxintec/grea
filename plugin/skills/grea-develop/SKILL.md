# GREA · 工程开发

新增游戏工程、转换导出、开发、实图和放行统一使用 Unity。Cocos 原包仍可作为恢复输入；Cocos/Creator 目标仅保留既有显式兼容入口和历史证据，暂停新增开发、主动修复与原生验收。

先读 [开发任务与模式选择](references/开发任务与模式选择.md) 与 GREA 的[共同约束与执行入口](../grea/references/共同约束与执行入口.md)。本技能负责已存在、已采用或已授权创建的游戏工程中的实现、Unity Editor 操作和受影响路径验证。

| 任务 | 路由 |
| --- | --- |
| 已有 Unity 工程的修复、资产/配置、结构治理、Editor 操作 | 本技能，按任务表读取相应专题 |
| 已有 Unity 工程按模块移除来源引擎残留 | 本技能按只减不增方式接续；不重新导出或重建工程 |
| 获批新功能、调优、原型、换皮或自有 Go 服务 | 本技能，先选择明确模式并绑定所需合同 |
| 对照原版修复规则、画面、交互或时序差异 | 本技能中的 parity 模式，读取规则、动画或界面专题并以原版为基线 |
| 从来源材料恢复、跨引擎转换或形成新工程候选 | [grea-recover](../grea-recover/SKILL.md) |
| 构建制品、验收目标 Player、封装或发布 | [grea-release](../grea-release/SKILL.md) |

已有可维护工程不因进入开发流程而重做恢复；普通修复不顺带重构。用户授权、目标模式和工具真实能力决定执行范围。规划、静态检查、Editor 保存或工具返回成功，都不能单独证明运行和产品验收通过。

## 按需参考

- [开发任务与模式选择](references/开发任务与模式选择.md)：模式边界、专题映射和开发验收顺序。
- 获准拆分独立模块或接续已有子 Agent 时，读取[功能模块并行协作](../grea/references/功能模块并行协作.md)：主开发承担关键路径与集成，按完整业务模块派工；人数、模型、共享资源和交付按该页及项目有效约定执行，小修不因此增员。
- [工程结构与开发规范](references/Unity工程结构与开发规范.md)、[开发前检查与迭代](references/开发前检查与迭代.md)：仅在治理或跨模块迭代需要时读取。
- 采用恢复候选或处理首次脚本导入差异，读[生成态、保存态与项目采用身份](../grea-recover/references/全量初版工程与协作.md#生成态保存态与项目采用身份)：资源与编译依赖分别核，静态显示与动态接线分别验。
- 已有项目成组出现 Prefab 布局/组件/图片恢复失真，或完整页面需先静态再接业务时，读[成组Prefab恢复与采用](../grea-recover/references/成组Prefab恢复与采用.md)：恢复仍由 GREA 调用 monkey，项目负责采用、接线和实际画面。
- 获准应用内虚拟指针测试时，读[虚拟指针与用户桌面并行](references/Unity界面还原与输入交互.md#应用内虚拟指针与用户桌面并行)及[输入证据分层](../grea/references/测试与结果交付.md#虚拟输入与原生输入分层)：先核固定后端和测试实例，不将旧PID鼠标模式当作虚拟设备。
- 资产、配置、性能、换皮、Cocos、Go 与 Editor 操作参考见开发任务表；不要求整组加载。
