# 候选交接与三方合并

用于从 monkey 候选进入开发工程，或接收后续恢复增量；普通工程开发不重新触发恢复。

GREA 维护接手方法，monkey 输出来源身份与独立冻结候选，beaver 负责当前工程的比较、采用、迁移及受控恢复。首次接手验证真实入口、manifest 与资源身份/引用、代码依据/未知、生成/人工/第三方所有权，再由 beaver 建立独立开发基线。原包和冻结候选只读。

已有工程须比较旧候选、新候选、当前工程。没有可靠共同基线或来源身份歧义时保留人工选择，不猜同名即同资源。仅候选变化、仅人工变化、双边冲突、移动和删除建议分开；源文件消失不直接删除工作工程资产。GUID/UUID/localID、Sprite importer、嵌套 Prefab/Variant 与动态资源键都属于兼容约束，单看文件哈希不够。

beaver 的计划固定当前/候选/工具身份、允许写区、expected-before、具体动作和恢复位置。原生资产移动和保存使用编辑器 API；apply 前复核前置状态，失败保留逐批回执。恢复仅撤销 still-matches-after 的自有变更，不覆盖后续人工修改、玩家存档或服务器事实。

采用、静态引用检查、原生导入与编译、实际运行和业务/视觉按影响分层记录。工具缺能力返回 needs_action，不能因生成了目录或 exit 0 宣称交接完成。调用准备见[monkey与beaver调用](../../grea/references/monkey与beaver调用.md)。
