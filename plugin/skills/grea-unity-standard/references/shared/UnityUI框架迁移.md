# Unity · UI框架迁移

工具推荐：unity_asset_ledger记录迁移，官方UI技能与Unity Editor API生成资源，RecoveryRuntimeAudit.cs（Editor C#）及真实输入回归。 入口和限制见 工具清单（`grea-native-port` 技能《工具选择与调用》）。

在用户明确要求将已恢复界面迁移到uGUI等另一框架时使用。先确认迁移范围、编辑目标和行为基线，保留原资源与证据；不要把所有恢复任务默认变成框架替换，也不要求最终生产继续依赖旧框架。

## 迁移不是只换Image和Button

盘点实际已接入根视图及可达流程，区分未接入包。记录组件树、图片/图集、字体、状态控制器、属性联动、动画/序列帧、遮罩、按钮反馈、声音、3D叠层、动态数字和输入通道。旧Presenter若仍暴露GComponent等类型，就只是适配起点，不代表业务与框架已解耦。

采用项目所需特性的有限、一次性转换器：常见布局/图像自动生成原生基础资源，复杂状态/动画显式映射；未支持项报错或进入清单，不静默丢失。转换器在工程外或一次性 Editor 目录运行，产出后生产不依赖它。不要先做通用万能转换器，也不要把旧框架完整仿写一遍再称为原生维护：源 Widget、Label 度量、Mask 命中、Button 过渡等应烘焙为 RectTransform 锚点、TMP 参数、Mask/RectMask2D 与 Selectable 配置，见 Cocos 映射（`grea-native-port` 技能《Unity源引擎映射-Cocos》）。

## 必须单独核对的契约

| 方面 | 核对重点 |
| --- | --- |
| 布局 | 坐标原点、父级缩放、锚点/pivot及pivotAsAnchor、尺寸关系、屏幕适配、绘制顺序 |
| 图片 | 图集旋转、trim、透明边距、九宫格、fill、对齐、灰态；空Loader应不显示而非白块 |
| 动态加载 | 赋纹理前后autoSize、原图尺寸、父子位置、min/max约束及保持中心；不能仅测空Loader默认值 |
| 状态 | 每个控制器页面、相关属性补丁、显示/禁用/触摸、状态切换引发的图片和尺寸变化 |
| 字体 | 位图字形UV、advance、基线、行高、缩放/描边；系统字体回退和跨平台差异 |
| 按钮 | 真实按下/抬起、缩放/染色、声音、重复点击、关闭期间释放，不只绑定onClick |
| 动画 | 原始起止值、缓动、时钟、自动播放、循环、序列帧延迟、完成回调、中断/重入清理 |
| 遮罩与3D | 反向圆形遮罩不等同矩形Mask；原3D背景与UI占位层的遮挡顺序 |
| 输入 | 唯一边沿来源、按下目标、拖动结束不误触、窗口外释放、失焦及模态遮挡 |
| 性能/资源 | 动态数字与静态HUD合理分Canvas；图集真实打包；材质、动态Sprite、Font、预览纹理的生命周期 |

不要把TMP默认字形或任意新字体当作原位图字体等价替代。选择文本组件要能解释字形/性能/平台边界；仅有字符可见还不证明排版相同。

## 分层验证

1. 用一个同时暴露布局、字体、状态和输入问题的代表视图验证路线，未通过前不批量宣称迁移完成。
2. 默认属性之外逐个状态页差分；组合状态和相关控制器另测，单页枚举不能证明所有组合正确。
3. 增加运行时赋值、打开/关闭/重入、暂停、换分辨率等动态检查。文件生成或默认属性一致不能覆盖加载后尺寸改变。
4. 在实际Player打开截图、查看动画关键帧和录像；真实OS输入与内部事件注入分别标注。测试先暴露旧效果差异，再修复，不改预期来迎合新实现。
5. 与旧SDK行为仍有疑点时，在隔离工程建立最小原实现oracle，精确记录输入与对象值；不要仅凭截图猜尺寸，也不把旧SDK重新加回生产作为兜底。

静态状态页通过仍可能遗漏 Loader 运行时 autoSize 与保持中心的行为；通过隔离原实现核对动态赋值。案例来源见 历史记录（外部历史资料）（`grea-native-port` 技能《维护与发布》）。

## 可维护交付

转换期可以把转换器生成的基础资产与人工修改分开；交付时每个界面只有一个原生 Prefab 作为真源，在 Inspector 修改后进入 Play 即生效，没有 Capture、回写或运行时重放源对象图。每个界面由按语义命名的 View 组件以 `[SerializeField]` 引用控件，事件在 View 中绑定 `onClick` 等原生回调；业务层通过明确的状态快照/操作请求与视图通信。运行时只加载原生资源；原包标识和源节点到目标节点的映射只保存在 Analysis，不以组件、uuid 字段或源脚本名留在 Prefab 与代码中。完整门槛见 [原生转换规范](Unity原生转换规范.md)。

将图标/字体的物理路径与业务逻辑key分开。转换生成的hash文件名只适合作为中间去重标识；最终命名由组件用途、状态和图像内容决定，保留映射表。原生可编辑资源必须可在Editor打开并回读，不能只是把.bin改扩展名。

## 退出旧框架

迁移回归与依赖检查完成后，在项目内Assets/Packages之外保存旧SDK、发布包、相关.meta、许可证、历史适配/转换代码及清单。检查源码、程序集、Catalog、场景、Editor生成器、QA和构建入口；生产不应通过反射或字符串继续启动旧UI。

归档包含恢复基线与方式、逐文件SHA-256、原路径/GUID及排除的系统缓存。有用的原纹理、字体图集和音频继续留在活动资源中。归档不等于完成全部平台或原版验收；跨平台差异和未观察分支保留在当前记录。
