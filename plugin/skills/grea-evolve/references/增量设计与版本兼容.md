# 增量设计与版本兼容

按[生命周期合同](生命周期与变更合同.md)选择本期模式。feature先给玩家可见的新行为和旧不变量；tuning给具体目标、测量条件与允许维度，不能把主观更好玩写成确定收益；prototype隔离工程/存档，只验证一个问题与留弃标准，复用现成正确能力，不默认全灰盒/强制重写。类型、关卡、UI/输入/音画参考只按本任务加载，不自动加原版没有的“must-have”。原版本来有的顿帧/震动/反馈应按证据恢复，新增节奏或动画事件时点须在批准范围。

规则、交互、资源按完整模块集成：核心动词、学习和反馈、失败/取消、结算/成长、返回/续玩均说明影响范围。UI按同状态/视口看可读性、层级、输入命中与遮罩；输入/音画反馈改变规则可见时点时一起回归，而非只看截图或追求表现。局部范围不重建整套设计/测试矩阵。

配置内容hash、save schema、服务协议与服务端数据库版本分别管理。新增字段的默认值、字段删除/单位/ID/枚举迁移均需业务依据，不能只凭JSON形状判安全。未知新档版本拒绝写入或降级；保留旧档、pending和回执幂等身份。客户端备份只恢复本地权威数据，不回滚已确认的服务端资产；后者沿MySQL事务和权威回读处理。

`compatibility_plan`只读显式合同/样例并生成新目录候选；现阶段仅顶层字段类型及声明默认值添加，嵌套/单位等仍需人工合同。配置hash单独变化不让所有旧档失效；保留普通存档不覆写。实际迁移仍需隔离副本、备份/中断恢复及关闭重开结果，不能把候选当迁移已验。

按可玩增量给版本：源码/设计与配置身份、实际入口、构建或候选、旧档/协议边界、原不变量与新行为结果、未验平台。构建/单测成功不等于可玩；不因参考列出Steam/手柄/灰盒就默认这些目标。工具说明见[兼容与只读预览](shared/lifecycle-analysis.md)。
