# 生命周期与有界变更合同

阶段与模式分别选择；不要求所有任务走完全生命周期。plan_workflow/init_case/start_case_revision增量接受lifecycle_stage（research/recover/reskin/develop/iterate/release/operate）、work_mode（faithful/reskin/feature/tuning/prototype/operate）、delivery_level。源引擎不决定目标，旧省略目标仍是Unity；未支持目标拒绝，不默认其他引擎。阶段、设计approved或user_source只是调用者声明，不授予发布/安装/生产写入权限。

恢复保持faithful，对比原版规则/事件/随机/结算和档案语义。reskin对比批准美术并保持约定不变量；feature对比旧不变量＋批准增量；tuning对比明确指标和允许变化；prototype在隔离工程/存档提出一个问题和可观察留弃标准。类型食谱是候选设计项，不能给忠实恢复添加原版没有的“必备玩法”。operate首先读取授权数据和输出候选，不默认发奖/支付/公告或线上配置生效。

change-contract显式区分v1与v2，未知版本拒绝。v1 ui_ux继续原有限视觉规则与隔离身份；v2声明scope、基线文件SHA、产品/存档身份、设计文件、objective、user_source、allowed_changes、invariants、verification及compatibility（config/save/protocol/pending）。feature/tuning可在保持存档合同下迭代同产品；reskin/prototype需不同产品/存档身份，prototype另有experiment.question与keep_discard_criteria。config内容hash不等于save schema版本，不能用hash变化一律拒绝旧档；保护pending/幂等信息，服务端资产不能用旧客户端快照覆盖。工具只校验声明与文件身份，不执行迁移。

现有evolve可使用v1 UI/UE或显式work_mode绑定v2；feature/tuning/prototype必须在Case中绑定相应合同。规划可以先留合同缺口，不把规划当执行。真实输入、视觉、引擎和规则证据仍分层。

monkey_bridge使用显式固定版本provider，串接具名来源、包级或显式切片候选与原始任务索引，按完整模块聚合AI包，不按每条脚本/诊断启动Agent。底层needs_action/partial/failed原样保留；文件齐全或exit0不证明原生完成。切片native resume仅在provider实际验证和文件身份回查后记录Editor结果，仍不代表Player/输入/业务通过。依赖或导入需修复时，保留原候选，在隔离adopted工程记录差异，不伪造provider原件通过；GREA自定义接续模块不能标成自动翻译的源业务。真实键盘UI和鼠标点击分别记录，自动坐标异常不能靠改写业务事件或直接调用Button.onClick冒充。方法和当前支持边界见monkey接入（项目文档 `docs/providers/monkey.md`）。

`compatibility_plan`现可分析声明的顶层字段、默认值与config/save/protocol/pending差异；不解析未知业务单位或自动升级普通档。`operations_preview`仅本地事件漏斗/首观测D1、经济流及配置候选，见数据与预览工具（项目文档 `docs/providers/lifecycle-analysis.md`）；未接生产或发行渠道。
