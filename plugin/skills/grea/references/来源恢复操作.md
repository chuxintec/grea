# 来源恢复操作

按源包证据选择模块，不执行原始客户端程序来填补缺失行为。先固定版本、源文件路径/哈希、目标 Unity 版本和预期范围。

| 目的 | 入口 |
|---|---|
| 枚举容器、建立源清单、转换 | `grea source inspect`、`grea source index-unity`、`grea source convert` |
| 依据请求恢复、验证并固定 Prefab | `grea prefab recover`、`grea prefab verify`、`grea prefab freeze` |
| 检查现有候选的 Shader 证据 | `grea asset classify-unity-shaders` |
| 盘点方法、固定原宿主、应用有依据的代码 | `grea code inventory-unity-methods`、`grea prefab prepare-hosts`、`grea code apply-unity-method-overlay` |
| 产生代码候选与执行探针 | `grea code unity-code-candidate`、`grea code wasm-code-candidate`、`grea code native-probe` |

新的开发工程以 Unity 为目标。已有 Creator 模板和基本对象转换可分别通过 `grea project cocos-project` 和 `grea source cocos-convert` 查询；这两项保留既有候选的兼容处理范围与原生验证状态。

## Prefab 路径

`grea prefab recover` 要求请求文件、其预期哈希和新输出目录。`grea prefab verify` 要求候选、预期清单哈希、Editor 路径和新输出；`grea prefab freeze` 绑定实际原生输出与执行身份。资源地址与源对象分开计数，共享依赖去重；无地址子对象、运行时创建物和无法进入原生静态候选的部分各自保留。

## 源码与 Shader

元数据声明、可定位的二进制方法体、可编译 C# 和行为验证各自建账。挂载回原节点需要组件身份和序列化引用。Shader 分类需要已冻结工程、清单和预期哈希；分类与实际编译、画面及运行时间序列分别验证。

每个命令的全部字段、可选格式和互斥条件可在[参数索引](功能模块和命令参数.md)查询。仅使用工具明确支持的来源/目标组合。

## 已导出 Prefab 的成组复验

使用 `grea prefab verify-static-set` 在独立副本中保存、冷读和强制重导。用 `--project` 指定可信 Unity 6 工程，`--selection` 指定 UTF-8 JSONL，`--expected-selection` 固定其 SHA-256。每行需要 assetPath、guid、sha256、sourceNodes，可用 source 记录源地址，用 capture 选择 ui、model 或 effect 抽查。指定同版 Editor 和全新输出目录。逐根结果在 results.jsonl，单色截图和运行时内容单独复核。该操作只验证候选副本。
