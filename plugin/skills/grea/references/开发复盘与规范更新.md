# 开发复盘与规范更新

在用户要求更新规范，或实际返工暴露共用缺陷且本轮获准修订时使用。出口是原主题规则的有据修订、调用方同步和验证记录；不把聊天、项目进度或一次成功变成通用要求。

## 核对与归属

1. 读当前入口、主题参考和调用方，确认是否已有等价规则。
2. 以代码/资源、失败与修复证据核对反馈；区分用户要求、观察、因果假设与未知。多项同时变化后通过，不能归因于其中一项。
3. 选择唯一维护位置：

| 内容 | 位置与处理 |
| --- | --- |
| 改变选路的稳定原则 | Skill 入口短规则 |
| 条件性方法或工具合同 | 已有主题参考，写适用条件、输入、处理、出口与限制 |
| 通用执行缺口 | 按[脚本晋升](项目脚本沉淀与工具晋升.md)交 monkey/beaver；GREA保留方法和薄调用 |
| 游戏参数、GUID、账号、状态、原始日志 | 留项目，不复制进通用 Skill |
| 未验证假设或未来能力 | 留项目待验项或维护仓库提案；不作为执行门槛 |

候选经验可用“触发→现象→证据/原因与置信度→修复→验证→不适用情况”记录。已有能力的未验产物仍是候选；文档更新本身不能提升工具、原生或业务验收状态。

## 历史经验检索

当前执行以技能和项目最新证据为准。需要解释旧返工时，在已配置且获准的记忆服务按主题检索相关原文，核来源身份、日期、适用条件及未验项。摘要只是索引；无结果不证明没有历史，缺来源不阻断无依赖工作。旧版本和项目状态不直接升级为当前事实。

## 有意义内容进入 memory 的流程

仅在当前授权允许保存时，通过指定记忆技能去重、提交并回读；不因本页自动写记忆。保存最小事实/经验及来源，区分排队、存档核验和整理发布；结果不明沿原请求查证，不换ID重发。技能是流程权威，记忆不另存竞争规范，不创建本地记忆副本。

## 修改与验证

- 修原条目而非末尾叠加相反规则；同义内容合并到唯一权威主题，其余用链接。短但有独立触发条件的说明可以保留。
- 删除或改名先查路径、锚点、工作流引用与兼容接口；来源和历史回执不追改。技能更新不扩大安装、外发、发布或全局配置权限。
- 验证五入口、引用/资源闭包及按需路由；涉及工具时只跑受影响合同和失败边界，不能用关键字计数证明Agent理解。
- 较大结构变更在隔离安装集合中用真实任务前向走查；获得授权且有必要时使用独立评审。行为评估不能偷偷执行游戏、联网安装或付费调用。
- 交付说明列变更、合并去向、已运行检查和未验范围；实现、安装、客户端加载与发布分别记录。
