# 流程 · 游戏恢复开发

工具推荐：先用unity_asset_ledger建立身份台账，再使用Unity CLI/Pipeline接入；规则用compare_events，显示用RecoveryRuntimeAudit.cs（Editor C#）。 入口和限制见 [工具清单](工具选择与调用.md)。

适用于 Unity 原工程恢复和跨引擎复刻。顺序按用户要求执行，阶段结论以实际可见流程为准。

## 先交全量初版，再接续业务

按[全量初版工程与协作](全量初版工程与协作.md)先冻结来源，再由固定monkey批量导出独立原生初版，GREA核真实交接后游戏Agent接续。以下代表闭环与逐系统业务阶段均发生在全量初版交接之后，不以单个Prefab小样替代全集导出；格式转换缺口归monkey维护，不在GREA另造转换器。

## 完整恢复的交付模块

完整恢复/首次重建维护以下四项；局部修复、换皮、重构、性能和交付只更新本次涉及部分，不补做整套恢复。

1. **原生内容证据包**：本期功能覆盖表、原包/运行时资源版本、逐项操作录像/截图、界面/玩法/动画说明及受限分支。获取与重跑见 [取证](../../grea-evidence/references/原版运行与内容取证.md)。
2. **完整资源恢复包**：尽可能全面提取 Prefab/场景、Sprite/纹理、Spine、音频、Shader/材质、模型、配置、SO、元数据与可恢复代码；按类别维护身份、依赖及失败/缺失清单，见 [提取](../../grea-evidence/references/提取与引用恢复.md)。
3. **原版优先的工作工程**：原始证据只读，工作副本保留原资源/代码映射，补充实现注明依据及差异，见 [重建](../../grea-unity-recovery/references/Unity工程重建与恢复.md)。
4. **迭代验收记录**：以下阶段先接通代表闭环再扩展；复用未变化证据，新增结果或替代失效结论。结果维度见 [验收](测试与结果交付.md)。

## 原版优先

先查提取清单和原版引用，再决定实现：原 Prefab/场景及层级 → 原资源和组件关系 → 原代码、配置和调用链 → 必要的兼容修复与缺失逻辑。禁止先自制替代品，再用原图包装成还原版本。用户明确授权换皮时，美术按 [批准页图制作流程](../../grea-reskin/references/游戏换皮与资源制作.md) 执行，保留该请求指定的玩法和 UE。

源游戏本身是 Unity 时，目标工程优先使用原 Prefab 工作副本，修复脚本和资源引用，保留 Transform、序列化 ID、动画曲线和依赖。

源游戏是 Cocos、Laya/FairyGUI、Egret 或 H5 等其他引擎时，属于跨引擎重建，不是找回原作者 Unity 工程。目标是纯原生 Unity 工程：以原资源、对象树和代码为依据，经固定monkey一次性批量生成原生 Prefab、Scene、AnimationClip 与 ScriptableObject，运行时只使用 Unity 机制和官方/主流插件。源对象到目标资产的对应表保存在 Analysis，不进入生产工程。规则语义与引擎语义的分界、禁止项和验收门见 [原生转换规范](../../grea-native-port/references/Unity原生转换规范.md)；专项契约见 [跨引擎恢复](../../grea-native-port/references/Unity跨引擎移植与行为一致性.md)。

代码区分可编译的原托管逻辑、IL2CPP 伪代码转写、元数据空壳和新增适配。转写检查分支、字段、调用时机及状态写入语义；例如任务可见条件与余额可执行条件分开，更新已有记录与创建记录不可混同。推断与修补独立标注，不把反编译器输出直接当可靠源代码。

## 第一阶段：Prefab、挑战逻辑、基础显示

- 恢复原场景/Prefab、Camera/Canvas、资源引用、任务/关卡对象身份和基础渲染。
- 从原代码恢复挑战规则、生成/随机、胜负、任务前置、消耗奖励和持久化；先核对完整相关调用链，再进行数值对照，不靠视觉近似反推规则。
- 恢复状态到画面的绑定、页面入口、任务列表、HUD、按钮可用性、弹窗排序、输入锁及重入。
- 完成一个实际入口到结果的代表闭环后再扩展。门槛是主要对象真实可见、规则有依据、入口可操作、状态与保存一致；表达组关系的连线、按钮声音/按下反馈、消除完成动画应随闭环接入。缺纹理或占位 Shader 导致空白不能留到“美化阶段”。

## 第二阶段：细节显示

对照同状态原生证据校正锚点、pivot/PPU、图集尺寸、字体、描边、遮罩、层次、裁切、屏幕适配及交互反馈。验证动态更新与重载后画面，不能只看编辑器静态预览。

## 第三阶段：特效与完整动态体验

接入原 Spine、Animator/Clip、粒子、Shader 效果和音效，恢复事件、阶段重叠、命中、跳过与清理。原动画本身承载状态完成回调或基础可见内容时，应在第一阶段恢复必要控制链，最后补齐表现；不能为遵守阶段顺序用固定延迟替代业务完成条件。

动画从真实引用选择，不默认取动画列表第一项。完成以原回调或已核对的状态/轨道为依据；看门狗超时必须报告失败或未完成，不能转为成功。最终检查整个时段，单张固定延迟截图不能证明移动角色从未出现。

## 阶段与重跑

每阶段维护“原版依据 → 工作资源/代码 → 实际入口 → 运行证据 → 差异”。阶段预览标明未补的效果，不等于完整验收。修复发现会推翻上一阶段的资源/规则错误时回到对应阶段，记录根因并重测受影响流程；没有新依据不反复调同一组参数。
