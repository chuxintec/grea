# 验收 · 测试与结果交付

工具推荐：Unity构建/测试、真实输入、video_manifest、verify_payload_tree；性能问题使用Profiler而非只计平均帧率。 入口和限制见 [工具清单](工具选择与调用.md)。

## 单一验收入口

阶段计划记录推进状态，验收记录保存测试结论和证据，两者通过链接关联；状态更新时机和完成判据见 [开发计划与状态维护](开发计划与进度管理.md)。

在实际项目已有报告中维护，或创建一个范围清晰的验收文件。不要并行维护互相矛盾的完成结论。可采用：

| 验收项/场景 | 模式与比较基线 | 实现入口/里程碑 | 必需验证维度及结果 | 证据与剩余差异 |
| --- | --- | --- | --- | --- |
| 受影响操作及预期 | 原版/批准设计/重构前行为等 | 模块路径；适用时记已提取/已实现/已接入 | 每维度：通过、失败、未运行或不适用 | 步骤、输入方式、代码/构建身份、报告链接 |

提取/实现/接入只记录实现里程碑；“已验收”表示本任务全部必需维度通过，不代表游戏整体完成。工作进度另按开发计划与进度管理维护，不能用最远里程碑掩盖失败维度。

按任务选择规则、真实运行、原版/批准设计体验、身份/迁移、性能和目标平台等维度；不适用须写范围依据。局部修复无需新建全部维度，不能用不适用移除已承诺的检查。仅在性能任务或有具体性能风险时读 [性能对照](../../grea-unity-standard/references/Unity性能分析与优化验证.md)。

例如某局部修复已接入，规则与 Mac 输入通过，但本期要求的原版视觉未运行，则进度是待验收；未要求 Windows 时写不适用（不在本期目标），已承诺 Windows 时必须写未运行并保留待办。缺证据与范围外不能混用。

每项维护一条当前结论，历史过程作为证据链接保留。新发现推翻旧结论时，在当前条目写明被替代结论及替代依据；不要只向长日志追加“已修复”，让旧的“未修复”或“已一致”继续充当状态入口。

证据摘要写清测试数据与输入方式。例如：合法鼠标操作连续通关、注入单一道具后点击、仅引擎模拟、原版真实通关。专项夹具能验证某个缺陷，不能证明自然生成、完整关卡或全套组合道具合格。

## 运行验收

分别记录以下三类结果，不汇总成一个含糊的“通过”：

| 类别 | 能证明的内容 | 不能替代的内容 |
| --- | --- | --- |
| 规则验证 | 数值、状态条件、资源消耗、奖励幂等 | 实际入口和原版体验 |
| 运行验证 | 真实输入、跳转、加载、关闭和恢复 | 原版顺序、节奏及美术一致性 |
| 体验对照 | 模式对应基线：原版或批准设计；可比状态的阶段、耗时、动作、图像与声音 | 未观察分支、不同状态；换皮美术通过不等于原版美术一致 |

测试预期应有原版证据或明确的软件正确性依据，不能从当前实现复制预期值再证明自身正确。出现用户实玩反馈与测试结论冲突时，回查测试覆盖和证据边界，不用测试数量否定反馈。

- 使用独立 QA 存储命名空间或明确的测试存档备份/恢复，不覆盖正常玩家存档。
- 在资源加载完成后截图；按 [固定对照条件](../../grea-parity/references/开发前检查与迭代.md#7-固定对照条件并保留决策依据) 核验可比状态。布局、动态状态、交互反馈分别判断。
- 动画关键阶段以实际事件时间或录像帧为依据；工具等待 200ms 后请求截图不保证获得动画第 200ms 帧。
- 按当前游戏和影响范围检查输入边界与业务状态；三消涉及无效交换、连锁/掉落及解锁时须覆盖，不给其他玩法强加不存在的分支。
- 结算检查实际存在的奖励来源、一次性入账、退出/重进恢复及下一流程；余步转换只在原版有该机制时验证。
- 渲染库 API、素材加载和生命周期必须在实际页面执行；资产解析测试不能代替运行集成。
- 自动测试按规则和风险选择。构建、控制台无错误、视觉对照和交互验收分别报告，不相互替代。

### 原生可维护性（跨引擎转换）

源游戏不是 Unity、任务是清理源引擎残留，或明确要求原生可维护Unity但实际仍为WebView/WASM宿主时，在上表三类之外单独记录"原生可维护"维度。每项写通过、失败、未运行或不适用，并附证据：

| 检查项 | 通过条件 | 证据 |
| --- | --- | --- |
| 守卫 | 禁止项 Validator 或 EditMode 测试零违规，或只剩登记过的白名单且没有新增 | 扫描范围、白名单条数、运行日志 |
| 原生制作可生效 | 人工制作的 UI/Scene/动画或 SO-authoring 配置修改后直接 Play；外部配置制作源按锁定 Schema 单向候选/导入，生成物不成为第二真源；不依赖 Capture 或源图重放 | 制作源/所有权、修改项、直接运行与回读 |
| 生产依赖已退出 | 实际生产程序集/序列化引用不再依赖完整源节点图、来源身份绑定、源生命周期或任意行 JSON 解释；合法 DTO、GUID、Spine 数据和普通 Prefab Variant 不按关键词误禁 | 静态候选、Editor 实际对象/依赖、实际 Player 元数据分别记录；零关键词命中不颁发通过 |
| 许可证 | 生产工程没有源引擎运行时源码或带源引擎许可证的文件；第三方包已登记许可证 | 见 [许可证与再分发](../../grea-delivery/references/许可证与再分发.md) |
| 转换器可移除 | 转换器目录删除后仍能编译和构建 | 隔离副本的编译日志 |

这一维度用上述检查证明，规则测试、截图或构建成功各自只证明自己的维度。各技能在本维度上的职责：`grea-native-port` 建立守卫并负责通过；`grea-parity`、`grea-reskin`、`grea-unity-standard` 的修改保持守卫不新增违规；`grea-delivery` 在构建前运行守卫并在交付说明中单列结果；`grea-evidence` 把源 uuid 与映射表留在 Analysis；源游戏是 Unity 的 `grea-unity-recovery` 任务记为不适用并写明依据。条件与禁止项见 [原生转换规范](../../grea-native-port/references/Unity原生转换规范.md#验收三门)。

### 入口与证据对应

针对本轮修改选择真实触发路径：新账号普通启动、已有存档重进、资源不足后的下一步、设置首次切换，或结算事件到奖励动画。隔离存档不等于绕过产品入口；测试若直接调用模块，应另列为专项夹具。

报告中将每项结论对应到实际检查：截图中的资源和位置、操作后的页面与数值、设置读回、控制台及异步完成情况。不要先写“已验收”再执行检查，也不要因 对象状态标记存在、等待时间到了或测试数量增加就推断视觉通过。

### 深层 QA 与普通构建

需要人工进度才能访问的深层分支，可用明确启用、隔离存储的 QA 夹具；记录状态来源、初始化条件与标记，重开不得重复赠送。通过原数据接口构造状态时仍检查其约束，不将预置进度算作自然解锁。QA 入口仅在明确测试环境开放，普通交付默认不触发。

高级档容易绕开教程、资源不足和解锁条件。交付普通玩家构建时，用隔离空档及已有档验证本次涉及的首启、持久化和重开；深层 QA 与普通构建分别关联 buildId/profile。开发包中的成功或录屏不能直接转为另一个普通包的验收结果。

### 已批准离线范围的失败路径

已知服务依赖时尽早核对本期交付范围，沿用已有授权。按“保留入口、明确不可用”交付的服务，应在平台边界返回可见失败，避免继续初始化依赖 SDK 的面板。检查提示、按原失败规则不扣除应保留的次数/资源、不发放成功奖励，以及失败后能继续操作；本地奖励与游戏内资源消费按原逻辑保留。

异步调用还需覆盖调用方忽略返回值的情形，处理未消费的拒绝且保留失败语义。检查应针对具体外部服务和对应状态，不能把正常本地提示弹窗一律当成 SDK 面板错误。用户另行批准的离线替代奖励属于产品适配，单列依据与验收，不计为真实服务成功。

### 公共组件回归

多个页面出现同类偏移、遮挡、裁切或配色错误时，先检查共用坐标映射、文字渲染、遮罩和层叠上下文，避免逐页叠加位置补丁。

修改前定位所有调用入口；修改后对全部受影响入口做基本检查，并选择长短标题、不同内容高度、屏幕比例、选中/未选中状态及关闭重入等边界做深入对照。不要把一个代表页面的截图当成所有调用方通过。修复范围超出本轮已检查范围时，在当前验收条目列出未检查入口。

### 区分逻辑缺陷、视觉误读与检查工具滞后

- 对“整行没消除”一类反馈，记录命中索引、伤害/清除事件及回填前后状态，并观察动画。迅速补入新元素可能掩盖清除；也不能仅凭引擎生成了整行索引就认定玩家看到的表现正确。
- 可访问性快照可能滞后。操作超时或结果页看似未出现时，核对当前截图、实际对象可见性和遮挡层，再判断是产品缺陷还是检查工具状态问题；不要强制点击穿透遮罩制造通过证据。
- 自动点击/拖动无效时，先核对实际构建路径、窗口、焦点与 Down/Up/Cancel 是否送达，再沿事件链定位。锁屏/后台/虚拟光标能力依当前工具契约及实测，不写成固定可用或不可用。保留同场景手动和自动结果；手动成功不等于自动输入通过。多人操作时固定操作者与起点；独立静态工作不被缺失输入能力阻塞。
- 数值采样区分“函数被调用”“通过收集门控”“实际余额变化”。单次实机结算值不应硬编码为关卡奖励，也不能把所有调用简单相加。
- 新模块须在当前 Unity Player 的实际场景/入口加载一次，核对动态资源、控制台和关闭重入；孤立夹具与构建成功不能替代。旧网页静态复制构建只能作为历史来源，不能计为当前 Unity 集成检查。

## 多 Agent：仅在已授权且有独立工作时使用

本 Skill 不要求或自动授权启动子 Agent。尊重当前会话是否允许委派、指定模型及并发限制。短小或强依赖任务本地完成。

适合并行时可按原版验证、关卡体验、外围系统分工，不固定数量。一个模拟器只由一个执行者负责输入；不同 Agent 避免同时改同一文件，接口变更先交接。

交接至少包含：

- 原版依据及尚属推断的部分。
- 修改文件、接口、资源路径及集成入口。
- 已完成的实际检查和可复现证据。
- 未完成项、失败现象和下一步；不能只写“测试通过”。

主 Agent 负责集成、跨模块流程和独立画面验收。接口和积压处理采用 [跨模块契约与执行节奏](../../grea-parity/references/开发前检查与迭代.md#5-跨模块契约先约定)。调整分工在安全节点交接，不丢弃未完成修改。

## 收口与范围变化

用户缩小范围时保留后续成果，但从本期必验清单移出；重新估算完成度，说明范围变化影响。纠正旧结论时记录撤回项和替代证据，避免旧报告被当作最新事实。

最终交付以实际观察为准：哪些流程已走通、哪些效果已比较、哪些只是适配或待验证。缺少关键验证时明确未完成，继续处理范围内可完成的工作，不以“全部一致”概括。

## 用户要求先看当前效果时

停止新增调查、功能扩展和下一轮重建，让进行中的写入到安全节点保存；通知已运行的协作者收尾。仅完成当前改动必要的集成和启动/入口检查，不把修完全部视觉差异作为停下前提。

提供可访问的最新预览、最短查看路径、隔离测试存档说明，以及已可体验流程和具体未验收项。保留未接入模块、导出数据和证据，明确阶段预览不等于全部还原通过。交付后等待反馈，不自动继续扩大工作。

## Unity 恢复专项验收

- 资源完整性、规则、真实输入、视觉和跨进程存档分别给出结论。Prefab 激活、计数正确和截图已生成都不能证明建筑/角色/文字真实可见；打开关键帧检查遮挡、空纹理、材质和表现。
- 动画至少检查开始、中段、结束与中断，使用实际轨道/状态/回调判定完成。禁止用无原版依据的“等待 N 秒后算完成”替代回调，或吞掉看门狗失败；夹具先核对 Play Mode、timeScale、加载就绪及原状态前提，错误夹具不能驱动生产规则修改。
- 同进程重新加载存档与独立 Player 退出重开分别标记；预置星星/进度只验证外围专项流程，不代表自然通关获得资源的完整链路。
- 建造或领取必须检查重复输入、动画中断、保存失败和重启后的状态一致性；保存失败不能留下已扣资源但未落盘的半提交状态。
- 本期必需的原版或批准设计比较失败时，即使规则测试全部 PASS，该项验收仍为未通过。将测试遗漏转成有实际断言和画面证据的检查，不只新增报告标签。

历史失败案例见 [来源记录（外部历史资料）](维护与发布.md)，不携带其当时项目状态作为当前结论。

## 短动画与帧率前提

- 先记录焦点/遮挡/后台状态、timeScale、实际deltaTime和采样时钟。短动画若比后台帧间隔还短，可能根本采不到中间帧；不能据此立即修改生产曲线，也不能仅靠降低测试标准判通过。
- 需要持续渲染的夹具可显式启用后台运行，并记录它是QA条件；不要顺便改变正常版本的后台策略。前台实玩与夹具结果分列。
- 测试同时检查资源引用、真实粒子或网格活动、中间状态、终态及中断清理。仅AudioSource.isPlaying不证明可听效果；仅内部旋转断言不证明真实输入延迟。

## 跨平台构建与单文件交付

构建、包体完整性和目标系统启动/输入/声音是不同证据。封装执行契约统一见 [单文件交付](../../grea-delivery/references/游戏构建与版本发布.md#单文件交付与运行身份)；此处保留旧锚点供既有引用导航。

## 连续输入与制品身份补充

- 连点回归记录接受/拒绝时间、动画阶段、状态变化及终态。至少覆盖拒绝反馈重播、其他合法对象在整理中被选、同对象重复点、联动组预约中再点；“最后都到槽”不能证明输入期间没有吞点。
- 每条运行证据绑定实际制品身份，核对方式见 [运行身份](../../grea-delivery/references/游戏构建与版本发布.md#单文件交付与运行身份)；源码已修改但未构建的包不能作为修复后的证据。
- 交叉构建无法执行目标系统时，交付明确待验，不将原生窗口钩子升级为已验证通用工具；目标显示检查见 [桌面窗口与显示验收](../../grea-delivery/references/Unity桌面窗口与显示适配.md)。

## 目录重构后的 App 冒烟

围绕受影响资源运行：普通启动→首页→关卡→代表上架/采集→暂停/继续→返回，另按改动范围覆盖胜负、道具、关闭重开。绑定本次构建与日志，记录截图实际状态和输入来源；焦点、后台帧率或同名旧进程先排除。纯目录调整不默认扩展为全关通关；基本冒烟也不覆盖全部机制、音频一致性或目标平台。

## 元素类型审计与代表关卡

- 几何玩法以元素类型×操作×状态组织覆盖：普通/复合物件、附属部件、固定件、接触触发件；移动/碰撞/消除；受锁、暂停、已移除、最后连接、重入及批量触发。先从源配置确认实际存在的类型，不把不存在的枚举分支计为已覆盖。
- 全量入口审计检查身份/引用、轴向、有限且不超请求的位移、只读探测无状态变化、已移除与暂停守卫、活动关系下不得清除。候选须按对象及首个分歧回到原规则确认，合法缺省值不能为追求零告警改成错误约束。
- 真实输入选择能代表共享逻辑的关卡，记录完整路线、受阻退让、移除集合、分数和道具库存；前缀路线不等于整关通关，使用道具解障不等于无道具通关。夹具种入关卡入口、自然完成关卡和原版同轨迹比较分列。规模很大的PASS不能替代后两项。

缺陷复现先把进程真实路径与已验收payload对应；安装包身份正确不替代真实输入验收。Mac反复请求文稿访问时检查运行位置、工作目录、日志/存档/QA通道，采用应用用户数据目录，不通过清档或关闭系统保护解决。

## 候选版本与验收适用范围

新 Case 使用 `start_case_revision` 冻结明确的候选文件/目录及可选构建清单。证据引用该 revision；运行证据另记实际 run_instance，平台结论绑定 buildId/manifest、平台与 QA profile。候选、原来源或包发生变化时旧结论失效，开启新 revision，历史记录保持不变。v1 Case 可读，但没有候选绑定的旧声明不作为当前版本验收。只读取证/评估采用身份门，不要求实现游戏。

调用方声明来源角色和 run_instance 不等于工具真的观察了游戏；证据路径、哈希、采样方法与具体结果仍需审阅。追加证据只校验新文件；case_status 明确回读当前 revision 和相关证据，不能声称已复核所有历史媒体。
