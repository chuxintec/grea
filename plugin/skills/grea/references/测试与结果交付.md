# 测试与结果交付

用于确定本次修改的验证范围并交付可复查结论。计划写推进状态，本页规定证据含义；沿用项目一份当前验收记录，历史原件不覆盖。工具选择见[调用表](工具选择与调用.md)。

## 单一验收入口

每项写清：任务与比较基线、代码/候选/构建身份、实际入口与输入方式、结果、证据、剩余项。各维度用“通过、失败、未运行、不适用”，不适用须有范围理由。提取、实现、接入不是验收；仅本期必需维度全部通过才关闭该项。成功按本次目标及其适用的产物、采用或运行结果判断；报告数、测试数、`completed` 或 static pass 只说明各自范围，不外推。

| 维度 | 证明什么 | 不能代替 |
| --- | --- | --- |
| 规则 | 数值、条件、消耗、奖励幂等、状态与持久化语义 | 正常入口、玩家可操作性 |
| 运行 | 真实入口、加载、输入、关闭重入、退出重开 | 原版或批准设计一致性 |
| 体验 | 可比状态的布局、画面、节奏、声音与反馈 | 未观察分支、另一平台或另一版本 |
| 身份/迁移 | 输入、文件、引用和制作源对应 | Editor类型、动态加载或业务正确 |
| 性能 | 固定负载和设备的受控比较 | 不同画质、随机、限帧条件下的收益 |
| 目标平台 | 实际目标制品运行与平台功能 | 交叉构建、解包校验或宿主平台结果 |

预期取自原版证据、批准设计或独立正确性依据，不从待测实现复制。用户实玩与测试冲突时追首个分歧，不用PASS数量否定反馈。旧结论被推翻就在当前条目更新并指向替代证据；缺证据不写成不存在功能。

## 运行验收

- 根据diff和依赖选实际受影响入口。共有组件先清点全部调用方，再检查基本流程与代表性边界；未检查入口明确列出。
- 使用独立测试身份加隔离数据，或明确备份/恢复方案；真实玩家档不动。普通首启、旧档续玩、同进程加载、独立进程重开分别记录。
- 局部功能可在独立测试身份和隔离数据上预置必要前置，再经真实业务入口验收，记录预置内容与构建身份；不直接写最终结果凑通过。未改成长规则时，不为局部功能每版自然练号。预置结果不证明自然解锁、成长或通关；本次涉及成长、教程、自然解锁或明确要求综合自然玩法时，再核对应自然路径；既有未变证据按适用范围复用。
- 深层QA夹具须显式开启。直接调用业务函数、合成事件和自然操作分列；普通分发包不默认携带测试入口/存档。
- 输入路径先服从项目已明确的选择（如 Computer Use）；未明确时用本次可用且获准的路径。自研或虚拟指针只在已有明确授权范围内使用，不默认升级技术方案。手动、合成事件、桌面自动化和虚拟输入分别记录实际路径，通过结果不能互相冒充。GREA 不规定真人试玩的频率或时长；项目有约定或具体风险确需真人时再安排。
- 资源加载就绪后实际打开截图、回看录像，记录可比状态、视口与时间口径。截图文件存在、对象激活、AudioSource播放、等待时长到达均不证明看见/听见或流程结束。具体方法见[实际体验](实际体验与画面对照.md)。
- 连续输入检查接受、拒绝、预约与提交；动画检查中段、终态及中断清理。具体规则按[界面与输入](../../grea-develop/references/Unity界面还原与输入交互.md)、[动画时序](../../grea-develop/references/Unity动画特效与事件时序.md)和[规则一致性](../../grea-develop/references/规则与随机一致性.md)，不把某游戏分支强加到所有玩法。
- 外部服务按获准范围实测。明确离线失败的功能检查可见失败、不误扣次数/资源、不假发成功奖励及后续可操作性；异步拒绝必须被消费。批准的离线替代单列为产品适配，不能记成真实服务成功。

### UI修复的分层出口

功能、视觉与目标Player分别记录：功能检查绑定/状态/交互结果；视觉按[同页同状态同视口对照](实际体验与画面对照.md#开发与ui对照)实际看图；Player使用匹配源码候选和真实输入。组件测试、Button.Invoke、独立Canvas或Editor截图不能代替后两者。项目若指定看图模型，按有效约定实际查看，但模型结论不代替输入证据。

涉及可再生UI时，必须另核[唯一生成源与重复生成不回退](../../grea-develop/references/Unity脚本与生成契约.md#唯一生成源与退役)。只修当前Prefab/实例而旧入口仍可覆盖，保留未收口。每组只补受影响编译/组件/页面检查；稳定后集中构建同源候选，不为逐页小修重跑全服务测试或逐页重打包。页面修复不自动关闭该版本剩余业务、服务或新手流程缺口。

### 虚拟输入与原生输入分层

应用内虚拟设备通过不等于macOS原生输入通过；按PID发送事件且同步系统鼠标仍属于原生输入。必须记录实际backend/input mode、固定producer、companion/构建身份、进程出生与实例、虚拟设备和坐标空间，不能用工具名称推断路径。后端未就绪、不支持或身份不符显式失败，不降级到会移动系统鼠标或激活窗口的路径。

| 结果层 | 必需证据 |
| --- | --- |
| virtual-input | 命令序号与目标消费回执、真实Action/UI/玩法输入路径、点击/拖动/滚动及松开清理；按具体动作分别记录 |
| native-input | 原系统事件/窗口绑定与输入保护实际结果；虚拟测试未运行此路径时记未运行 |
| visual | 同构建/实例/状态的实际目标画面或帧及观察；消费ack或状态日志不能替代看图 |
| business | 正常产品流程、存储与服务的实际结果；输入被消费不等于经营、发奖或续档正确 |
| 用户桌面并行 | 目标失焦仍可输入，在用户自然操作其他应用的同一时段有目标处理及状态/帧证据，物理与虚拟来源隔离 |

代码路径无warp/全局事件/激活调用与动态无工具驱动的系统鼠标/焦点变化分别核验。用户自己的鼠标和焦点可以变化，不以绝对位置恒定作为通过标准；只采必要位置和前台身份，不收集无关输入内容或屏幕。没有自然并行样本时该层待验，不用自动操控无关App代替真人，也不为单项待验否定其余已验证层。

超时/断开/主动接管须核虚拟设备状态已释放、清理不触及用户物理设备；部分执行或回执未知保留已消费范围，不自动重放可能产生业务效果的输入。中性App与正式消费者分别验收，只有实际通过的对应任务解除前台输入等待，其他原生/人工项保持原状态。通道和采用规则见[工程事务操作](工程事务操作.md)。

### 原生可维护性（跨引擎转换）

仅对跨引擎转原生Unity、清理源引擎残留或明确原生维护任务增加此维度；Unity原包恢复不因此重建另一套迁移门。方法见[原生转换规范](../../grea-recover/references/Unity原生转换规范.md#验收三门)。

| 检查 | 所需证据 |
| --- | --- |
| 禁止项与例外 | 扫描范围、具体命中、经审查例外；零关键词不等于真实依赖退出 |
| 制作可生效 | 原生Prefab/Scene/Clip及正式JSON配置修改保存后，实际消费者读回；SO管理资源引用，不维护重复可编辑数值表 |
| 生产依赖退出 | Editor实际对象/依赖与Player元数据；不能依赖完整来源图、源生命周期或源引擎模拟层，合法强类型JSON/DTO不误禁 |
| 转换器可移除 | 隔离副本移除转换器后仍可编译/构建，不破坏唯一原件 |
| 来源与许可证 | 按[再分发核对](../../grea-release/references/许可证与再分发.md)保留必要声明并核分发范围 |

恢复产出候选，开发接续保持这些约束，发布按本次输入复用或补验；不因阶段切换自动升级候选为通过。

## 失效、复用与收口

证据绑定实际构建/进程和输入，源代码改了但旧包未更新不能作修复证据。仅文档或审计器变化时重验相关链接/原件，不无条件重跑游戏；运行时、资源或依赖变化则核受影响消费者，参见[证据复用](开发计划与进度管理.md#成组开发与证据复用)。

真实输入失败先核实际路径、窗口/焦点、Down/Up/Cancel与坐标链。工具快照滞后需与当前画面/对象状态交叉核对，不强制穿透遮罩制造通过。

用户先要看效果时，当前写入到安全节点保存，只完成必要集成与入口检查并交预览；列可体验路线及具体未验项，不扩展为全版修复。范围缩小则更新当前必验清单并保留范围外成果，不改写原历史结果。

## 短动画与帧率前提

焦点、后台/遮挡、timeScale、deltaTime与采样时钟会影响短动画观察；工具请求时间不是动画帧时间。采不到中间帧先查观测条件，不改生产曲线迎合夹具。QA后台渲染开关与正常产品策略分开，详细验证归[动画专题](../../grea-develop/references/Unity动画特效与事件时序.md)。

## 跨平台构建与单文件交付

制品结构、封装、签名、安装和平台运行按[构建交付](../../grea-release/references/游戏构建与版本发布.md#单文件交付与运行身份)。源码、完整payload和包体身份分别记录，不能只用可能未变的启动EXE哈希。未运行的平台保持未运行。

## 候选版本与验收适用范围

使用GREA Case时，以`start_case_revision`固定候选及可选构建清单；运行证据另记`run_instance`，平台结论绑定buildId/manifest及QA profile。候选、来源或包变化后创建新revision，旧记录不覆盖。v1可读但无候选绑定的声明不作为新版本验收。

被其他回执或索引用SHA引用的报告视为封存字节，不在原文件追加消费者结论、改pending或整理格式。新结果写独立版本化补充，记录原报告路径/SHA、补充路径/SHA、替代的状态与范围；计划或当前索引指向补充，原报告和失败原件保留。发现同名SHA漂移时，先保留新增内容，再仅从已保存原件或可精确匹配封存SHA的已知旧序列恢复；不能为凑绿改上游索引或猜原始证据，不因此重跑已验游戏。

角色、run_instance、审阅声明都不等于工具观察。`case_status`只回读当前revision及关联证据，不证明重新观看历史媒体；API细节见[接口与证据](接口调用与证据记录.md)。不用Case的项目沿用等价身份记录，不为文档格式制造额外工作。

恢复分阶段验收时，按[静态完整与动态恢复](../../grea-recover/references/全量初版工程与协作.md#先静态完整再动态恢复)分别给结论：满足静态七项可单独pass，业务脚本/物理输入not_run不自动否定它；静态pass也不替代动态、目标Player或产品交付。证据绑定生成态、保存态或适配态及当前字节，不能跨层使用旧哈希证明新候选。
