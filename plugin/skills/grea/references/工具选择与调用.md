# 选择功能和调用

先选本次想验证的结果。查看 `grea commands`；按模块运行 `grea commands prefab`，按操作运行 `grea commands prefab intake-plan`。机器可通过 MCP 的 `command_catalog` 读取同一份参数结构；通过 `run_tool` 选择模块作为 tool_id，arguments 依次传动作和参数，run_dir 指向新的回执目录。

| 需要的结果 | 模块 | 实例 |
|---|---|---|
| 对来源和游戏设计做判断 | research、source | `grea research inspect-target`、`grea source index-unity` |
| 恢复方法、预制件和资源 | code、prefab、asset | `grea code inventory-unity-methods`、`grea prefab recover` |
| 采用、配置、调整界面 | project、config、ui | `grea project adopt-plan`、`grea config schema-validate`、`grea ui inspect` |
| 验证、核对和交付 | qa、evidence、build | `grea qa player-run`、`grea evidence compare-traces`、`grea build payload-verify` |
| 服务和环境 | server、system、workflow | `grea server toolchain`、`grea system toolchain-check`、`grea workflow plan-workflow` |

完整索引见[功能模块和命令参数](功能模块和命令参数.md)。独立工具由 `grea system list-tools` 和 `grea system describe-tool` 查询。平台限制、可执行文件、原生连接、样本实测和业务验收分别登记。工具存在和命令清单都不证明目标工程已通过验收。

## 平台与兼容入口

冻结的项目、制品和事务按原身份继续。外部工具或历史接口必须使用它们自己的参数、作用域和回执；不能取当前候选结果替代旧事务的阶段证据。

## 新工具准入

先寻找同一模块的现有操作。缺口确有复现时，在 GREA 仓库实现并验证公共行为，游戏规则和专用素材留在游戏侧。资源核验见[资源审计与制品校验工具](资源审计与制品校验工具.md)，规则核对见[规则差分与数值纹理工具](规则差分与数值纹理工具.md)。
