# 全量初版工程与协作

完整恢复／首次重建采用：GREA调研取证与来源冻结 → monkey一次批量导出独立初版 → GREA编排交接 → beaver在隔离工程采用与验证 → 游戏Agent接续业务、视觉、服务器 → 交付及持续迭代。只读研究、来源辨识和输入准备可以在导出前进行；已有工程的局部修复不无条件重导。

monkey维护源格式解析、资源转换、目标原生装配及代码依据／初稿导出；GREA维护流程、冻结调用和交接判定、Unity/Cocos/Go规范入口；beaver维护开发工程操作、通用框架/生成、配置、测试及构建实现。GREA不另写平行转换器；monkey不先实现整游戏业务。Unity来源目标Unity6，Cocos来源按声明支持选择Unity6/Creator3.8；其他格式先查固定provider能力。目标或能力不支持时明确报未支持，不能用小样或另一引擎替代。

输入按游戏、引擎、修订及manifest冻结已取得全集，区分主包、分包、Bundle、代码／metadata与可证实补齐文件。全量指该明确来源集合，不承诺未知服务器或全部受保护代码。工具commit／版本／能力摘要固定；游戏不自动跟随工具main。

初版交接要实际包含适用的资源、Scene/Prefab、动画、字体音频、配置以及可恢复代码初稿／原始依据，并保留唯一逻辑源ID→目标路径/GUID映射和AI入口。未知方法、不可恢复资源保留源码位置、依据、TODO或明确原因，隔离未实现代码；具名草稿和已证实逻辑不等于全部业务恢复。散列空类、清单、lookup、IR、gallery或媒体池不能冒充完整初版。

依源实际类别核对：源含Prefab/Scene时必须检查实际原生图文件和引用；源没有这些类别时不凭空增加数量门。每项输入有去向、每个逻辑资产有处置，和原生工程可导入／编译分别验证；conversion.completed、文件数量或exit0都不能单独放行。全量初版与游戏可玩是两个出口，不能以全玩法实玩反过来阻断初版交接，也不能以初版导入通过关闭玩法/视觉。

真实CLI边界见monkey接入（项目文档 `docs/providers/monkey.md`）：新工作流通过 `monkey_pipeline` 固定 monkey 0.4.0，plan 冻结完整显式输入，run 执行 Cocos 全集／Unity all-scope 命令，audit 核实际产物。Unity 可分 prepare→export→convert 复用固定阶段。package/slice/handoff 旧入口继续兼容；不猜参数、不复制转换器。新导出后先核 manifest 与来源去向，再依据真实引擎回执审计原生交接；静态字节、completed、目录规范及工具可用均不能替代业务/视觉验收。

交接核清后，游戏Agent按完整模块接续业务、交互、视觉、服务器及换皮。有既有工程时，由 beaver 在独立全量候选与工作工程之间按来源身份三方比较并成组合并，保护既有代码、GUID、正式JSON和存档。来源转换共因交monkey，工程操作共因交beaver，流程／编排共因交GREA，游戏专用业务保留项目；不因这份规范新增推送、安装、渠道或生产权限。

## 本机工具就绪

先 discover/check，再 ensure 绑定本机实际 monkey。完全未安装时，显式 `ensure --install-if-missing` 获取 `chuxintec/monkey` GitHub 最新稳定 Release，校验 wheel 身份与 SHA256SUMS，安装到独立用户数据目录并记录固定能力；不会下载执行安装脚本。已安装版本不自动升级；配置/绑定优先于 PATH，歧义或失效先报错，不静默换工具。`ready=true` 后 plan/run 默认读取持久 lock；每个既有计划保持原工具身份，不能追溯切换版本。完整命令见各恢复子技能与接入说明（项目文档 `docs/providers/monkey.md`）。
