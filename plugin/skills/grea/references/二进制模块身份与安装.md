# 二进制模块身份与安装

本页定义开发中的 Mac ARM64 二进制入口。monkey/beaver 为 GREA 内部模块；新公开 GREA 产品只分发已审的模块二进制、必要接入资源与许可证，不再内置模块源码 wheel。历史源码模式和冻结锁保留，现有游戏不自动切换。Windows 执行阶段须在 Mac 组合实际通过后开展；下述安装和身份校验不证明组合已通过。

## 独立身份

新包根有 `binary-provider.json`，合同 `grea-binary-provider/1`、schemaVersion 1，包含 provider、真实 version、sourceCommit、target、entrypoint、capabilitiesSha256、files、sourceBoundary。首批仅接受稳定 monkey 0.7.0 / beaver 0.6.0 业务基线的明确来源，target 为 `{"system":"Darwin","architecture":"arm64"}`；编译包不得把新功能开发候选换号作为稳定输入。编译适配如改代码，sourceCommit 必须为实际新提交，baseSourceCommit 另列稳定来源；经 owner 交付和 GREA 审核登记精确提交后才能通过，不能假称未改稳定源码。

entrypoint 是包内相对路径，必须指向实际 ARM64 Mach-O。files 枚举除 manifest 本身以外的全部运行文件：相对 path、sha256、bytes；不接受符号链接、目录逃逸、未列文件、资源漂移或空清单。manifest 原始字节 SHA 与整个 ZIP SHA 分别固定。capabilitiesProjection 必须命名稳定投影：monkey 为 `monkey-capabilities/1`，哈希完整既有 JSON；beaver 为 `beaver-capabilities-stable/1`，仅取原 envelope 的 contract、status、producer、data 四字段，排除每次变化的 operationId。保留原始 envelope 证据，不改其公开语义。capabilitiesSha256 是该投影的 UTF-8、sort_keys=true、ensure_ascii=false、separators=(逗号,冒号)规范编码 SHA。版本、协议、实际 producer 与 data 仍被绑定。

beaver 编译模式的 implementationSha256 使用 `grea-binary-runtime/1` 摘要：contract、provider、version、实际 sourceCommit、target、entrypoint，加按 path 排序且仅含 path/sha256/bytes 的全部 files。排除 capabilitiesSha256，避免自身哈希循环；不能接收空文件 map 或伪造旧源码 producer。旧 Python producer 和锁继续原校验。

sourceBoundary 保存工具内部算法、公开接入 SDK、生成用户工程模板和第三方资源分类及证据。该声明不是明文 helper 的自动白名单；须核实际文件和编译内嵌内容。Python/bytecode/wheel、生成 C/C++、source map、备用源码与嵌套归档不以改名绕过；当前有限安装器遇嵌套归档拒绝，确需资源归档另审合同。C#/JS/Swift/Shader 等也必须逐项说明用途与交付方式，用户工程保持原生可编辑。

## 显式安装与 pin

通过既有 GREA `run-tool` 或 MCP `run_tool` 调用，参数均为数组：

```json
{"tool_id":"grea_modules","arguments":["install-binary","beaver","--archive","/absolute/beaver-macos-arm64.zip","--expected-archive","<archive-sha256>","--expected-manifest","<manifest-sha256>","--state-root","/absolute/retained-provider-root","--output","/absolute/fresh-install-receipt"],"run_dir":"/absolute/fresh-install-run"}
```

只从提供的本地归档验证、搬迁到明确版本目录；不下载、不装源码模块、不修改 binding。保管方须声明保留/退役条件，见[运行连续性](固定候选与运行连续性.md)。返回 `installed` 只是完整性安装，probe/native 仍为 not_run。

以安装回执的实际可执行文件配置 `GREA_PROVIDERS`，probe 使用同一 command 加 monkey 的 `capabilities --json` 或 beaver 的 `capabilities`。随后分别调用 `monkey_pipeline pin` 或 `beaver_pipeline pin`，使用 `--binary-manifest /absolute/installed/binary-provider.json --expected-binary-manifest <sha256> --output /absolute/fresh-pin`。不能同时给 Python package-root/identity-root，不能伪 shebang。

monkey 生成独立 v3 binary 锁，beaver 生成独立 v2 binary 锁；它们实际核二进制入口/资源及能力，不造空源码清单。旧 Python v2/v1 锁继续走原校验。新锁每次执行前后核真实 runtime；未适配操作仍拒绝，身份就绪不扩展命令权限。

## 采用与分发出口

模块 owner 先交真实编译包、构建来源、依赖与资源边界；GREA 组织独立安装、搬迁和源码不可访问条件下的公开 CLI/MCP 与代表链。分别核非零/partial/not_run、超时取消与自有进程清理，不以头部测试 fixture 或 CLI 0 冒充运行、恢复或原生构建成功。消费者是否需要升级另按既有授权决定。

Mac 通过后才验 Windows 原生包。新公开源码与完整发行包还须审计全部嵌套制品和 private CI→public artifact 通道；私有源码/凭据/构建中间源不进入公开产物。历史 Release、许可及已下载源码不被新二进制规则撤回，也不宣称二进制不可逆向。
