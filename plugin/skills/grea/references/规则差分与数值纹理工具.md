# 规则差分与数值纹理工具

用于规则轨迹、二进制常量、数值纹理或已有Laya解析器的定向核对；不执行原游戏、不替代真实画面/输入。先按[统一接口](接口调用与证据记录.md)查看实际ID和参数，执行模块由registry.delegate决定。资产台账/依赖和包体检查见[资源审计](资源审计与制品校验工具.md)。

## 轨迹与二进制常量

- `compare_traces`比较两份有序JSONL，重复`--field /board`、`--field /rng/calls`选择JSON Pointer；输出首个差异的零基索引或长度差。0一致、1差异、2输入错误。字段缺失报错，不自动对齐、容差比较或推断采样正确。
- `read_elf_values`读取ELF32/64、两端序的PT_LOAD文件映射；示例`--address 0x1234 --type f32 --count 2`输出偏移和值。地址必须是ELF链接期虚拟地址，运行地址/RVA需先按实际基址换算；无唯一映射、越界、非有限浮点或扩展程序头计数拒绝。不反编译、不读取进程，不能据常量猜业务作用。
- 两者只读输入并输出stdout；需要保存时使用新的run_dir或报告文件。

## 数值纹理

```sh
bin/grea legacy audit_numeric_texture /path/vat.raw --width 33 --height 46 --channels 4 --dtype f16 --candidate /path/unity-export.raw --output /path/new-report.json
```

宽高和格式来自原对象，不从扩展名猜。只支持无mipmap的紧密排列原始浮点数据；有mip链先按格式拆出指定层。输入文件不修改；报告必须新建，父目录须存在。遇到非有限值或candidate不一致返回1。只有源文件检查时candidate_equal为null，不冒称Unity回读通过。采样/sRGB/mipmap由C# Texture入口读取；是否符合该纹理用途由原始契约决定。

## 事件schema

每行JSON：`{"seq":1,"event":"hit","state":{"remaining":10}}`。seq须严格递增，event非空，state为对象；两侧默认精确比较seq/event/state，额外时间或随机字段用 `--field /rng`。不自动重排或对齐不同事件，不把浮点容差、业务常量或随机种子写进公共工具。原逻辑向量生成与C#采样仍属于项目适配。工具不启动原游戏或执行原版脚本。

```sh
bin/grea legacy compare_events native.jsonl unity.jsonl --field /rng
```

## Laya回归边界

```sh
bin/grea legacy laya_contract_audit --converter /path/project/Tools/convert_laya.py --mesh /path/model.lm --global-skin --particles /path/project/Tools/laya_particles.py
```

--global-skin 必须由源 SimpleSkinnedMesh 类型确定；普通蒙皮不要加。检查顶点/骨骼索引、全局索引不被重映射，及合成16帧粒子曲线不丢失。解析器现有流程仍含项目路径/数据约定，故不搬进 GREA宣称通用Laya转换器。

这些结构检查没有证明烘焙矩阵空间、渲染状态和最终姿态等价；它们是继续提炼转换器前的回归门槛，不能替代原场景GPU与逐帧对照。只有显式指定可信本地Python时才使用此入口，因为Python模块顶层代码可以有副作用。


## 结果交付

记录输入哈希、所选字段/格式/地址、首差异及解析限制；继续追原规则或渲染链，不把结构相同写成行为/画面一致。无candidate时只报告源检查；明确解析器可信范围，Python模块导入可能执行顶层代码，不能对未知脚本直接使用Laya回归入口。
