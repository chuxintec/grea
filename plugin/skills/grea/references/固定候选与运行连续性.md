# 固定候选、消费者采用与运行连续性

从真实项目缺口开始，先查已有模块及其命令。来源恢复、工程采用和进程生命周期由 GREA 实现；业务规则、场景选择和产品断言留在项目。

## 从缺口到结束

工具项只在所属工具的一份任务源维护；项目项记录消费关系并引用它，不复制工具进度表。至少写明：

| 内容 | 必要证据 |
| --- | --- |
| 消费者 | 项目与任务ID、原脚本或公开操作、实际失败入口 |
| 最小复现 | 固定输入与工具身份、预期/实际、失败范围和可用替代 |
| 现有能力核查 | 当前capabilities、公开帮助或Schema；能通过现有spec/profile表达时复用，不新增API |
| 固定交付 | 源码commit、版本、制品SHA、producer/包文件/能力身份、所需运行时及GREA支持的有限操作 |
| 采用 | 项目在自然集成点实际使用的入口、锁、输入及回执；发送成功只表示已交付 |
| 相关验证 | 原失败消费者与具有同机制的独立样本；中性变体单列，第二项目无适用场景时不虚构复用 |
| 结束条件 | 原问题解除、声明范围内重复调用成立、项目重复实现可退为薄调用；未验边界仍保留 |

状态分别记录为实现中、固定候选已交、消费者已采用、相关验证通过。单测通过、doctor就绪、方法更新或项目手工绕过不能代替采用结果。消费者和结束条件满足后结束该项；新缺口另带真实依赖，不用“完善工具”无限扩大范围。无依赖的游戏开发继续。

Player 启动先核 manifest、spec、profile 已有表达能力。正常退出、超时、停止、冷启动、子进程回收和业务结果按本次范围分别验收。

## 规则与版本分发

源码或文档改完，不等于已进入安装包、共享 Skill 副本或当前会话。源码提交、构建包、共享副本同步和会话实际加载分别记录；GREA 版本与能力以 `session` 为准，Skill 规则以实际读取的副本为准。

- provider 固定版本（lock、producer）与流程 Skill 身份分开记录，一方更新不能推断另一方。
- 无实际需要时，不自动升级活跃项目，也不热换已有锁；新候选由项目在自然集成点显式采用。
- 成组修正规范后核实际消费入口：技能路由能否到达新参考、项目读的是哪一份副本、已有调用方是否仍指向旧条目。
- 修订只更新当前约束，过期内容按[修改与验证](开发复盘与规范更新.md#修改与验证)处理。

## 运行时归属与保留

记录解释器、依赖、入口和本次实际部署的版本与内容哈希。复验必须能定位当时使用的实现；开发工作区、独立安装、原生 Editor 和玩家制品各自固定。

venv可能通过解释器链接、`pyvenv.cfg`或`.pth`继续依赖宿主目录。新候选须从打包制品在独立目录安装，用真实公开入口核实际导入及所需依赖，确认不依赖开发工作树、临时目录或随客户端升级删除的插件缓存。工具私有开发目录只能按证据标记为临时保留，不能自动登记为永久部署；长期位置和保管责任须在实际采用记录中明确。具体安装/运行时实现归所属工具，不在项目另造执行平台。

已闭合的旧链修复复用原回执，不重放历史事务。需要迁移时生成新的入口/消费者绑定和锁，核对原包、实际导入及受影响公开操作；旧锁保持原字节，不因版本更高全局换包。安装就绪、plan、apply、目标构建/运行分别报告。

删除旧运行时前，必须有实际消费者清单和新绑定验证，确认没有活跃进程或仍获准使用它的固定链。封存事务引用的历史身份与不可重放边界继续保留；不能把目录标记“旧版”当作退役依据。没有新增安装/切换授权时只登记保留责任和条件，不搬迁、覆盖或热替换。

## 结果口径

只按本次变更核查受影响范围；固定候选就绪后再做有限集成，不重验未变的游戏全链。记录明确分母的恢复结果、剩余人工修补、同一公开能力的真实复用，以及从缺口到固定交付再到采用的实际用时。没有时间证据不补造历史周期，测试数和报告数不作为产品进度。
