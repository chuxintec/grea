# 使用指南

当前本地开发线采用 GREA Skill＋monkey 恢复＋beaver 工程操作。完整新执行链先用 `toolchain_check` 显式核两项必选依赖；GREA 核心可启动不代表 provider 就绪。详情见[beaver接入](providers/beaver.md)。旧接口仅在既有固定基线或接收过渡中保留，不能替代新版依赖。


用途：对明确输入执行一个有证据回执的任务。先完成 [安装](安装与平台.md)，Unity 开发另见 [Unity指南](Unity指南.md)。

## 最小任务流程

1. 运行 `session` 核对版本、包路径、能力与限制。
2. 运行 `list-tools` 或查 TOOLS（GREA 安装目录 `TOOLS.md`）；用 `describe-tool` 回读真实依赖、格式、命令及副作用。
3. 为输入冻结哈希，指定全新输出目录与 run_dir。不能覆盖源文件或复用上次运行目录。
4. `run-tool --input request.json` 执行；CLI 与 MCP 使用同一契约。请求文件须为 UTF-8，不含凭据。
5. 检查 envelope 的 status/error、run.json、stdout/stderr 和输出哈希。退出码、解析成功、资源闭包与可玩结果分开报告。

```json
{
  "tool_id": "static_asset_copy",
  "arguments": ["--source", "/absolute/input", "--output", "/absolute/new-copy", "--map", "a.txt=b.txt"],
  "run_dir": "/absolute/new-attempt",
  "timeout_seconds": 120
}
```

将上面内容改为本机绝对路径后保存为 request.json，执行 `grea run-tool --input request.json`。Windows 可使用 `C:/work/...`；不要直接复制 POSIX 路径。完整参数和操作表见 [接口](接口与证据说明.md)。

## 选择任务

恢复/转换使用 `plan-workflow` 明确 intent、来源引擎/版本/格式、target_engine（unity/cocos/none，省略仍unity）、backend（none/go）、目标平台和验收 profile。只读评估不自动进入实现；局部修复只补相关证据。实际流程转交 [GREA 技能](../SKILL.md)。

- 资源/代码取证：显式目录、冻结清单；Cocos 2.x 与 Creator 3.4.1 不共用猜测 reader。
- 配置：先用声明 schema/codec 的预检，再进入类型化制作；不执行 RNG/奖励/存档求值。
- 表现与性能：采集器提供实际身份/帧/环境，分析工具只判断声明合同，不把 RSS 当 GCAlloc。
- 依赖缺失：只阻止对应能力；读 [专项契约](providers/README.md)，不自动安装或更换供应方。

## Case 与验收

`init-case` 建立来源与任务身份；`start-case-revision` 冻结候选文件；用证据操作追加不可覆盖记录，`case-status` 回读。候选改动使旧验收失效，建立新 revision 后重新核对受影响门槛。旧 v1 只作为对应基线读取，不悄悄覆盖。

系统锁/进程超时、取消、输出上限失败时先保留回执，检查是否 cleanup_complete；不以新 ID 重跑掩盖未清理进程。更多见 [故障排查](故障排查.md)。

开发候选：[调研工具](providers/research.md)、[Cocos生成/转换](providers/cocos-target.md)、[Go六服源模板](providers/server-go.md)。研究不授权立项，模板生成不自动安装/启动服务。
