# 接口与证据契约

CLI命令用短横线，MCP工具用下划线，例如 `inspect-target` 与 `inspect_target`。具名操作的相对文件路径按 CLI 调用目录／MCP 服务工作目录解析；跨项目调用推荐绝对路径。通用 run-tool 的 argv 原样传递，文件参数须用绝对路径。两者调用同一应用层，输入使用严格JSON Schema：未知字段和无效类型被拒绝。完整模式与schema由 操作目录（GREA 安装根目录资源 `schemas/operations.json`；实际参数先用 `describe-tool`/工具 `--help` 核对） 生成；工具实现及环境位置由 `registry.json`（GREA 安装目录） 维护。

## 操作

使用 `grea session` 查看实际版本，`grea list-tools` 查询工具，`grea describe-tool '{"tool_id":"TOOL_ID"}'` 读取当前参数、依赖和副作用。CLI 参数为 JSON；MCP 使用同名操作及结构化参数，运行前按实际加载的契约选择操作。

## 结果与退出码

受控执行默认 timeout_seconds=120、max_output_bytes=16 MiB、max_inline_bytes=32 KiB（每个流）。有效预算同时出现在结果与运行回执中。这里只定义语义，实际可接受的范围以生成 schema 为准。

每次调用返回schema_version、product/version、operation、run_id、status、result、evidence、limitations、limits、error。错误包含稳定code、message、details、retryable、next_action。CLI输出完整JSON，退出0=ok、1=partial、2=error；MCP的工具执行错误同时isError=true。原始工具退出码在result.exit_code，不被统一接口抹掉。

已登记差分工具的退出1映射partial；未登记为“发现差异”的非零码仍是error。超时、取消、日志截断上限分别为TIMEOUT/CANCELLED/OUTPUT_LIMIT；未知工具、依赖缺失、错误参数、既有输出分别有独立错误码。文件缺失与未检查不能解释为不存在功能。

run-tool的timeout、总日志字节上限和每个流的内联字节上限都可在请求中显式指定，回执保存有效值。stdout/stderr完整捕获内容留在新run_dir，内联预览省略时标记partial；达到总日志上限会终止所属进程组并保存失败状态，不把截断报告记为完整。所属进程组清理不保证覆盖主动脱离进程组的守护进程；Windows 使用执行前纳管的 Job Object，清理回执记录 owned_job 与 cleanup_verified；正常退出也结束所属后代。它不是任意守护进程或系统沙箱的绝对保证，原生范围见验证报告。

目录inspect的完整性只覆盖实际枚举的范围；不跟随符号链接。不完整时observed_inventory_sha256仅标识已观察清单，target.sha256为空。需要更多覆盖时显式增加预算或缩小到目标子目录。

## 项目内记录

```text
project-XX/.grea/
  case.json                 基线文件哈希、模式、必需维度（保留旧 v1 可读性）
  revisions/rev_<digest>.json 显式候选/构建/平台身份，不覆盖旧修订
  evidence/ev_<digest>.json  内容身份与来源角色；实际媒体仍在项目Evidence
  verifications/vr_<digest>.json 审阅声明，保留历史，不覆盖
  .lock                     并发文件锁
```

证据类型为original_static、original_runtime、candidate_runtime、approved_design、test_report、build_manifest。视觉对照至少绑定原版运行和候选运行，授权换皮用批准设计和候选运行；仅静态测试不能填成运行/视觉通过。原包/证据字节变化或记录哈希不符会拒绝继续使用旧结论。哈希用于完整性，不是签名或对来源真实性的认证。

最小调用示例：

```sh
grea describe-tool '{"tool_id":"verify_payload_tree"}'
grea run-tool '{"tool_id":"verify_payload_tree","arguments":["--help"],"run_dir":"/absolute/new/help-receipt"}'
```

先核对返回的实际模块、依赖和参数再执行；`--help` 成功不代表真实文件已校验。纯 Skills 不提供可执行程序，须另有兼容的 GREA CLI/MCP 与已固定模块；这属于运行依赖，不是文档依赖。

初始化、登记和审阅记录是显式写操作，不从读取项目自动创建；原始证据不覆盖。用户原有授权仍决定哪些原生操作、安装、收费、账号或发布动作可执行。

## Unity 工程静态规划

`validate_unity_project`、`plan_unity_project`，CLI 为对应 kebab-case；均直接只读并返回公共 envelope。project_root 必填，profile/baseline 为项目根内相对路径。文档 Schema 由 contracts.py 聚合并由同一生成脚本输出；详见 [项目配置与只读规划](../../grea-develop/references/Unity工程工具与生成.md)。生成由独立操作执行；静态 ok 不代表 Editor 或游戏通过。

## Unity 工程生成

`plan_unity_generation`、`generate_unity_project`、`recover_unity_generation`，与静态规划兼容接口分开。工程生成 planId、暂存写入、Editor 执行、所有权清单、过期/恢复门槛和实际副作用见 [工程生成契约](../../grea-develop/references/Unity工程工具与生成.md)。manifest schema 增加可选 recipeId；工程生成执行要求该身份。静态规划仍只做静态设计，不接收工程生成 planId。

操作与机器可读 Schema 由当前 GREA 契约生成，能力以实际 `session`/`describe-tool` 为准。辅助模块未捕获异常转为退出码 2；不靠日志文本推断差分结论。

## 变更合同与候选证据

`plan-workflow`/Case/revision接受 `evolve` 与可选 `change_contract`；evolve的Case/revision必须提供有效合同并绑定source文件SHA，不能删除规则/身份/运行/视觉或适用native维度。UI/UE合同见 [变更合同 Schema](../../grea-develop/assets/change-contract.schema.json)，主题映射见 [工具](../../grea-develop/references/主题资源映射与台账工具.md)。visual对照批准设计，rules对照旧基线静态依据与测试。候选设计可以制作样板，不能记录为批准视觉通过。合同和证据角色均为声明，不替代用户授权或实际运行。
