# 从来源到开发工程

使用 `grea commands` 查看此安装的功能模块；用 `grea commands 模块 动作` 核对本次所需的参数。CLI 和 MCP 的参数清单来自执行用的同一组解析器。CLI 的完整模块索引见[功能模块和命令参数](功能模块和命令参数.md)。

## 当前实现边界

来源恢复生成独立候选。已有开发工程通过显式计划采用候选。两步都在 GREA 中执行；需要 Unity 的操作仍要求准确的 Editor、目标工程路径和可用依赖。能力清单、命令帮助和文件清单各自只能证明其覆盖范围。

- 固定原包、容器哈希、序列化文件和对象 ID。Prefab 链从 `grea prefab recover` 开始，经 `grea prefab verify` 取得原生回执，再用 `grea prefab freeze` 固定候选。参数与输入材料见[来源恢复操作](来源恢复操作.md)。
- 核对既有工程 GUID、文件和人工改动。只新增资产用 `grea prefab intake-plan`；有共同基线的三方采用用 `grea project adopt-plan`。分别用匹配的执行或回滚命令；不能互换计划和事务。见[工程事务操作](工程事务操作.md)。
- 标明哪些根通过保存、冷读、Play Mode 和画面对照。运行时服务、动态加载和服务器状态单列。用户要求保持的既有事务继续使用生成时的工具版本、内容哈希和项目路径。

安装、发布、生产操作和全局工具升级分别按已有授权执行。当前源仓库统一维护，历史发布和在途固定身份只作原版本依据。
