# 工程事务操作

先固定工作工程的实际输入和现有修改。在隔离副本生成计划，核候选、版本、目标和文件身份，保留可回退的既有状态。

| 任务 | 入口与边界 |
|---|---|
| 增量接收新 Prefab 和资源 | `grea prefab intake-plan` 读取候选、目标和 spec；`grea prefab intake-apply` 要求计划文件、预期计划 SHA、Editor 和新输出；失败时查事务日志并按 `grea prefab intake-rollback` 的原合同恢复。 |
| 三方采用 | `grea project adopt-plan` 对照旧基线、新候选与工作工程。仅在有相应输入与授权时用 `grea project adopt-apply`；保留后续人工修改。 |
| UI 与接线 | `grea ui inspect` 需要 Editor 和目标 spec；`grea ui analyze` 与 `grea ui repair-plan` 使用已取得的快照；`grea ui wiring-plan` 生成计划。 |
| 项目迁移与退役 | `grea project unity-plan` / `grea project unity-apply` 根据明确的原生操作 spec 执行；`grea asset references` 检查消费者。目录/资源移动须保留 GUID 和 localID。 |
| Player、输入与附着验证 | `grea qa player-run`、`grea qa bind`、`grea qa virtual-bind` 均有各自的输入身份与宿主要求。只操作已授权的测试实例；输入通道、物理桌面、Play Mode 和实际业务结果分开报告。 |
| 封装 | `grea build payload-verify` 验证制品清单。新目录物化需要 `grea build payload-plan` 与 `grea build payload-apply`；搬运成功不计作 Prefab 原生采用。 |

增量接收的 apply 和 rollback 可用 `--timeout` 指定每个原生阶段的秒数。当前范围为 1 到 1200，默认 600。越界在事务开始前返回 `INTAKE_BUDGET`。

隔离工程首次导入可能生成缺少的 .meta。应先预热副本再生成采用计划。若预检报告输入变化，核对新增、删除和修改文件，在确认后的副本重新生成计划及其 SHA。

三方采用对既有工程的只读盘点允许累计 64 GiB；新候选仍受单次 8 GiB 的全量导出上限约束，不能通过候选清单扩大既有工程的策略。文件数与单文件限制不变。

纯资源的新增/更新达到 128 项时，原生采用按 128 项分组导入，每组写入前持久化事务意图，导入后逐项核验哈希、GUID 和 localID；退出后仍独立重开检查。包含代码编译边界、移动或 SDK 接线的事务继续使用各自既有流程。中断回滚可识别一组内尚未写入的新增项和仍为原态的更新项，不能直接重放未完成事务。

## 回执

统一 CLI 的 result 保留底层操作回执。实际写入前核前态；当事务记录可能有局部写入，先读 journal，再选择受控回滚或新计划，禁止盲目重放。预览、执行、独立重开、画面对照和实际输入分别记载。外部 Editor、SDK 和服务的可用性在需要它们的操作中验证。

计划中的 `implementationSha256` 固定实际执行实现。新运行时通过 `development/implementation-scope.json` 声明同时覆盖工程实现、功能模块和命令边界；文件移动或修改会改变指纹。旧计划和旧运行时仍保留原哈希格式，不能把旧计划的生产者改成当前值后继续写入。

`grea prefab intake-export-bindings` 只在原生准备的两次进程均成功退出、快照一致且原生 helper 未改变时，复用原验证向新目录续导。`--native-runtime` 指向原固定运行时的工程实现目录：新格式为 `development/`，要求相邻的 `features/`、`commands/` 一并存在；旧运行时按原单目录盘点。工具只读取原运行时并核对 `--expected-native-producer`，不会导入其 Python 或重新运行 Editor。

若原生 apply 与独立 verify 都已逐项通过，只有最后状态提交失败，可用 `grea project adopt-finalize --transaction 事务目录 --editor-path Unity路径 --timeout 1200` 再次重开核验并提交状态；不重新写入候选资产。要求原 Editor 脚本哈希未变、固定候选未变、无后续采用，部分写入仍须走 rollback。

新计划会在写入前拒绝候选与既有目录的大小写/Unicode 拼写差异。旧事务仅因既有父目录拼写不同而无法落账时，可在 finalize 增加 `--canonicalize-parent-case`；只允许新增文件落在原已存在目录的实际拼写下，不能改文件名、移动既有目录或放宽字节校验。回执与采用状态记录原请求路径到实际路径的映射。
