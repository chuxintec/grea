# GREA · 游戏调研

先明确用户要作出的决策，读取[游戏调研与成本判断](references/游戏调研与成本判断.md)与[共同约束](../grea/references/共同约束与执行入口.md)。已有证据按身份与适用范围复用，事实、推断、假设和未知分开。

1. 观察同版本原版，记录核心循环、教学、系统入口和受限分支；方法见[原版运行与内容取证](references/原版运行与内容取证.md)和[实际体验与画面对照](../grea/references/实际体验与画面对照.md)。按分析范围获得必要证据，不用静态数量替代体验。
2. 只在会改变判断时补资源、技术或协议证据。需要包体识别/解包时调用[恢复阶段的只读取证模式](../grea-recover/SKILL.md)，以明确输入和问题结束；不因此生成或运行游戏候选。
3. 给出品类、核心/成长/变现循环、系统与内容规模、客户端/服务器边界、目标路线、成本区间与主要风险。品类常见机制不当原版事实，不能将传统人日直接除以 Agent 数。
4. 需要结构化报告时按[调研工具与证据合同](references/调研工具与证据合同.md)编写输入，使用随技能分发的 Schema；`research_report`校验和整理声明，不替分析者判断。

交付研究结论、来源/覆盖表、成本前提及未知项，回答哪些证据会改变结论。报告推荐不是开发授权；用户决定恢复后转 `grea-recover`，已有可维护工程或已批准原创设计直接转 `grea-develop`。技术提取、原生运行、可玩性、视觉和商业可行性分别报告。
