# Unity · 动画特效与事件时序

> **何时读**：动画、粒子、Spine 或 Shader 表现与原版不同，特效"导入了但没播放"，或命中、结算、奖励的时序与原版不一致时。
> **读完产出**：从请求到画面的引用链检查记录、事件时序对照（命中 → 表现 → 移除 → 完成）、动画写入所有权说明、按阶段截取的录像或关键帧证据。

工具推荐：`video_sheet` 定位阶段，`compare_events` 对齐命中与结束；粒子与 Spine 由 Unity 回读和真实画面核验。入口和限制见 [工具清单](shared/工具选择与调用.md)。

本页给出通用检查方法；对象、参数和时长由当前游戏的原代码与录像确定。具体玩法的历史返工记录见 [案例教训](https://github.com/chuxintec/grea/blob/3d1a2be71292696ecc910523f33e949c160e3927/docs/history/案例教训-玩法与动画.md)。跨引擎项目用 Unity 原生组件（Animator、补间插件、ParticleSystem）得到原版的结果，映射见 [Cocos 映射](shared/Unity源引擎映射-Cocos.md#动画补间与特效)。

## 完整流程与状态调度

1. **补全流程证据**：录像覆盖从触发到结算结束的完整过程，记录阶段、轮数和时长。
2. **区分三类问题**：流程（阶段缺失或顺序错）、状态调度（实时推进还是预计算后串行播放）、渲染（画面错）。先判断类别，再决定改参数还是改结构。
3. **对齐生命周期**：可再次触发的对象，同时恢复其生命周期、候选扫描、并发关系和完成条件；退出条件以原代码为准。
4. **结构差异单独修**：原版实时推进而复刻预计算时，修正推进方式本身；调整单个时钟或粒子只解决局部。

完整检查步骤见 [完整流程与调度检查](开发前检查与迭代.md#完整流程与调度检查)。

## 奖励表现与流程边界

- **四个量分开**：奖励资格、已确认奖励、屏幕计数和最终存档分别维护。视觉数量从已确认奖励派生，奖励只由业务层发放。
- **动画参数来自事件**：沿实际接受的奖励事件给动画传入来源位置、金额和时间；发射数量追到实际循环和调用参数。
- **飞行闭环逐阶段核对**：散开、转向/加速、终点、逐个计数、声音和完成屏障。进入结果页、跳过、退出和切后台时按原版生命周期收尾，验证不重复到账、不遗留帧循环、等待都能完成。
- **入口分别验证**：首次进入、已有存档、未完成关卡、正常回主页是不同入口；资源不足按"尝试 → 提示 → 返回 → 再次进入"的完整路径验证，失败时不扣资源、不推进任务，重复点击只提交一次。
- **平台回调定义四种结果**：广告、分享、云存档分别定义完成、取消、不可用和重复回调。获授权的离线自动领奖走同一完成入口并标为离线策略，见 [原生转换规范](shared/Unity原生转换规范.md#平台-sdk)。

## "导入了但没播放"的检查链

1. **请求解析到对象**：对照源资源标识、导入后名称、目录与运行注册表；使用显式映射，歧义时报错，关键特效缺失时记录错误。
2. **对象实例化并发射**：记录请求次数、活跃实例、粒子数、发射器启用和生命周期。粒子计数为 0 时，状态记为"未接通"。
3. **关键帧推进**：序列帧区分常量、随机常量、曲线、随机曲线，核对帧数归一化、循环、起始帧和图集方向；size/color/alpha/rotation 曲线、重力、限速和模拟空间分别验证。
4. **消失与命中对齐**：追踪命中 → 表现 → 缩小/碎裂 → 移除 → 计数/完成；原版完成回调晚于命中时，等回调后再隐藏和结算。原代码中的短时补间按其时长恢复。
5. **复用与清理完整**：池化对象在取出前复位粒子、颜色、缩放、旋转、锚点和计时状态；分别证明暂停、切关和销毁后无残留、无重复扣减。

## 可打断反馈与动画写入所有权

- **保留稳定基态**：重复触发的缩放/弹跳从稳定基态或专用反馈子节点开始；重播前取消旧反馈并复位，基态随业务状态（升级、动态缩放）更新。
- **用操作代次让旧动画失效**：可并行的连续操作从当前可见姿态续接；用 generation/操作 ID 判断，只有当前操作写最终位置、解除忙态和发完成事件。扣费、领奖等事务回调按事务规则处理，不随表现一起丢弃。
- **一个 Transform 一个写入者**：补位、揭示、上架、翻转等动画可能同时写同一对象；定义当前写入者、交接和取消方式，并检查中段而不只检查终态。
- **外观从同一状态派生**：隐藏、揭示、高亮等状态影响的所有部件（主体、数字、附属件）从同一可见状态派生，并随状态更新。
- **序列帧使用固定画布**：保持稳定的锚点；表现调整不改变一次性采集、奖励与完成回调。

## 特效排错顺序

黑块、缺图、错位或节奏错误时，先追完整引用链，再修改效果：

1. 对象是否使用正确的材质、Sprite、图集页、UV/旋转和裁切。
2. alpha 是否保留；原 Shader 是普通透明、预乘还是加法混合。按混合方式修正材质，保留原像素。
3. 像素与世界单位是否混用；父变换、Camera、发射空间是否重复应用；镜像与排序是否正确。
4. burst、delay、lifetime、连续发射、速度、重力、size/color 曲线是否按源数据采样。
5. 父子发射器是否重复遍历；效果是否在正确事件启动、暂停、结束和销毁。

修复使用原始纹理。投影方式与 Unity 材质不同的部分，用实际画面对照确认效果。

## 材质替换与 UI 粒子合成

- **替换材质或 Shader 前**列出业务实际访问的属性、关键词和机制状态，对当前使用的 Shader 回读，并从每个真实机制入口触发验证。
- **UI 粒子分两段检查**：先确认粒子本身输出正确，再检查 Canvas 合成（激活根节点、Camera/RenderTexture 范围、alpha 混合、色彩空间、遮挡）。原始输出正确而最终被遮挡时，修合成链。
- **同帧多事件的音效**：核对去重的作用域与完整事件集合，覆盖不同移除顺序、跨帧连续触发和声音关闭；事件日志、有效样本、可听效果分别报告。

## 完成条件

- 每个修复的表现有触发事件、开始/中段/结束三处画面证据，与原版同状态录像对照。
- 事件时序（命中、移除、完成、奖励）与原版轨迹一致，或差异登记为缺口。
- 复用、暂停、切关、销毁后无残留和重复结算。
- 结果按 [分层验收](shared/测试与结果交付.md) 记录；跨引擎项目同时通过 [原生可维护门](shared/测试与结果交付.md#原生可维护性跨引擎转换)。
