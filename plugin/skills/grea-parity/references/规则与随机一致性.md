# 玩法 · 规则与随机一致性

> **何时读**：恢复或转换后的数值、随机序列、状态事务、几何判定与原版不一致，或把 JS/TS 规则转写为 C# 时。
> **读完产出**：规则 oracle（原代码或原版轨迹）、逐步对照轨迹与第一个分歧点、JS→C# 类型与语义对照表、按机制组织的回归用例。

工具推荐：`compare_events`/`compare_traces` 对照事件与随机，`read_elf_values` 核对常量，`run-tests-bounded` 限制失败测试。入口和限制见 [工具清单](../../grea/references/工具选择与调用.md)。

本页给出通用方法；对象、参数和分支由当前游戏的原始证据确定。具体玩法的历史返工记录见 [案例教训](https://github.com/chuxintec/grea/blob/3d1a2be71292696ecc910523f33e949c160e3927/docs/history/案例教训-玩法与动画.md)，只在机制相同时作为排查候选。

## 1. 建立规则 oracle

1. **选定 oracle**：可执行原代码时，用最小宿主桩调用原方法；不能执行时，用同版本原版录像和日志整理轨迹。保存原文件哈希、桩覆盖的宿主依赖和限制。
2. **导出逐例结果**：每个用例记录输入、初始状态、输出、状态变化和各随机通道的调用次数。桩只替换宿主依赖（时间、存储、平台 API），待测规则保持原样。
3. **对照目标实现**：C# 规则在 Domain/Gameplay 中运行同一组用例，逐字段比较。测试预期来自 oracle，从当前实现复制的值只能作回归快照。

## 2. 定位第一个分歧

1. 固定种子、初始状态、操作序列和调用顺序；四者一致才能比较随机结果。
2. 每一步记录状态快照、输入、各随机通道计数和派生结果（生成物、连锁轮数、奖励）。
3. 找到第一个不一致的步骤，再追它的调用链。最终胜负、平均值或终局状态只用于发现问题，定位依据是第一个分歧。
4. 固定种子的专项夹具与普通设备种子分开登记。一个种子对齐只证明这条轨迹；尚未恢复的分支单列为缺口。

## 3. JS→C# 规则对照方法

原版规则多为 JavaScript/TypeScript（Cocos、Laya、Egret、H5）。转写到 C# 时，按下表逐项决定实现，并用第 1 节的 oracle 测试证明，而不是在 Unity 中模拟 JS 引擎。对照表记录在项目 Analysis，C# 代码只保留结论。

### 3.1 number 分级

JS 只有 IEEE-754 double。按值的用途分级，每个字段在对照表中写明级别与依据：

| 级别 | 适用值 | C# 类型 | 检查 |
| --- | --- | --- | --- |
| A 计数与索引 | 数量、等级、下标、ID；原代码只做加减和比较，且确认始终是整数 | `int`；可能超过 2³¹ 时用 `long` | 用 oracle 的最大值和边界值测试；对 `/` 结果用 `Math.floor` 的地方显式整除 |
| B 金额与累计 | 货币、经验、分数等会累加、相乘或超过 2³¹ 的值 | `long`；原代码依赖小数时用 `double` | 列出全部乘法与百分比加成，核对每一步的取整位置 |
| C 公式中间值 | 含除法、百分比、幂、三角函数的中间结果，以及最终取整前的值 | `double`（与 JS 相同精度） | 不要换成 `float` 或 `decimal`；取整前后的值都进入对照用例 |
| D 表现量 | 坐标、缩放、动画时长等不影响规则结果的值 | `float` | 不进入规则 oracle，按可观察结果对照 |

- 位运算（`|0`、`>>>`、`&`）会把值截成 32 位整数；C# 中写成显式 `(int)`/`(uint)` 转换，并测试负数与大数。
- `parseInt`、`Number()`、`+str`、隐式字符串拼接的转换规则不同；按调用点逐个写出 C# 解析方式（`int.Parse` 与 `CultureInfo.InvariantCulture`），并测试空串、小数串和非法输入。
- `NaN`、`Infinity`、`undefined` 参与比较和运算的结果要在对照表中给出处理方式；默认值缺失时（如旧存档字段为 `undefined`），显示、行为和持久化使用同一个默认值。

### 3.2 排序稳定性

- `Array.prototype.sort` 自 ES2019 起要求稳定；C# 的 `List<T>.Sort` 和 `Array.Sort` 不稳定。相等元素的先后会影响结果时，用 `Enumerable.OrderBy(...).ThenBy(...)`（稳定），或在比较器中追加原始下标作为最后的 tie-break。
- JS 不带比较器的 `sort()` 按字符串排序（`[10, 9, 1]` 得到 `[1, 10, 9]`）；按原行为写成字符串比较器，并使用 `StringComparer.Ordinal`。
- 比较器返回 `a - b` 时，C# 中用 `a.CompareTo(b)`，避免整数相减溢出。
- 用含相等键、已排序、逆序和单元素的输入做对照。

### 3.3 随机与种子

- `Math.random()` 无法设种子，也没有跨引擎一致的序列。原版只用 `Math.random()` 时，规则层定义一个可注入的 RNG 端口，对照依据是分布、调用次数和消费顺序，不追求逐值相同。
- 原版自带种子 RNG（LCG、Mulberry32、xorshift 等）时，在 Domain 中逐行转写算法，按原代码的 32 位截断和无符号移位实现，用同一种子的前若干个输出做 oracle 测试。
- 一个随机通道对应一个 RNG 实例；表现随机使用独立实例，不消费规则通道。记录每个通道的调用次数，作为第 2 节轨迹字段。
- `Math.floor(Math.random() * n)` 一类区间映射，在 C# 中保持同样的乘法后取整，不换成 `Random.Range(0, n)` 的其他映射方式。

### 3.4 toFixed 与字符串格式化

- `Number.prototype.toFixed` 按二进制值舍入（`1.005.toFixed(2)` 得到 `"1.00"`），C# 的 `ToString("F2")` 与 `Math.Round` 默认规则不同。规则依赖格式化结果时（例如格式化后再解析），在 C# 中实现与原版相同的舍入，并用边界小数做对照。
- `Math.round` 对 `.5` 向正无穷舍入（`Math.round(-2.5)` 为 `-2`），对应 C# `Math.Floor(x + 0.5)`；不要用 `Math.Round` 的默认银行家舍入。
- 只用于显示的格式化（千分位、缩写单位）归 Presentation，按截图对照；格式化统一使用 `CultureInfo.InvariantCulture` 或项目指定的文化。

### 3.5 Date 与时区

- `Date.now()` 返回毫秒，C# 的 `DateTime.Ticks` 单位不同；时间戳统一换算为 Unix 毫秒 `long`。
- `new Date()` 的 `getDate`/`getDay`/`getHours` 使用设备本地时区。每日刷新、签到、离线收益等规则先确认原版使用本地时间还是 UTC，再在 C# 中通过可注入的时钟端口实现，并测试跨午夜、跨月、夏令时切换与修改设备时间。
- `getMonth()` 从 0 开始；`Date` 对越界值会自动进位。转写时逐个调用点核对。

### 3.6 整数溢出与精度

- JS 整数在 2⁵³ 以内精确，超出后丢失精度但不回绕；C# `int` 在 2³¹ 处回绕。B 级字段用 `long`，并在关键计算处使用 `checked` 或范围断言，用 oracle 的最大值验证。
- 原代码有意依赖 32 位回绕（哈希、RNG）时，在 C# 中使用 `unchecked` 并保留注释说明来源。
- 浮点比较保持原代码的写法；原代码用 `===` 比较浮点结果时，C# 也用精确比较，不自行加 epsilon。

## 4. 只读查询与事务提交

- **只读入口独立实现**：提示、可行步搜索、审计等入口使用状态副本或纯函数，不调用会结算、补充或消耗随机数的方法。临时修改在异常路径也要恢复；测试证明调用前后状态、步数和随机计数均不变。
- **事务先计划后提交**：涉及多个对象的操作（预约、移动、消耗、释放）先在计划副本上算出完整结果，全部成立后一次提交；失败时返回明确结果并验证没有部分提交。
- **事件分开记录**：数量归零、在途完成、整组完成和资源释放是不同事件；按原版的时点分别触发和测试。
- **规则修正后重验**：状态模型变更后，按新模型重放受影响的关卡与求解路线，旧通关记录只对旧规则成立。

## 5. 几何与碰撞判定

1. **画出调用链**：输入捕获 → 约束 → 路径探测 → 姿态提交 → 接触进出 → 关系更新 → 结算，标出每一步发生的帧和会改状态的方法。
2. **按碰撞职责恢复**：区分主体、附属部件、传感器、触发器和输入碰撞体，逐个核对层、trigger、拥有者和过滤规则；原方法逐个查询附属碰撞体时，目标实现也逐个查询。
3. **分开维护关系与几何**：静态配置、活动绑定、接触集合和可移除状态各自维护；覆盖部分脱离、完全脱离、重入和移除后缓存失效。
4. **确认探测的副作用**：沿调用者确认首次接触是否立即结算；真实移动与只读探测分开验证。
5. **普通与快速输入分别回归**：同起点同方向覆盖慢速连续移动、单帧大位移、受阻后反向、松手再拖；比较首次碰撞对象、停止位置、关系集合和得分。
6. **字段按所属模式生效**：轴向、局部/世界方向、锁定和阈值逐分支对齐，只作用于原分支。

## 6. 优化与性能对照

- 性能优化保持候选优先级、同距离 tie-break、遮挡、随机和预约状态不变。可以采用等价的空间索引、提前退出、缓存与剪枝；缓存键和失效时机覆盖所有实际依赖。
- 报告设备、构建、分辨率、关卡/种子、在途对象数、采样窗口，以及均值/P95/最大帧时；两段采样使用同一轨迹才能计算优化比例。详细方法见 [性能分析与优化验证](../../grea-unity-standard/references/Unity性能分析与优化验证.md)。

## 6A. 数据表读取与查找键

- reader 保留原查找键的完整组成。原表以（ID, 序号）等复合键查找时，按单 ID 去重会静默丢行；先从原方法的 lookup 签名与全部行确认唯一键，再写 DTO 与读取器，并用原表行数和键集合做回读断言。
- 坐标/单位换算（如格子坐标→世界坐标）以原方法为依据逐字段对照，不从一两个样本猜比例。
- 数千行的表用“每种机制至少一条＋按风险抽样＋全表结构/键/引用自动校验”验收，不逐条人工比对，也不把抽样通过写成全表一致。

## 7. 完成条件

- oracle 用例与目标实现逐例一致，或差异逐项登记为缺口。
- JS→C# 对照表覆盖本模块全部规则字段，每个字段有级别与依据。
- 跨引擎项目同时满足 [原生转换规范](../../grea-native-port/references/Unity原生转换规范.md#验收三门)：规则实现在 Domain/Gameplay 中，不依赖 JS 解释器或源引擎运行时。
- 结果按 [分层验收](../../grea/references/测试与结果交付.md) 记录：规则测试、真实输入与原版体验分别报告。
