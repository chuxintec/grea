# 维护与发布

用途：维护 GREA 产品与构建可评审候选；游戏工程和用户安装不属于仓库源码。先核对 Git 根、AGENTS、分支和本轮授权。

## 架构与唯一来源

- `src/grea`：CLI/MCP 共用应用、契约和工具；OS 差异集中 `host/`。
- `registry.json`：工具 ID、别名、依赖及 argv；`contracts.py` 生成 schemas。
- `plugin/`：8 个技能、权威流程、启动薄层和目标 runtime lock。
- `tools/`：Unity 包与非 Python 实现；`scripts/` 只做维护/测试准备。
- `docs/`：六份使用说明与必要格式契约；`validation/` 保留不可变报告；已完成过程从冻结 Git 历史追溯。

新增工具先核对现有语义；保留旧 ID、参数和别名，同步实际调用方。不要为“统一入口”复制业务实现。未验证的候选与当前能力分开。

## 开发验证

```sh
uv sync --frozen
python scripts/generate_contracts.py --check
python scripts/check_docs.py
python scripts/check_semantic_docs.py
python scripts/render_brand_assets.py --check
python -m unittest discover -s tests -v
```

上面的 python 应为 `.venv/bin/python` 或 Windows `.venv/Scripts/python.exe`。Skill 只修改 plugin；用 `scripts/sync_skill.py --destination /absolute/isolated/skills` 同步，再加 `--check` 检查；候选验收不更新全局安装。

## 供应方与公开分发

凭据、providers.local、二进制、游戏素材、原始日志和本机 .venv 不提交。暂存后运行 `scripts/audit_public_tree.py` 审计实际字节，并人工检查许可证与归属；模式扫描不能证明无全部敏感内容。许可来源见 THIRD_PARTY（GREA 安装目录 `THIRD_PARTY.md`）。

跨平台文本为 UTF-8。Windows Case 使用共享/独占 LockFileEx；目录使用同卷、无替换移动；工具先挂入 Job 再执行。平台事实与原生验收边界见 验证索引（GREA 安装目录 `validation/README.md`），不把权限位当 Windows ACL 或用清 PATH 冒充沙箱。

## 构建候选

在匹配平台、干净提交上分别运行：

```sh
python scripts/build_plugin.py --target macos-arm64 --out dist/plugin
python scripts/verify_plugin.py --bundle dist/plugin/grea-plugin-macos-arm64.zip --report dist/plugin/plugin-acceptance.json
```

Windows 使用 `--target windows-x64` 和 `grea-plugin-windows-x64.zip`。构建时联网取得锁定归档/依赖，使用时不下载；重复构建比较哈希。`--worktree` 仅未发布预览，不能标成提交制品。发布仅提供两个完整插件 ZIP，内部保留全部技能；`scripts/release.py prepare` 生成元数据，attach-plugin 绑定两平台及验收报告，verify 必须检查完整目标集合。源码使用 GitHub 自动下载，不额外生成安装 ZIP。

## 发布流程

仅收到明确发布授权后统一 package/runtime/uv.lock/两份客户端版本、更新 `validation/release-notes/<tag>.md` 发布说明并提交。推送版本标签才会触发 Release 工作流；rc 自动预发行。源码、目标包和各自验收报告须绑定同一提交；缺目标不得用其他平台报告代替。使用 `release.py verify` 核验附件清单、哈希和发布回读。

发布前在开发分支及合并后的 main 上通过 CI 与 Release dry run，才创建正式标签。Windows Server 原生 CI 是本轮 Windows 门槛；桌面/Unity/Player 实机明确排除并记 not_run。用户安装独立授权，不随发布升级。

平台实现依据：[LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex)、[MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)、[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)。API 文档不代替本轮原生测试。
