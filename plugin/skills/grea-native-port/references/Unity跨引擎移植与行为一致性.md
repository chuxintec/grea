# Unity · 跨引擎移植与行为一致性

工具推荐：laya_contract_audit调用项目解析器，compare_events连接项目oracle；不重新导入已整理资产。 入口和限制见 [工具清单](../../grea/references/工具选择与调用.md)。

用于 Cocos、Laya/FairyGUI 等源运行时向 Unity 恢复。先确认源引擎、格式版本、目标管线和原版宿主；这里列排查契约，不提供可套用所有游戏的常量。目标形态、规则与引擎语义的分界由 [原生转换规范](Unity原生转换规范.md) 决定：本页契约是**对照与验收清单**，用于确认 Unity 原生实现得到相同结果，不是在 Unity 中复刻源引擎运行时的依据。

## 来源与资产身份

- 保留原包、解压数据、曾可运行的H5适配与目标工程的独立清单。比较原模块正文与适配层，记录包装、换行及真正逻辑变化；不能把修改过的平台桥接当原版代码。
- 以稳定的源标识映射目标资产/组件。文件扩展名、Prefab根名和运行键可能不同；建立显式别名表并拒绝冲突。不能全局删除后缀后“取第一个”，也不能找不到关键效果就静默返回。
- 原UI组件、控制器、子节点、transition和字体是转换输入：用一次性转换器按 [Cocos 映射](Unity源引擎映射-Cocos.md) 等手册生成原生 Prefab 与组件配置，保留其视觉与交互结果，不在生产工程保留源节点身份组件或源运行时语义。来源映射表留在 Analysis；生产不持续加载旧包，见 [原生转换规范](Unity原生转换规范.md) 与 [UI框架迁移](UnityUI框架迁移.md)。转换器未覆盖的特性列入清单，不先拼一个相似页面再宣称原UI恢复。

## 行为契约检查

转写原业务代码时，结果仍可能因宿主语义不同而失败。适配前沿实际调用链列出相关启动依赖、运行时 API、事件参数和资源引用；遗漏语言表、格式化模块或音频接口，可能表现为资格提示错误或弹窗清理中断。先定位第一处异常，不直接修改消费条件或页面布局去绕过它。

针对已使用或本次新增的高风险契约做小范围检查。下表说明要对照的结果；实现选用 Unity 原生组件或主流插件（如 DOTween/PrimeTween、`UnityEngine.Pool`、Coroutine/Awaitable），在其上设置相同的复位、取消与完成语义，不编写仿源引擎的 Tween、调度器或节点池：

| 契约 | 核对与验证 |
| --- | --- |
| 数值方法与对象身份 | 按源版本确认原位修改/新建对象、返回接收者/返回值及维度；检查真实调用方，不能只补同名空方法消除异常 |
| Tween/动作重用 | 同一缓存实例再次启动、中途重启、并行动作及剩余时间预算；按原语义重置，观察长流程有无残留 |
| 对象池与节点生命周期 | put/get 对父节点、active、监听和显示的影响；验证重复回收后再显示、滚动往返和关闭重入 |
| 调度与回调 | 按钮禁用、组件停用、暂停、场景切换是否影响定时器及完成回调；避免禁用按钮后连重新启用它的回调一起停止 |

预期依据源代码/格式版本或原版观察，夹具用于定位和回归；修复后回到实际失败入口，再检查受影响调用方。一次对象池修复不关闭所有列表空白问题，后来出现的大步长滚轮等不同触发需独立保留。UI 映射细节见 [界面与交互](../../grea-parity/references/Unity界面还原与输入交互.md#映射中容易遗漏的细节)。

## 几何、动画与渲染

| 契约 | 应核对内容 | 容易产生的错误 |
| --- | --- | --- |
| 坐标与父链 | 镜像/手性、轴向、单位、父节点倾斜、局部旋转与世界旋转、运行时偏移 | 合并父层级后，自动转动或大幅拖动围绕错误轴 |
| 蒙皮 | 每种网格的骨骼索引是全局还是submesh调色板局部；权重范围和矩阵布局 | 将SimpleSkinnedMesh的全局索引再次重映射，模型塌缩 |
| 烘焙骨骼矩阵 | Animator根空间、mesh空间、镜像矩阵、采样帧/半浮点格式 | 将mesh节点世界矩阵错当Animator owner矩阵 |
| 材质与光 | 序列化参数加运行时覆盖、ambient/diffuse/specular、gamma/linear、forward轴 | 只复制场景灯光而漏掉初始化时重设方向 |
| 透明与覆盖 | 源深度测试/写入、队列、blend、遮罩、顶点色及纹理采样 | 连线被挡、粒子黑块、主页UI底图遮住原3D场景 |
| 图集与清晰度 | 原尺寸、压缩、mipmap、最大尺寸、颜色空间、DPI客户区 | 使用了原图仍因导入缩小或错误适配而模糊 |

分别用静止基准姿态、原动画帧、真实Camera/父节点、运动中状态验证，不把静态mesh可见当作骨骼或动态层次通过。场景中嵌套的Static/背景节点要按源查找规则处理；不能只查直接子节点，也不能无条件关闭所有同名节点。

## 时钟与状态

- 区分UI/粒子时钟、玩法时钟、射击调度、广告剩余时长、合并过程和暂停门控。有些原动画不随玩法倍速变化，不能统一乘gameSpeed。
- 预留目标、扣弹、命中、缩小、移除和完成任务分开追踪。合并可能需要转移pending/active/nextRelease及在途任务所有权；“剩余方块对了”不证明这些顺序一致。
- 自动收尾、失败自救、复活强制射击等易被简化掉的分支，应从实际调用者发现。静态有方法、测试桩调用成功与真实按钮接通分别登记。
- 原代码可运行时做小范围差分oracle，记录源哈希、环境桩、随机调用和数字语义；不要把适配过的H5结果当完全独立原版证据。

## 本次案例的可迁移教训

跨引擎迁移时，连线可能由双色网格生成，投射物可能由程序尾迹驱动，破碎也可能依赖粒子与缩放时序。先核对原对象、资源绑定和调用链，再选择目标组件；具体尺寸、时长、角度、槽位和图集参数必须从当前输入提取。

输入与UI生命周期见 [界面与交互](../../grea-parity/references/Unity界面还原与输入交互.md)，特效证据链见 [动画与流程](../../grea-parity/references/Unity动画特效与事件时序.md)，发布和目标平台验证见 [验收与协作](../../grea/references/测试与结果交付.md)。
