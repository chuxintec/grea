# 美术 · 游戏换皮与资源制作

适用于已有功能正常、可维护的原生 Unity 工程的授权换皮。目标是完整替换指定美术表现，原布局、入口、操作流程和玩法规则继续有效。已有交付版本和功能证据可复用，按改动风险补回归，不重新把换皮当首次恢复或先修一遍所有玩法。

## 先美术，后调优

换皮主线按以下顺序推进；本期授权已有批准素材或已完成阶段时复用，不重复制作或审批。

| 阶段 | 实际工作与出口 | 不可替代的边界 |
| --- | --- | --- |
| S1 风格选样 | 从真实功能界面/状态中选核心样本，配代表角色和按轮廓、骨架、动作差异选择的代表怪物；产出同一风格的可见界面稿、角色/怪物概念和核心技能效果方向 | 项目明确要求“10 界面 + 1 角色 + N 怪物”时落实为实际 ID 和可见稿；N 按已有怪物差异确定，不凭空新增。清单、提示词、改色、标签修补或可运行 Player 不等于风格成果 |
| S2 成套生产 | 制作 UI/ICON、拆分 UI 元素；角色/怪物原画与核心技能特效；制作所需角色/怪物 Spine 和特效 Spine，核对完整导出组 | 原画、静态 PNG、已编辑骨架、已导出、已接入和实机通过分别记状态；不能用静态贴图冒充 Spine |
| S3 样板完整替换 | 选样范围内 100% 替换 UI、角色、怪物、特效，保持该范围原有功能和操作，查看真实效果 | 100% 指选样的美术和功能覆盖；可玩、能构建或换几张图不足以关闭样板。不是先缩减原功能再补齐 |
| S4 全量换皮与 Bug 修复 | 用户确认可见样板风格 OK 后，成组替换全量约定美术并修复受影响 Bug | 不给每页/每个资源追加用户审批，不以新稿覆盖已否定版本；不能把风格候选声明成批准 |
| S5 游戏调优 | S4 完成后，按单独约定调整 UI/UE；涉及布局/导航/反馈等转 有限二次开发（`grea-evolve` 技能） | 约 30% 如有约定只用于此阶段的整体页面/流程范围；不是美术覆盖率、每页配额或像素计量，不提前混入 S1–S4 |

用户已授权先做样板时直接产出候选设计及可见素材，按约定审阅，不在具体成果前再次询问是否允许换皮。美术候选不是批准设计；明确要求先批准 Overview 再生产时遵守该要求。独立的 UI/UE 修改任务沿其已授权范围执行，不因此强加全套美术阶段。

## 一份持续维护的台账与设定

从 S1 起维护同一份资源台账，以及界面、角色、怪物、特效、关卡设定。每阶段更新实际状态、来源版本和差额，不每阶段复制一套表。原资源/功能 ID 保持稳定；没有新关卡或新机制时记录原设定引用，不发明内容。

每条映射至少能追溯：原资源/功能 ID → 设计来源与版本 → 原画/源稿 → 切片 → 所需 Spine 生产与导出 → 目标资源/Prefab/组件引用 → 当前状态及相关证据。设计来源不是完整生成提示词；私有原件、完整日志、原始提示词、图片和工程留产品内部，不进入公共工具仓库。

Spine 条目记录实际编辑器与运行时版本、骨架、附件、动画名、事件名（确实无事件时明确空列表）、atlas、纹理、导出文件及目标引用。尚未制作就记 pending，已制作未导出记 authored；导出/导入/运行是不同事实。原工程继续使用的 Spine 或不采用 Spine 的对象写明理由，不能用 `not_required` 绕过用户要求的骨骼制作。新增/替换骨架先核对版本和原玩法事件、发射点、命中/结束/取消时点，不改变游戏规则或用任意新时钟驱动伤害。

工具接口及自有声明示例见 [主题映射与台账](../../grea/references/providers/theme-assets.md)。`theme_assets validate-ledger` 只校验台账结构、引用关系和状态声明的完整性；不读取媒体、不认证风格/骨骼/导出或运行成功。PNG 自动化仅用于已存在的单 Sprite UI 图像；角色、怪物、特效骨骼和新 GUID 继续用工程原生制作能力，工具不足准确报缺，不要求游戏先试用本工具才开始设计。

## 设计来源与工具选择

- 先复用本期明确有效的设计；候选、批准、否定/退出版本区分。批准设计文件及 SHA 用于后续比较，旧版本不混入新来源。
- 用户要求从批准页面拆分时，该页为按钮、标题、底框、图标等元素的来源；已批准独立素材直接复用。指定“页面图为唯一来源”后，旧独立图集退出依据，缺失状态登记差额并按授权补充。
- 用户允许独立 ICON/按钮图集时可成组生成，统一背景、留白、视角和光照；合批不能覆盖唯一页面来源要求。
- 制作服务与模型使用依当前实际能力和授权；不默认特定服务或增加安装、上传、收费权限。已授权生产不因工具候选清单不完整停工，真实能力不足时说明缺口并继续独立部分。

## 切分、接入与定向验收

- 切片登记来源页面/源稿、原尺寸、裁切矩形、透明处理、pivot/基线、用途及复用范围。检查不吞金边/阴影，不带入邻接数字、底块；按钮底、艺术字、图标和动态数字分开，真实数值继续绑定文本。
- 先看透明棋盘和正常/按下/禁用/选中状态。`image_alpha_audit` 的 alpha、尺寸和边缘统计不能代替切片视觉或按压实测。
- 保持素材比例；布局使用既有锚点、安全区和容器。仅明确设计为九宫格的资源使用 border，不靠拉伸改变弹窗比例；不能将整页截图作为可交互 UI。
- 成组接入前验证一个代表对象及共用组件的风险，然后覆盖选样实际差异；不要求每个资源重跑全套功能/全平台。运行时核对真实入口、模态返回、按钮状态、Shader 原有属性和受影响骨骼事件，不合并玩法颜色身份。
- 用户确实授权序列帧代替 Spine 时，保留触发/结束/取消关系；统一画布、帧时长、循环和身体锚点，透明 bbox 不作为身体配准算法。没有此授权继续原骨骼制作要求。

UI/输入细节见 [界面与交互](../../grea-parity/references/Unity界面还原与输入交互.md)，骨骼/特效细节见 [动画特效与事件时序](../../grea-parity/references/Unity动画特效与事件时序.md)。按当前任务分层记录：可见设计、源稿、切片、Spine 导出、Unity 引用、运行输入和 Player 各自有证据，任一层完成不替代其余层。
