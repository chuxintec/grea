# 工具 · 选择与调用

本页是任务到工具的唯一选择表。确认工作区后，将 `GREA_ROOT` 设为 grea 的绝对路径；命令不一定在 PATH。先复用已有产物和当前契约，只检查本次用到的工具。环境变化或相关失败才做诊断，不因每次加载技能运行全量 doctor。

工具文件、依赖/系统安装位置、Unity 包库存见 [TOOLS](../../TOOLS.md) 与 [registry.json](../../registry.json)。参数、退出码、副作用及样本验证由 [脚本目录](../../docs/tools/制品与资源检查.md)、[恢复工具契约](../../docs/tools/规则与格式检查.md) 维护；下表 CLI 名称使用实际调用 ID。

## 规范参数入口

Unity依赖用 `grea audit-unity-dependencies`，资产快照用 `snapshot-unity-assets`，玩法轨迹用 `compare-gameplay-traces`，浮点纹理用 `inspect-numeric-texture`。CLI/MCP共用严格参数与输出；其他已登记工具用 `describe-tool` 查看，再调用 `run-tool` 或旧参数兼容 `legacy`。具体schema由 [统一接口](../../docs/接口与证据说明.md) 维护，下面表格说明所复用的底层能力。

## 按任务调用

`recovery <ID>` 表示 `$GREA_ROOT/bin/recovery <ID>`；先查看该 ID 的帮助并核对目标和输出，不能将 Editor C# 或技能名称当 CLI 参数。

| 当前步骤/任务 | 推荐入口及类型 | 结果边界 |
| --- | --- | --- |
| 环境变化/工具不可用 | `bin/decode-doctor`；`recovery registry_doctor`（CLI） | 存在、help、启动和真实样本分别记录；日常只核对相关项 |
| 原包获取/展开 | `recovery unpack_xapk`；`bin/7zz`、apktool/jadx、wxapkg-unpack（CLI） | 匹配 APK/XAPK/微信封装，保留源；解包不等于安装或反编译 |
| 原版运行与录制 | adb/scrcpy（CLI）；本会话允许的 CUA；ffmpeg/ffprobe | 显式设备；录制权限、音轨与原版版本分别核验 |
| 录像核验/关键帧 | `recovery video_manifest`、`recovery video_sheet` | 解码/音轨/联系表不证明语义或声音一致 |
| Unity 资源提取 | `bin/assetripper`；grea Python 运行时中的 UnityPy | 先看包哈希和库存；读字段失败查 schema，不修改原件 |
| Mono/IL2CPP 代码 | `bin/ilspy`、`bin/cpp2il`、`bin/il2cppdumper`；Ghidra/Rizin | 类型/地址与方法实现分开；依据支持版本选择，定向追调用链 |
| 第二解析器 | `bin/il2cpp-inspector` | Redux 警告/退出限制见 grea；不默认替换已验证解析器 |
| 重建依赖/资产身份 | `recovery unity_dependency_audit`、`recovery unity_asset_ledger` | 文本 GUID 闭包不覆盖动态键；台账不证明可删除 |
| 配置/有限原生资源制作 | `recovery unity_config_candidate`、`recovery unity_native_assets` | 显式 schema/目标、候选哈希和拒绝覆盖；Spine 仅页闭包；[制作契约](../../docs/providers/unity-authoring.md) |
| 迁移清单核对 | `recovery unity_asset_ledger` 的 check-plan/verify-moves/compare | 计划内身份与计划外变化分查；类型和加载由 Editor 回读 |
| Unity 项目与实际资源回读 | Unity CLI/Pipeline 与对应官方 Unity 技能；`grea/tools/unity/audit/RecoveryRuntimeAudit.cs`（Editor C#） | 连接/执行见 [Unity编辑器连接与任务执行](../skills/grea-delivery/references/05-Unity-编辑器连接与任务执行.md)；C# 的 Run/Texture 入口见 [说明](../../tools/unity/audit/README.md)，不是 CLI 工具 ID |
| UPM 安装/恢复 | Unity package-management 技能；`grea legacy unity_package_backup plan` | 备份先验哈希；缺版本走当前 UPM 解析；CLI 模块管理不等于 UPM |
| 规则/时序/原生常量 | `recovery compare_traces`、`recovery compare_events`、`recovery read_elf_values` | 显式事件 schema、字段、地址与单位；首个差异不证明采样完整 |
| 数值纹理 | `recovery audit_numeric_texture` + Editor C# Texture 回读 | 原始字节、格式、实际采样分别核验，不把 PNG 当浮点数据 |
| Shader/实际显示 | `shader_probe`；glslangValidator/spirv-cross/spirv-val；Frame Debugger | 探针编译不证明 Unity 最终画面一致 |
| 授权素材制作 | 已批准素材直接复用；需要制作才按 [换皮流程](../skills/grea-reskin/references/07-美术-游戏换皮与资源制作.md) 选择用户指定且当前可用的工具；未指定时按能力与任务条件选择 | 只在本期存在设计确认要求时进入该环节；不重复审批已有批准版本 |
| 换皮 alpha/边缘检查 | `recovery image_alpha_audit` | 对实际制作输出只读检查，不替代按钮正常/按下/禁用实测 |
| 跨引擎映射 | `recovery laya_contract_audit` + 明确信任的项目解析器 | 源格式和运行契约见 [跨引擎移植与行为一致性](../skills/grea-native-port/references/05-Unity-跨引擎移植与行为一致性.md)；不自动覆盖工程 |
| 有界测试 | `grea/scripts/testing/run-tests-bounded.py` | 只管理自己的进程组；RSS 采样不是硬上限 |
| 性能问题/风险 | Profiler、Frame Debugger；已安装 Profile Analyzer/Memory Profiler | 先查目标工程 manifest/lock；基准按 [性能分析与优化验证](../skills/grea-unity-standard/references/05-Unity-性能分析与优化验证.md) 触发 |
| 构建与包体验证 | Unity BuildPipeline；`recovery verify_payload_tree`；需要单 EXE 才用 `recovery package_windows_portable` | 构建、封装与实机分别验收；生命周期和发布见 [游戏构建与版本发布](../skills/grea-delivery/references/09-交付-游戏构建与版本发布.md) |
| 技能维护验证 | `recovery check_grea_skill`（静态检查）；[任务场景集](../../tests/scenarios/README.md)（人工/获授权行为评估） | 静态检查不能证明 Agent 决策正确；不自动调用付费服务或启动子 Agent |
| 静态文件映射复制 | `static_asset_copy` | 仅辅助/历史产物，不改变 Unity 专用开发路线 |

## 新工具准入

先查既有目录，选择复用、扩展或新增。自有 Python 功能模块放 grea/src/grea/tools/，非 Python 工具和 Unity 包放 grea/tools/，测试放 grea/tests/；仓库维护脚本放 grea/scripts/；参数化路径、包名、设备与对象 ID，提供帮助、依赖、输出 schema 和副作用。至少两组不同输入及适用失败分支实测；项目专用工具、清单和证据保留项目，不搬空后改符号链接。

Unity 新装第三方包更新 grea/.private/backups/unity-packages 的版本来源、哈希和恢复说明；Assets/Plugins 中第三方库保留许可证和 meta。项目原生输入桥等专用插件仅备份，不宣称可通用安装。

技能只保存文档。迁移到其他机器需同时部署 grea 与系统依赖；项目历史证据可能未随根 Git 分发，它是按需追溯来源，不是加载本技能的必要条件。新调用 ID 同步分发器及适用注册表，参数只在 grea 维护，不在多个技能文件复制命令模板。

## 平台与兼容入口

调用前核对 registry 的 host_support 和 alias_of：旧名字只引用正式契约；Mac 二进制不可直接用于 Windows。Windows 原生依赖通过显式 GREA_PROVIDERS 配置，不静默替换工具；平台候选不等于实测通过。部署、诊断选择与未支持项见 [工具整合与跨平台](../../docs/安装与平台.md)。诊断默认查存在，版本／帮助使用明确工具 ID；旧 decode-doctor／registry_doctor 同样遵循该规则。
