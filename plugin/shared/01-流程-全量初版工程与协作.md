# 全量初版工程与协作

完整恢复／首次重建采用：GREA调研取证与来源冻结 → monkey一次批量导出独立初版 → GREA核真实交接 → 游戏Agent接续业务、视觉、服务器 → 交付及持续迭代。只读研究、来源辨识和输入准备可以在导出前进行；已有工程的局部修复不无条件重导。

monkey维护源格式解析、资源转换、目标原生装配及代码依据／初稿导出；GREA维护流程、冻结调用和交接判定、Unity/Cocos/Go标准及通用开发框架。GREA不另写平行转换器；monkey不先实现整游戏业务。Unity来源目标Unity6，Cocos来源按声明支持选择Unity6/Creator3.8；其他格式先查固定provider能力。目标或能力不支持时明确报未支持，不能用小样或另一引擎替代。

输入按游戏、引擎、修订及manifest冻结已取得全集，区分主包、分包、Bundle、代码／metadata与可证实补齐文件。全量指该明确来源集合，不承诺未知服务器或全部受保护代码。工具commit／版本／能力摘要固定；游戏不自动跟随工具main。

初版交接要实际包含适用的资源、Scene/Prefab、动画、字体音频、配置以及可恢复代码初稿／原始依据，并保留唯一逻辑源ID→目标路径/GUID映射和AI入口。未知方法、不可恢复资源保留源码位置、依据、TODO或明确原因，隔离未实现代码；具名草稿和已证实逻辑不等于全部业务恢复。散列空类、清单、lookup、IR、gallery或媒体池不能冒充完整初版。

依源实际类别核对：源含Prefab/Scene时必须检查实际原生图文件和引用；源没有这些类别时不凭空增加数量门。每项输入有去向、每个逻辑资产有处置，和原生工程可导入／编译分别验证；conversion.completed、文件数量或exit0都不能单独放行。全量初版与游戏可玩是两个出口，不能以全玩法实玩反过来阻断初版交接，也不能以初版导入通过关闭玩法/视觉。

真实CLI边界见[monkey接入](../../docs/providers/monkey.md)：当前GREA已验package/slice旧合同和显式handoff审计，**新的all-scope批量导出适配not_available**。上游正在补齐不等于插件已支持；保持候选，不调用猜测参数、不自行复制转换器。静态审计只能核字节和声明；native receipt来自实际引擎记录，角色仍是提交者声明，不是GREA独立执行了Editor。

交接核清后，游戏Agent按完整模块接续业务、交互、视觉、服务器及换皮。有既有工程时，在独立全量候选与工作工程之间按来源身份成组合并，保护既有代码、GUID、正式JSON和存档。工具共因交monkey，流程／编排共因交GREA，游戏专用业务保留项目；不因这份规范新增推送、安装、渠道或生产权限。
