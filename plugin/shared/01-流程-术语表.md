# 流程 · 术语表

| 术语 | 本插件中的含义 |
| --- | --- |
| 原版证据 | 同版本游戏的包体、资源、代码及可观察运行结果；必须记录来源与适用条件 |
| 恢复 | 源游戏本身是 Unity 时，重建其资源引用、代码与工程运行闭环 |
| 原生转换 | 把其他引擎的制作数据一次性转换为 Unity 资源与代码，运行时不重建源引擎 |
| 原版一致性 | 在明确状态与输入下比较规则、画面、时序和交互，不等于架构相似 |
| 原生可维护性 | 使用正常 Unity 资源、组件、序列化与编辑器工作流，后续开发无需源引擎模拟层 |
| 只读规划 | 根据输入生成建议和变更计划，没有执行计划中的工程修改 |
| 能力检测 | 检查入口、文件或依赖是否存在；不等于业务调用已通过 |
| MCP 连接 | 客户端完成协议初始化并发现工具；不等于 Unity Editor 已连接 |
| 业务验收 | 实际执行选定工具或游戏流程，并回读产物、状态和失败边界 |
| 完整插件 | 技能、MCP 启动配置、自有工具和固定版本 Python 运行时的可迁移制品 |
| 文档 Skill 包 | 独立流程文档；不携带或自动连接 MCP 运行时 |

验收维度与证据要求见 [分层验收](08-验收-测试与结果交付.md)，执行约束见 [共同约束](01-流程-共同约束与执行入口.md)。
