# Unity · 编辑器连接与任务执行

仅在需要控制 Editor、运行 Unity 命令或排查连接时读取。本页管理会话连接和执行生命周期；工具选择由 [工具清单](02-工具-选择与调用.md) 维护，工程导入/代码恢复见 [工程重建](05-Unity-工程重建与恢复.md)。文档/静态证据整理不要求连接 Unity。

## 发现目标与只读往返

1. 按当前可用的 `unity:unity-cli` 技能操作；无前缀同名技能可作兼容入口。先确认实际项目、Editor 版本/进程和当前状态，不沿用历史 PID、端口、对象 ID 或路径。
2. 分开核实插件安装、项目 manifest/Pipeline、MCP 握手、工具发现、Editor ready 和一次明确项目的只读状态回读。installed/enabled 或握手成功不证明 Editor 已可用。
3. 先读本版本帮助/schema 再发命令，不猜 run_script 等参数。UPM 用 package-management/UPM API，编辑器模块管理不能替代项目包安装。
4. 零工具、Safe Mode、编译/域重载或主线程忙时检查实际日志和加载状态；按当前等待机制有界回读。不因短时不可用立即另起同工程 Editor、反复重装插件或手改活场景 YAML。

## 编辑与长任务

- 场景/资源修改使用已发现的 Editor API，编译成功后回读实际组件、引用和保存状态。停止、执行、编译、构建、Play 等有依赖的步骤逐步确认，不把失败后续命令无条件串行。
- AssetRipper 等服务只绑定本机回环地址；以当前帮助及实际页面/API确认导入、等待、导出。服务启动或 HTTP 200 不等于导出完成；恢复工具输入输出边界见 grea。
- 长任务创建 run-id，记录输入哈希、开始时间、PID/job-id、报告位置及预期完成标记。外层超时不表示内层终止；先检查该任务进程、报告时间戳和实际状态，再决定等待、修复或有依据的重试。导入、构建、扣费和领奖不得盲目重复。
- 输入/项目不匹配、未判定的重复 GUID、关键引用缺失或编译失败时，暂停依赖写入/集成，继续独立静态工作。只有新证据、参数或工具能力变化才重试失败路线。
- 锁屏或 UI 权限受限时继续不依赖窗口的工作；恢复后重新发现窗口和焦点。UI 操作限当前会话允许的工具，不照搬历史事件注入方式。
- 日志留项目，只读回结果、关键错误和下一问题；不要把完整反编译结果或全量工具目录塞入对话。

## 契约复用

项目 toolchain.json 等现有记录可缓存绝对路径、版本、帮助/schema 来源、输入/输出、成功条件和副作用。环境、版本、接口或实际结果变化时刷新，不要求每次重新探索完整工具链。资源修改后仍需与本次状态对应的回读，旧 PASS 不是当前执行结果。
