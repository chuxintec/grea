# 授权换皮：初心 AI 生图与 ComfyUI 切图

仅在用户授权换皮、美术重绘或新增 UI 素材时使用。原版恢复仍优先恢复原资源；换皮保持用户指定的玩法与 UE 不变量，按已批准的设计图验收美术。工作区默认中文玩家文案，项目另有语言要求时从其要求。

## 先判断是否需要制作

先盘点最新批准设计、已有成品素材和本次差额。已有可用素材直接接入，只修受影响页面/状态；不重新生图、重走总览或对已批准内容再次询问。需要新设计才进入下面页面流程；仅补一个元素不自动重做全部页面。页面图为唯一裁片来源，只在用户已明确指定时适用。

## 工具与状态

- **需要新生图时**，遵循当前会话工具要求及用户已指定的服务；工作区推荐「初心 AI 创作」技能和公司 MCP。选择该路线后，实时发现 Provider 与 operation，按该技能完成输入上传、预检、计费参数、确认和幂等。优先选择用户指定的 Nano Banana 系列；精确 provider 名和是否支持多图图生图以当前返回为准，不抄旧会话参数。
- **需要切图/抠图时**，用户指定 ComfyUI 就使用该工具；未指定时本工作区推荐本机 ComfyUI，实际调用仍遵循当前会话可用能力。发现实际地址、可用节点和模型后使用对应工作流；记录输入、工作流、输出与哈希。不把指定 ComfyUI 的任务静默换成 Python 阈值抠图或另一生成服务。
- 元数据检查、联系表和验收图拼接可用普通脚本；它们不承担 AI 重绘或替代 ComfyUI 抠图。未连接时先完成页面清单、提示词与切分规格，依赖生成/切图的项明确待办，不自动安装模型或更换服务。
- 等待异步任务按返回的轮询间隔与状态；暂未出现图片不等于失败。保留任务引用并查询同一任务，网络重试复用原幂等键；终态失败只在当前用户授权的重试范围内重建，说明次数和可能费用，禁止无限重复创建。

## 先完成页面设计，再拆图

1. **列本期页面和状态。** 从实际入口盘点主页、局内、暂停/设置、胜负、道具、提示及外部服务入口；标注与 UE 参考页的对应关系。界面内容由游戏截图/用户要求确定，风格图不决定入口或布局。
2. **明确输入角色。** 每页使用“统一风格参考图＋该页面实际游戏/UE 截图＋可选已批准页面”进行多图图生图。提示词逐一说明角色，锁定入口、布局、交互层级、文案和需重绘范围；仅写风格文字不能替代必需的源图。
3. **每个需要新设计的页面单独出示意图。** 先统一材质、字体、圆角、光照与阴影；同一 HUD 在早晚关只改变真实解锁/数值状态。每张记录 page-id、输入哈希、实际模型/mode、提示词、输出哈希与审查状态。
4. **按本期设计审查要求出示。** 对照本期页面和共用区；用户要求先确认 Overview 时，批准后才进入拆图和 Unity 接入。已有批准版本无需重复询问；被否定版本标记 retired，不能混入当前美术来源。
5. **冻结已批准来源。** 用户要求从页面图拆分时，以最新批准页图提取按钮、标题、底框、图标等元素；已有批准独立素材则直接复用。用户指定“页面图为唯一来源”后，早先独立生成的 ICON/按钮图集即退出实施依据。缺失状态先登记差额，再做授权的补充设计。

需要新生成 ICON/按钮状态且用户允许独立图集时，尽量一次生成 N×N 等单元图集，使用纯色底、固定留白、统一视角与光照，无格线/说明标签；之后拆成独立素材。合批不等于提高图片 count，也不能覆盖“只从批准页面切图”的要求。

## ComfyUI 切分与接入

- 为每个元素登记源页面、原像素尺寸、裁切矩形、透明处理、pivot/基线、目标用途与复用范围。裁切不能吞掉按钮金边、阴影，也不能带入邻接数字、蜂巢或整块背景。
- 按钮底、静态标题、文字装饰、图标和动态数字分开。用户要求保留批准图中的静态艺术字时可切出透明文字元素；动态关卡/库存/计时始终绑定真实文本。字体、字号、描边和颜色以该页规范为准，不把数字单独放大。
- 看透明棋盘预览，再测正常、按下、禁用、选中。没有 alpha 的矩形底图在按压染色时会暴露灰色方块；含 alpha 也不代表边缘切对。`image_alpha_audit` 只检查尺寸、alpha 和边缘统计，不能替代按压实测。
- 保持素材比例。版式用锚点、安全区、容器和专用长宽比解决；只有明确设计为九宫格、边框不变形的资源才设置 border。不靠非等比拉伸适配长短弹窗。
- 公共素材只复用相同外形、状态和用途；所有页面都从批准页图裁切不等于整页截图充当可交互 UI。用独立元素搭建真正按钮、开关、数值和模态遮罩。
- ComfyUI 返回完成后核对实际输出、透明边、尺寸和内容；任务已结束但没有有效素材仍是失败。禁止用臆测路径、旧任务图片或已否定素材替代。

## 序列帧与运行验收

用户要求用序列帧替代特效/Spine 表现时，保留原玩法事件、触发/结束/取消关系；原生 Spine 没有替换授权时继续使用原骨骼。序列帧统一画布、帧号、时长、循环和稳定身体锚点；翅膀/光效范围变化不能导致逐帧包围盒中心漂移。透明 bbox 是诊断数据，不是身体配准算法。

先验收一个代表页的真实输入、文字、alpha、灰态、动画和不同窗口比例，再接入其余已批准页面。比较对象是批准的当前 Overview/页面，而非已否定草图。Shader 换皮需覆盖隐藏、冰冻、双色、溶解等已存在机制属性；颜色风格不能合并玩法颜色身份。运行/表现的通用检查见 [界面与交互](5-界面与交互.md)、[特效流程](7-特效调度与流程.md)。

## 来源与限制

素材生产以最后明确批准的设计与页面验收为基线；旧设计中的已替代要求不继续作为约束。需要分别验证裁片归属、锚点、透明度、交互状态和 Shader 组合，不将单个历史项目的美术参数当作默认值。本规范不额外授予广告、外发或模型安装权限。
